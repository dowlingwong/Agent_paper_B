\section{Method}
\label{sec:method}

The method has three parts: a rule layer, a forecaster, and a fixed rule that turns the forecast into the two decisions (Proposition~\ref{prop:onestep}). Only the forecaster is learned.

\paragraph{Rule layer.}
The rule layer runs first. It skips proposals that are detectable no-ops and proposals that duplicate an earlier evaluated configuration (Proposition~\ref{prop:app-rules}). A skipped proposal is charged no worker run.

\paragraph{Forecast.}
Every forecaster outputs a categorical distribution over 12 bins of the standardised increment $z=\Delta/\sigma_{\mathrm{node}}$: one no-op bin and 11 value bins. From the bins we read $\pi$, the mass of the no-op bin, and $\mu$ and $\tau$, the mean and standard deviation of the remaining mass, computed from bin midpoints and rescaled by $\sigma_{\mathrm{node}}$ (Appendix~\ref{app:arms}). The forecaster sees the task, the edit and the ledger. No forecaster sees an audit value of the current or any later proposal.

\paragraph{Rule.}
Let $\sigma$ be the comparison noise, which is measured per node and is not learned, and let $g$ be the declared run price.
\begin{itemize}
\item \emph{Screen (before the run).} Execute if and only if $(1-\pi)\,V(t^*;\mu,\tau,\sigma)\ge g$.
\item \emph{Keep (after the run).} Keep if and only if the observed increment exceeds $t^*=-\mu\sigma^2/\tau^2$.
\end{itemize}
Given the forecast, the rule maximises the expected audited gain per run under the declared price. It does not control an error probability.

\paragraph{Arms.}
Table~\ref{tab:arms} lists the arms. A1 is the index policy that the theory gives when nothing is known about the individual proposal. A3 is a gradient-boosted multiclass model \citep{ke2017lightgbm} over the 12 bins. A4 asks the proposer typed questions about its own proposal and calibrates the answers. A5 is a small decision model \citep{kev2026} fine-tuned with low-rank adapters to output the 12-bin forecast, with the sum of the ranked probability score and the cross-entropy as loss. \TBD{Adapter rank, learning-rate grid and selected checkpoint, from the committed training records.} A5 also reads the proposal text, and on GPU nodes an excerpt of the code diff, which A3 does not; a contrast between them compares the two full forecasting arms. Training source and model size are chosen on development instances. Details, the reference rules and a conditional arm (A6) are in Appendices~\ref{app:arms} and~\ref{app:closed}.
