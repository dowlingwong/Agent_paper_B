\section{Introduction}

\paragraph{The loop.}
In an automated research loop, a language-model manager proposes a change to a training setup, a worker trains and reports a validation metric, and the loop keeps the candidate as the new incumbent if its metric beats the incumbent's. A campaign runs many such trials on a fixed budget of worker runs.

\paragraph{Two ways to lose budget.}
The metric of one training run is noisy, and the default keep rule ignores this: deciding on one run keeps 49.9\% of truly neutral candidates \citep{jalaian2026noise}, and best-of-32 selection alone produces an apparent gain 2.7 times a preregistered threshold \citep{grover2026lucky}. Proposers also repeat themselves: in our first logged sweep, \SweepOneDuplicates{} of \SweepOneProposals{} replayed proposals repeated a configuration that had already been evaluated. Statistical gates bound the probability of a false accept \citep{wang2026sage,shawn2026pace,sgm2025,lonkar2026evidence}, which does not say what a loop with a fixed budget gains.

\paragraph{The question.}
\emph{At a matched budget of worker runs and manager calls, which control decisions raise the fresh-seed audited gain of a campaign, and by how much?} We study a \emph{governed} loop: a control plane, separate from the manager, decides whether to execute or skip each proposal and whether to keep or discard each candidate, and every trial is written to an append-only ledger. Three ingredients of control are separated:
\begin{itemize}
\item a \emph{rule layer} that skips duplicates and detectable no-ops before a run is spent;
\item a \emph{noise-aware one-step rule} that sets the screening and keep thresholds from a forecast of the proposal's increment and a declared run price;
\item a \emph{learned forecast} per proposal, in place of one constant forecast per node.
\end{itemize}
In the vocabulary of dynamic algorithm configuration (DAC), the configured parameters are a screening threshold and a keep threshold per proposal. The learned object is a forecaster, and the policy is a derived rule applied to the forecast. We make no claim about multi-step control.

\paragraph{The measurement.}
Each arm controls fresh campaigns on the same instances, with the same budget of worker runs and the same cap on manager calls. The outcome is the improvement of the final incumbent over the start configuration, re-measured on fresh seeds that the campaign never saw. Four arms cross the rule layer with the one-step rule, so the gain from de-duplication and the gain from noise-aware decisions are measured separately. Two learned arms, a tabular model and a fine-tuned small language model, are compared with the rule-based arm. A separate, preregistered offline test asks whether a learned forecast improves one-step decisions on logged proposals. Each result keeps its own error control, and both are reported whatever they show (Section~\ref{sec:setup-readings}).
