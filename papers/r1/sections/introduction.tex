\section{Introduction}

\paragraph{The loop.}
An automated research loop repeats three steps. A language-model manager proposes a change to a training setup. A worker trains and reports a validation metric. The loop keeps the candidate as the new incumbent if its metric beats the incumbent's, and discards it otherwise. Each step is cheap to automate, and a campaign runs many trials on a fixed budget.

\paragraph{The known problem.}
The metric of a single training run is noisy, and the default keep rule ignores this. That such loops accept noise is documented. \citet{jalaian2026noise} replay accept rules on real runs: deciding on one run keeps 49.9\% of truly neutral candidates, and peeking after every run gives 11.3\% false accepts at a nominal 5\% level. \citet{grover2026lucky} shows on a controlled language-model task that best-of-32 selection alone produces an apparent gain 2.7 times a preregistered threshold. A family of statistical gates responds to this: paired tests against the incumbent \citep{wang2026sage}, anytime-valid commit tests \citep{shawn2026pace}, tests under a global error budget \citep{sgm2025}, and confidence bounds on fresh audit samples \citep{lonkar2026evidence}. Each gate controls an error probability of acceptance.

\paragraph{What the gates leave open.}
Four questions remain.
\begin{itemize}
\item \emph{The objective.} A loop with a fixed budget wants the largest real gain per run. A bound on the false-accept probability does not say which threshold achieves that, and it puts no price on a run.
\item \emph{The timing.} A gate decides after the candidate has been evaluated, often after extra runs. Many proposals could be judged before a run is spent: some repeat earlier configurations, and some are of a kind that the ledger shows to be harmful.
\item \emph{The proposer.} The manager reads the ledger, so the law of the next proposal depends on what was kept, discarded and displayed. Classical selection theory assumes a fixed set of alternatives.
\item \emph{The value of learning.} A theory-derived rule with a constant prior is a strong, cheap baseline. How much a learned, per-proposal forecast adds beyond it at matched compute has not been measured.
\end{itemize}

\paragraph{This paper.}
We study a \emph{governed} loop: a control plane, separate from the manager, owns the decision to execute or skip a proposal and the decision to keep or discard a candidate, and every trial is written to an append-only ledger. We measure real increments by retraining candidate and incumbent on fresh seeds that the loop never saw. Our approach differs from the gate family in four respects.
\begin{itemize}
\item[(a)] \emph{Gain per run under a declared price.} The acceptance and screening rule maximises the expected audited gain per run under a run price that is declared in advance. The gate family controls a false-accept probability.
\item[(b)] \emph{Screening before the run.} A per-proposal forecast of the increment distribution decides whether the run is spent at all.
\item[(c)] \emph{Theory for a ledger-dependent proposer.} We show a winner's curse of the recorded incumbent for any adaptive proposer, and give conditions under which the one-step rule is globally optimal, with an example in which it fails by an unbounded amount.
\item[(d)] \emph{Learning against the index policy.} We compare learned forecasts with the theory-derived index policy at matched compute, under a preregistered gate.
\end{itemize}

\paragraph{Framing.}
We frame the control plane as noise-aware dynamic algorithm configuration (DAC). The configured parameters are the screening threshold, the keep threshold and the verification count. An instance is a tuple (node, seed, manager, budget). The learned object is a forecaster, and the policy is a derived rule applied to the forecast. Under stated no-feedback and no-information conditions, the dynamic problem reduces to one-step decisions. This reduction is a conditional theorem. We do not claim that the loops we run satisfy its conditions, and we make no claim about multi-step control.
