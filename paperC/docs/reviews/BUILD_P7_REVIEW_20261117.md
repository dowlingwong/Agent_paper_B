## Findings

1. **MAJOR — the support check can certify an action that the relevant FQE regression has never seen.** `ope.py:242–256, 265–285, 323–341`. FQE fits one model per stage. The gate counts actions by a potentially coarser cluster, checks held-out target propensity and checks that each stage appears at least once. The target-required action can have zero observations in that stage despite a large count in another stage of the same cluster. In an independent two-stage probe with 200 disjoint training and 200 held-out trajectories, both stages use one E1 cluster and observed-action propensities are 0.5. Stage 0 has 100 executions and 100 skips, while stage 1 has 200 skips and zero executions. The candidate mixes both actions at stage 0 and executes at stage 1. The stage-1 execute payoff in the held-out data is 10. `evaluate` returns FQE 0 and **meets thresholds** with pooled cluster counts 300 skips and 100 executions and decision ESS 360. Include a stage-by-action training support diagnostic for every required target action used in held-out prediction and in recursive backups. Known empty cells must yield insufficient data. Add a regression check that pooled support cannot hide this gap.

2. **MAJOR — OPE checks logged probability without replaying the sampled action.** `ope.py:132–192`, compared with plan §4.2 and `schema.py:938–944`. `load_campaigns` invokes the campaign checker without its behaviour replay hook, then checks that the chosen action was possible under the named component and matches its probability. I generated a budget campaign with a skip-first static base and ε = 0.25 at instance 51. Changing each recorded ε key from 60002 to 60006 leaves the records structurally valid and lets OPE load all 43 rows. Replaying the component against the mutated key finds four action mismatches. Require mechanical action and probability replay on the P7 benchmark loading path and expose a replay contract or require a prevalidated input for other logged sources. A replay callback must use the same observation/forecast as propensity reconstruction. Test the wrong-key case.

3. **MINOR — the fit/evaluation context omits the chosen forecast view.** `ope.py:132, 162, 178–181, 211–215, 323–328`. Two calls can choose different `belief` names for the same node and environment. The numeric features and target policy inputs then change semantics between training and evaluation while the context comparison still succeeds. Include the chosen belief in the context check. Suite and tier should also be part of the identity if additional sources can reuse a node name.

4. **MINOR — the benchmark documents shortfalls for every screen and gives no positive support control.** The generated report is transparent. It shows 0/36 blocks meeting the count and ESS criteria in every world and target cell. FQE coverage is as low as 6/12, and the late live WDR ESS median is at most 1. Thus the numerical comparison is useful as a sparse-data diagnostic. Preserve it and, where feasible, add a deterministic supported positive-control case with the same exact comparison law or a known-answer integration case. Report passing and insufficient-data cases distinctly.

P7 satisfies the computational and evidence-format portions of the runbook. The stage support and replay defects prevent acceptance. Real-node collection, the SPT-0 clustering declaration, and calibration for deployment remain outside this review.
