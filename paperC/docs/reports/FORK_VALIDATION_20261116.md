# Fork design and go/no-go statistics: validation on E-SYN

ENGINEERING_ONLY. Generated by `python -m paperc.forks_validation` (build runbook P6, step 4); data in `esyn/fork_validation_v1.json`. E-SYN results are implementation checks, not evidence about the real loop.

Set-up: behaviour = each world's tuned N1; continuation policies N1 and N0; r = 2; design q_uniform = 0.15, q_oversample = 0.5, near bands 0.1 sigma_cmp around N1's g and h; 40 roots per collection. Intervals: 95 % percentile cluster bootstrap over roots (B = 300 for tau^2, 200 with refitting for N6). Proportions carry ± 1.96 Monte Carlo s.e. Units: raw metric; tau^2 in squared raw units, tau = sqrt(tau^2) also in units of sigma_cmp.

`d` is the continuation difference (the total fork difference minus the forked candidate's own increment if kept); `q` is the total fork Q difference. Which one carries the go/no-go floor is the author's pre-declaration choice (see `paperc.forks`).

Notes. *bootstrap s.e. / sd*: the mean bootstrap standard error (interval width / 3.92) over the sd of tau^2_hat across the independent collections; below 1, the intervals are too narrow. The s.e. of a variance estimate depends on fourth moments, which 40 clusters estimate poorly when the fork differences are heavy-tailed. *Roots for 80 % power*: n x (2.8 sd / tau^2_pop)^2 with n the roots per collection (40, or 160 in C2), from the observed sd and the population tau^2 of P (rough: both are uncertain, and the sd is taken to scale as 1 / sqrt(roots)). The population values in P carry the same fourth-moment problem, so coverage against them is approximate.
