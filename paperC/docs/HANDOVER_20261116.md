## 6. Traps

- **Table fingerprints.** `esyn/oracle_table_v1.json` (`paperc.esyn.table`) and `esyn/ladder_table_v1.json` (`paperc.runner`) store code fingerprints that the tests compare with the code.
  - The oracle table's fingerprint covers the E-SYN sources, `sim.py` included. The ladder table's covers `policies.py`, `runner.py`, `schema.py`, `seeds.py`, `seeds/registry_v1.json` and the oracle-table sources.
  - **Any edit to those files, even a docstring, requires a rebuild:** `python -m paperc.esyn.table` (about 10 minutes), then `python -m paperc.runner` (about 30 minutes).
  - After a rebuild, verify that the new tables equal the old ones apart from `code_sha256`, `seconds` and `oracle_table_sha256`. Keep a copy of the old files before rebuilding and compare the JSON with those keys stripped.
  - Batch all such edits before one rebuild.
- **Validation fingerprint.** `esyn/fork_validation_v1.json` stores `forks_validation.code_sha256()`, which covers `forks.py`, `forks_validation.py`, `policies.py`, `esyn/sim.py`, `esyn/worlds.py`, `esyn/extra.py`, `esyn/policies.py` and the ladder table. Any edit to those requires a validation rerun.
- **Root campaigns must stay bit-identical** when `sim.py` changes. Fingerprint a set of root campaigns before and after: all seven worlds × a few policies × 25 instances, `record=True`, hashing `(Y, runs_used, end_reason, rows)`.
- **Recorded instances.** `record=True` allows instances 0–9999 only (seed block `paperc_instances`). The validation uses disjoint ranges per part: A/C 0+, C2 2000+, P 8000–9599, B 9600–9659.
- **Fork ids** are unique within a root, not across roots. Key fork trajectories by `(campaign_id, branch_path)`.
