## Findings

### B2-R1 — MAJOR — continuation target belongs to a different fitted policy

**Quote before judgment.** `experiment_scaffold/src/causal_branch/control/timing.py:201–204` says the deployed `w2` uses all development roots and “`c2=None` sets the target's cutoff to the median out-of-fold prediction.” The implementation at `:216–222` is:

```python
oof_a2 = _oof_second_stage(rows, keys_h2, l2, n_folds)
if c2 is None:
    c2 = float(np.median(list(oof_a2.values()))) if oof_a2 else 0.0
y_wait = _continuation_target(rows, oof_a2, c2)
```

`ProposedTiming.fit`, `:350–351`, calls `fit_global` without `c2`. `evaluate_tree.py:119–125` scores that already fitted model once and iterates over each controller's grid, which includes multiple `c2` values. `:271–276` calibrates parameters after fitting and evaluates the original model without refitting its continuation target. By contrast, `docs/paper_split/B_CONTROLLER_DESIGN_20260927.md:75–87` defines `Y_wait` using the second-stage decision with calibrated `c2`, and `papers/paper_b/sections/05_method.tex:28–36` calls this the value of the fitted second-stage policy.

**Observed evidence.** `harness.py`, bounded context world (240 development and 240 held-out roots; seeds 30/31), gives fitted target cutoff **0.058961504874829096**, evaluated cutoff **−0.5**, calibrated tuple **(0.2, −0.5, 0)**. Rebuilding the continuation target at the actual evaluated cutoff changes held-out `Vwait` by mean absolute **0.05998484588344382** and maximum **0.14212407265313415**. Both computations use the current nested out-of-fold helper.

**Interpretation.** The original M1 in-sample-selection bug is repaired, but the evaluated `Vwait` is still the value of a different threshold policy. This weakens the stated interpretation of `s1=A1−Vwait`; it is not resolved by the existing fixed-`c2=0` null test. The difference is material relative to the declared .02 practical margin. This finding does not claim the heuristic must be optimal under the shared batch budget.

**Concrete fix and classification.** This is an execution correction to the adopted design, not a request to revise its scientific controller or tuning protocol. Design §3 already defines the calibrated-cutoff policy and its target (`B_CONTROLLER_DESIGN_20260927.md:75–87`); §4 requires “the same model family and capacity,” “the same template-family folds,” and “the same number of candidate configurations and the same development data” (`:97–102`). Make each existing candidate `c2` use its matching nested out-of-fold continuation target during development calibration, retain the selected model/cutoff pair and freeze it before test scoring. Cache continuation fits at the three existing `GRID_C` values while retaining the ridge family, l2, fold count/family membership, development data and all 27 existing allocation configurations; do not expand any grid or retune on test data. Add a boundary check that the fitted target cutoff equals the evaluated cutoff and a counterexample where changing `c2` changes `Vwait`. If the author intends a separate fixed continuation-reference cutoff, explicitly document that different estimand through the author decision process before treating the manuscript interpretation as satisfied.

### B2-R2 — MAJOR — evaluation drops feasibility masks

**Quote before judgment.** `allocator.py:36–37` defaults `feasible1=True, feasible2=True`; the allocator itself honors them at `:110` and `:125–128`. However `evaluate_tree.py:101–106` constructs each `AllocatorRoot` with `root_id`, scores, `reached2`, `terminated`, family and split, omitting both masks:

```python
AllocatorRoot(
    root_id=r.get("draw_id", r["root_id"]),
    s1=scores[r["root_id"]]["s1"], s2=scores[r["root_id"]]["s2"],
    reached2=bool(r["reached2"]), terminated=bool(r.get("terminated", False)),
    family=r["family"], split=r.get("split", ""),
)
```

The design explicitly requires “batch roots with feasibility masks” (`B_CONTROLLER_DESIGN_20260927.md:122–131`); the manuscript says infeasible roots fall back (`05_method.tex:93–99`).

**Observed evidence.** `eval_semantics.py` marks all 240 test roots `feasible1=False, feasible2=False`. The evaluated adapter spends **60** calls while a direct call to the current allocator with the same explicit masks spends **0**. A complete `evaluate_tree` call with all development and test masks false still selects **60 calls for each** of proposed, myopic, BAVAR and constant reserve. The cap holds; eligibility does not.

**Interpretation.** Direct allocator tests pass while the consumer silently erases their preconditions. Existing mask-free context fixtures cannot detect this. This is a controller/evaluation interface defect, not evidence that the current realism task encounters infeasibility.

**Concrete fix.** Pass `feasible1` and `feasible2` into `AllocatorRoot` with documented defaults for legacy rows. Test all-infeasible and phase-specific masks through the full evaluation path and bootstrap resampling. Retain every original root in the denominator with its declared fallback outcome.

### B2-R3 — MINOR — `family_bounds_at_p0` stores only qualifying bounds

**Quote before judgment.** `replay_validity.py:153–154` returns `qualifying, bounds`. `evaluate_tree.py:350` assigns `family_bounds, _ = simultaneous_family_bounds(...)`, then emits that first result under `"family_bounds_at_p0"` at `:356`.

**Observed evidence.** `eval_semantics.py` produces `family_bounds_at_p0={}` with two populated primary contrasts. A standalone negative-gain input gives first result `{}` and all-bounds result `{"negative": -0.8066036458008113}`.

**Interpretation.** The field silently loses non-positive sensitivity bounds, obscuring abstention and negative results. The p-grid and working-p arithmetic are separate and still compute correctly.

**Concrete fix.** Capture the second return value for `family_bounds_at_p0`; expose qualifying members separately if useful. Test that both primary keys survive when no member qualifies.

### B2-R4 — MINOR — evaluated reports omit declared resource accounting

**Quote before judgment.** `B_CONTROLLER_DESIGN_20260927.md:132–133` requires recording “realized calls, unspent calls and total work per controller”; `05_method.tex:98–99` says these are reported. `allocator.py:150–156` returns those fields, but `evaluate_tree.py:109` immediately returns only `.regimes`. Its report dataclass at `:72–89` and construction at `:379–384` expose one batch budget and policy regimes, with no per-controller call/unspent/work fields.

**Observed evidence.** `harness.py` returns values and budget 60; inspection of the report schema confirms no per-controller accounting. Calls can be reconstructed from regimes, but total work cannot be read from the report. This was checked by code/schema inspection, not a model-cost experiment.

**Concrete fix.** Preserve each base `AllocationResult` long enough to report realized calls, unspent calls and declared allocator work per controller, and document that this allocator work excludes fitting/model costs. Check reported call counts against the realized regimes. No live timing measurement is needed for this repair.
