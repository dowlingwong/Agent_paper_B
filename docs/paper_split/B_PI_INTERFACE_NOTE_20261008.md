## Backend-owned sessions and checkpoints

Keep scripted session handling as it is. Extend the backend seam to own session storage, native fork/reopen, checkpoint capture and history reading. The current `AgentBackend.run_turn(workspace, session, tools, prompt, stop, seed)` is insufficient: it assumes a Python-written session and a `stop` argument (`experiment_scaffold/src/causal_branch/control/executor.py:216–222`); `PiBackend` currently always refuses (`:257–265`). Pi's adapter accepts `session_dir`, either `session_id` or `fork_session` plus `fork_child_session_id`, separate `working_dir`/`launch_cwd`, and budget/deadline limits, but no checkpoint-stop or seed argument (`experiment_scaffold/src/causal_branch/adapters/pi_agent.py:364–389`). Therefore define checkpoint completion as a **settled bounded turn**, with the settled native leaf ID; do not interpret the scripted `stop` string as an adapter capability. Checkpoint turn boundaries must be explicit in the prompt/tool protocol and reviewed before implementation.

Use a fresh, external per-branch session directory and external agent/runtime directories, separately bound to the workspace snapshot. Record the workspace tree digest **and** the canonical session prefix digest/leaf ID. Do not place Pi sessions in the snapshotted `.session/` workspace or copy Python-written child files into Pi's target directory. The adapter refuses source-in-target and any populated fork target (`pi_agent.py:749–799`). Start children with native `--fork <frozen-parent-file> --session-id <frozen-child-id>` (`:946–958`). Pi rewrites a new v3 header with `cwd` and absolute `parentSession`, then copies **all** non-header source entries, preserving their IDs and parent links (`third_party/pi/packages/coding-agent/src/core/session-manager.ts:1579–1629`). Freeze a prefix-only parent artifact before dispatch; use `restore_parent_to_checkpoint` on a working copy if necessary, preserving original evidence (`experiment_scaffold/src/causal_branch/pi_fork.py:205–240`). Require `verify_fork(...).verified`, not merely a returned record: it checks distinct child, identity, parent, canonical inherited prefix and exclusion of post-checkpoint entries (`:281–353`). At checkpoint 2 fork from the settled continuation child's prefix, not checkpoint 1. Reopen only with the explicit same-session selector.

Use `agent_settled` as terminal; `agent_end` is deliberately nonterminal (`experiment_scaffold/src/causal_branch/pi_rpc.py:67–95`). A successful adapter turn obtains `get_entries.data.leafId` and verifies membership in `entries`; timeout, provider failure and budget exhaustion are distinct unsuccessful terminals (`pi_agent.py:673–726`). Native RPC event sequence IDs are not persistent session checkpoint IDs.

## Native entries and the history translator

The native JSONL shape is a header `{type:"session",version:3,id,timestamp,cwd,parentSession?}` followed by entries `{type,id,parentId,timestamp,...}`. Message entries nest `message`; configuration/compaction/custom/label/session-info entries also exist (`session-manager.ts:30–153`). User `content` is a string or blocks; assistant `content` is an ordered array of text, thinking and `{type:"toolCall",id,name,arguments}` blocks; tool outputs are **message** entries with `role:"toolResult",toolCallId,toolName,content,isError` (`third_party/pi/packages/ai/src/types.ts:360–368,409–463`). Top-level scripted `tool_call`, `tool_result` and `checkpoint` records are not native entry types.

Add a Pi-specific translator rather than widening the scripted reader implicitly (`executor.py:273–307`). Follow the selected leaf's `parentId` ancestry, stop exactly at the bound checkpoint leaf, preserve content-block order, map first user text to `task`, later user text to `observation`, assistant text/visible thinking to `assistant`, toolCall blocks to `tool_call` and toolResult text to `tool_result`. Use deterministic event steps even when one entry yields several events; retain entry/block and tool-call IDs as provenance outside the visible history. Add the `checkpoint` history event from the externally bound settled-leaf record, without writing a fabricated native entry. Keep runtime configuration/identity metadata out of visible histories. Explicitly classify or refuse unsupported custom messages, images, compaction and branch summaries; never stringify unknown objects or silently erase context. `HistoryEvent` permits only the six visible kinds (`experiment_scaffold/src/causal_branch/control/configurator/serialiser.py:36–69`). Preserve existing information/redaction boundaries.

## Tools, arm blindness and decoding

Create a **new B extension** registering exactly `fit_candidate`, `verify_candidate`, `submit_candidate`; use `{}` for fit and an object-valued `candidate` argument for verify/submit, matching `ToolHandlers.call` (`executor.py:56,99–119`). Reuse the Unix-socket transport, not the old seven-tool dispatch: `registered_tools.ToolBridge` rejects B's fit/verify names and its existing submission requires a path and the D7 schema (`experiment_scaffold/src/causal_branch/registered_tools.py:46–54,218–236,288–326`). Supply a ToolBridge-shaped B wrapper `execute(ToolRequest, *, regime_id) -> ToolResult` that forwards to the **same** per-turn `ToolHandlers`, normalizes success/refusal/error and preserves request IDs; regime identifiers stay host-side. This fits the existing `default_executor(tool_bridge, regime_id)` (`experiment_scaffold/src/causal_branch/tool_socket.py:274–284`) and socket framing/capability-token/duplicate-ID rejection (`:1–16,180–204`). Retain the extension's observed prompt hooks and schema/surface digest checks (`experiment_scaffold/pi_extensions/scientific_tool_bridge.ts:179–304`); do not expose the legacy tools. Socket run/branch identifiers are transport metadata, not prompt content.

Pass the same arm-blind per-root `launch_cwd` across all branches while the wrapper owns each branch workspace; Pi appends process cwd to the system prompt (`pi_agent.py:102–125,423–437`). Keep directories free of discoverable append prompts and validate observed rendered/request prompt digests. Launch with the explicit extension/tool allowlist and disabled built-ins, skills, context discovery and templates (`:929–944`). Fold checkpoint-2 arrival text into the submitted `prompt`; do not append a hand-written user record. Neutral slot names alone do not prove arm blindness: `b0`…`b3` map to regimes in the scripted executor (`executor.py:53–55`). Native headers include filesystem paths, so fixture normalization and translator exclusion must also be reviewed.

**Seed plumbing is incomplete.** The adapter's `run_turn` has no seed/temperature parameter and reports `REQUESTED_UNVERIFIED` (`pi_agent.py:187–192,364–389,625`); a repetition index is not a provider seed. A possible mechanism is an immutable per-turn endpoint sampling binding: `native_models_record` copies `endpoint.sampling` into native `samplingParams` (`experiment_scaffold/src/causal_branch/pi_models.py:21–59`), and vendored OpenAI completions merges sampling parameters into its outgoing body (`third_party/pi/packages/ai/src/api/openai-completions.ts:915–916`; options documented at `types.ts:181–189`). This is a code-level route, **not end-to-end verification**. D-DEC1 must fix temperature, repetition seed derivation and within-turn request semantics; then capture actual outgoing request parameters and server support before any stronger seed claim. No value or seed rule is chosen here.
