# Independent protocol review: B1 pinned-harness I/O overlay

**Verdict: ACCEPTED for the bounded protocol assessment of paper-side candidates `5efa3501` and `64b613fe`**, with the disclosure and limitations below. This is not evidence of numerical equivalence, full campaign readiness, or permission to launch. Reviewer: Codex, independent of implementation. This was source review only; no host, model, GPU, training, or experiment was used. The locally inspected harness HEAD was `a3fedbbd44309b3fdf99d853ad841b9ec2c299e2`.

The paper checkout leaves the pinned harness source on disk intact, but its execution is **instrumented**. In `r1/exam/campaign.py:182-196`, the real path installs the paper-side `B1IntegrityWorker` and the editable-preservation context before invoking the pinned `run_real_campaign`. `r1/exam/b1_editable_preserve.py:120-147` temporarily replaces the pinned campaign module's path constructor and configures guarded worker paths, under a serialized-use assumption; `r1/exam/b1_proposal_guard.py:59-77` also checks proposals and wraps artifact paths. Call this “the pinned `a3fedbb` harness with paper-side B1 runtime I/O and proposal guards,” not “an unmodified harness execution.” The author explicitly retains the harness pin and excludes cgroup containment; this assessment adds neither a harness replacement nor a new cgroup condition.

**Proposal, edit, metric, and recovery trace.** The manager is selected and passed to the pinned campaign in `r1/exam/campaign.py:177-196`; the overlay does not itself generate proposals. The existing integrity guard examines each proposal before the superclass worker (`b1_proposal_guard.py:73-77`), so unsafe proposals can STOP instead of following ordinary harness handling; it is not accurate to claim all possible proposal inputs behave identically. For an accepted proposal, pinned `src/autoresearch/worker/local_worker.py:129-186,353-398` still parses the directive, reads the selected canonical editable, applies its edit, executes the worker command, parses its log metric, and restores the original bytes on worker failure. The wrapper supplies a guarded path for that same selected editable. Pinned `src/autoresearch/control_plane/campaign.py:888-911,1514-1515,1954` snapshots declared editables and restores the appropriate snapshot for a discarded decision through the guarded path; this is a byte-level account, not proof of entire filesystem-state equivalence. Replay and audit still consume recorded proposals and configurations (`r1/exam/campaign.py:199-212`).

**Material differences.** For each guarded replacement the old inode is moved to a node-local `_to_delete` directory, a new inode is created at the canonical path, and requested content is written (`b1_editable_preserve.py:23-78`). Its mode is copied, but inode identity, timestamps, directory contents and potentially other metadata differ; retained versions increase disk usage. The replacement interval and extra I/O can affect elapsed time, scheduling and budget-bound outcomes: the pinned campaign uses `perf_counter` around worker work and budget consumption (`src/autoresearch/control_plane/campaign.py:1514-1531,1667-1683`). Source inspection of the three node Python directories found no recursive directory enumeration, inode or timestamp lookup; their OpenML benchmarks resolve fixed dataset, cache and artifact paths. That limited search is not proof that dependencies or all invoked programs are insensitive to metadata or retained files.

`r1/exam/b1_worker_artifact_guard.py:9-19` creates trial outputs exclusively and raises a `SystemExit`-derived STOP on a collision or failed write. Likewise, an editable preservation error escapes ordinary `Exception` handling. These deliberately alter collision/error recovery: they preserve the partial evidence and stop rather than overwrite it or proceed as an ordinary invalid trial. No automatic rerun or change is implied. Successful writes preserve intended content, but failures, resource exhaustion and timing can change campaign outcomes. The adapter is not a durability guarantee or defense against malicious same-UID interference; neither is an author requirement for B1.

**Evidence and limits.** Independent engineering review `docs/r1/reports/B1_PINNED_EDITABLE_ENGINEERING_REVIEW_20261107.md` at review commit `f1d9aaeb` reports 35 passing targeted tests with the actual pinned harness and mocked worker subprocess execution. The tests exercise edits, restoration, normal logs and collisions, but do not measure paired uninstrumented-versus-instrumented training, real model decisions, node runtime, host timing, or numerical outcomes. An initial run had 12 environmental failures before the reviewer set the pinned harness root; the review records both. The above source trace supports retaining the same underlying parsing and metric algorithms on the normal path; it does not establish statistical equivalence or a guarantee that instrumentation cannot affect the scientific result. Record the runtime overlay and these limitations with B1 provenance, and apply the existing host preflight and independent launch conditions to the integrated checkout.
