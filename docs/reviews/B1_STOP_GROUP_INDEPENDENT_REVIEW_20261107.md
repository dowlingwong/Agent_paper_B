**Result: ACCEPTED for the scoped fix** at `0606f5cd4b339b08737fc0e93392c080cc18a01f`, based on `d3066c1b`. This accepts the process-group repair for the previously reproduced root-exit case, not the complete B1 checkout or launch.

The production B1 campaign is started with `start_new_session=True`, making its root the leader of a new session and process group. The B1 parent observes root exit with `waitid(..., WNOWAIT)` without reaping it; on STOP it confirms the root is still its unreaped child, sends TERM and then KILL to that owned process group, and only then waits/reaps. Keeping the child unreaped protects its PID/group identity against reuse while signalling. If the child is no longer waitable, the check fails instead of signalling an unverified group; the shutdown error is recorded and the original STOP propagates. This is cooperative process-group management, not a cgroup, supervisor, freezer, receipt, or malicious same-UID defense. Pinned worker subprocesses and Python audit pool workers inherit this process group; no session change was found in the reviewed pinned worker and B1 campaign paths. External processes in separate sessions are not targets. A descendant that intentionally creates a new session would not be covered; no such behavior was found in these reviewed paths.
