# M3 offline replay boundary — independent design review

**4 November 2026. Verdict: NOT ACCEPTED as an implementation-ready design.** Independent review by Codex (AI-assisted). Reviewed the uncommitted design sketch `C3_REPLAY_OFFLINE_BOUNDARY_DESIGN_20261104.md`, SHA256 `c3feea054a665d1dcf7a83af510058666004bcc6be8d29ca0c937a26cce57b4b`, against the predeclared replay protocol, the prior M3 review and the pinned `6adf385` worker/benchmark source. This review used no remote host, real dataset download, real replay or GPU. The existing hard STOP stays in force.

## Major 1 — a needed download is already a STOP, not an open choice

The sketch's final paragraph asks the reviewer to choose whether an attempted but denied connection is a STOP. The predeclared protocol already says that a case which requires a download is STOP, with all configurations established executable offline **before scheduling**. Isolation that prevents egress is necessary but does not itself establish that the code never attempted to retrieve missing data. Define in the design what constitutes a data-download attempt by the exact OpenML load, require a trustworthy observable indication, and make such an attempt a STOP even if access is blocked. If the mechanism cannot distinguish or reliably observe it, fail closed rather than treating a returned dataset or unchanged cache alone as proof. If a different policy is desired, present it to the author as a proposed protocol change; do not silently weaken the existing protocol. Distinguish benign non-data-related attempts if relevant, with a justified and reviewable rule.

## Major 2 — the containment and its assurance are requirements, not yet a design

The sketch correctly notes network namespaces do not prevent pathname Unix-socket proxy access and mentions inherited descriptors and escaping, but proposes no concrete launcher, filesystem/IPC boundary, privilege model, trusted bootstrap or enforceable policy. A seccomp filter alone cannot be assumed to distinguish safe from unsafe pathname access or to prevent every route via shared files, named pipes, `/proc`/descriptor access and cooperating processes outside the boundary. Resolve the intended threat model, including what is assumed about other same-UID processes and host administrators, and specify how every named route within that model is prevented or detected. Identify the exact trusted parent, when filters are installed relative to exec/import, which file descriptors survive, which namespace or policy settings cannot be removed by descendants, and how a failed setup refuses execution. Where complete isolation cannot be verified, STOP; describe limitations instead of making a host-wide proof claim.

The manifest requests proof of inheritance for the whole process tree, but periodic PID snapshots alone can miss short-lived children. Specify the invariant or trusted launch mechanism that covers shells, grandchildren and all later descendants, and what observable evidence supports it. The host-supported permissions and kernel behaviour must be independently qualified; a sketch or a failure to connect to one endpoint is not that qualification.

## Major 3 — tests must exercise the actual loader as well as isolation

The proposed synthetic tests allow fakes implementing the selected API. Fakes are useful for negative controls but alone cannot prove that the pinned scikit-learn/OpenML loader has the expected cache-hit, partial-cache and network-attempt semantics. Require a local fixture-based integration test through the actual pinned `fetch_openml` implementation and the actual node/data ID path, with any network attempts captured by the trusted boundary. Cover complete, missing, partial, corrupt and wrong-identity cache states; demonstrate an attempted download produces the declared STOP and that no request escapes. If a pinned environment or representative fixture is unavailable, report that as an unverified prerequisite, not a pass. Keep fixtures synthetic and traffic local; this does not authorize retrieval of real data or remote execution.

## Assessment of the rest of the sketch

The sketch appropriately requires all-node preflight before scheduling any of the 16 cases; complete-return checks, per-node dataset identity, cache digests, fresh per-case copies, no writes to preserved inputs, explicit time-of-check/time-of-use handling and no inference of historical provenance from current cache hashes. It correctly keeps the exact pinned worker command, interpreter and seed controls and calls for synthetic metric equivalence without claiming historical equivalence. The eventual design must specify how exclusive ownership or another justified control handles the stated concurrent cache/source mutation threat, and must bind the actual execution copy to the preflight digest. Its proposed attempt tests, including IPv4/IPv6, DNS, Unix proxy, inherited descriptors and escape operations, are valuable but finite probes do not substitute for the enforcement invariant.

The author has not authorized a host capability check or the scientific replay in this task. A future concrete implementation and its tests, then separately authorized host qualification and independent review, are needed before reconsidering the STOP. Existing B.2 gates and historical results remain unchanged.
