## Blocking: error cleanup may abandon the child and descriptors

`r1/c3/offline_listener_probe.py:133–151` raises immediately if `pidfd_send_signal` in the `finally` block returns an error other than ESRCH. Thus it skips both `waitpid` and descriptor closes. A pure mock of a failed listener handoff followed by `PermissionError` from `pidfd_send_signal` raised that error and recorded `cleanup_calls []`: neither mocked `waitpid` nor `os.close` was called. A real blocked notification child could remain alive on this path. Even when signal delivery succeeds, `waitpid(pid, 0)` has no deadline, so the claimed bounded teardown is not established if a child is not promptly reapable. Fix by making descriptor closure unconditional, providing a bounded test-owned-child cleanup/reap policy that fails closed on uncertainty, and preserving evidence of any remaining child. Do not signal any unrelated process.

## Blocking: own-child PID identity is not guaranteed if auto-reaping is inherited

`observe` at lines 64–80 forks, then opens a pidfd; its fallback `os.kill(pid, SIGKILL)` at lines 144–148 uses the numeric PID if opening the pidfd failed. The code never verifies the SIGCHLD disposition. On Linux, an inherited ignored SIGCHLD disposition can auto-reap an exited child, allowing numeric PID reuse before pidfd acquisition or a numeric-PID fallback. Consequently the statement that every signalled process is necessarily the freshly forked child is not established. Require a demonstrably safe child-reaping/identity protocol before fork and avoid signalling an unverified numeric PID; cover the acquisition-failure path synthetically. Do not execute a real kernel probe to establish this.
