# Independent review: M3 supervisor pidfd wait hardening

**Verdict: ACCEPTED for the bounded, synthetic-only pidfd-wait change at `af20df0553b5d9cc5a38734abfb2490f7ecd9bd6`.** This is not M3 supervisor acceptance, Linux/site qualification, or replay authorization. Review was static; no tests were rerun, no host, model or GPU was accessed, and no workload or process was started.

The earlier poll loop entered `waitpid(pid, 0)` after any pidfd event. The candidate first handles a readable listener, fails closed on listener invalid/error/hangup and pidfd invalid/error/hangup, and uses `waitpid(pid, WNOHANG)` only for pidfd readability without pidfd error bits. Zero or mismatched return stops. This removes that blocking wait from the targeted event branch. Listener readability retains priority over a simultaneous child event or listener HUP, while pidfd error bits take precedence over pidfd readability. The new mocked cases exercise these specific branches and check `WNOHANG`; the implementer reports 55 synthetic tests passing. I did not independently rerun them or verify target-kernel behavior.

The teardown change reports `ChildProcessError` as an unverified child wait and still attempts the cgroup drain; the test models this and asserts the teardown operations. It does not establish that all possible wait or cleanup errors are bounded, nor that the cgroup, pidfd identity, kernel, bootstrap and listener protocols operate as mocked. Other teardown exceptions and the listener receive path remain outside this unit's boundedness claim.

**Remaining STOP:** a poll snapshot showing pidfd readiness does not establish that a listener notification cannot become readable or be withdrawn concurrently, and bare HUP does not prove absence of prohibited attempts. The candidate can still return `COMPLETE_UNQUALIFIED`; that value is not evidence of offline isolation or a production pass. The already documented interrupted-notification and HUP distinction, all 16 case bindings, complete supervisor integration, and ordered independent Linux/site qualification remain unresolved (`MAC_M3_HUP_SOURCE_BLOCKER_20261107.md`). No author decision or new host authorization is inferred by this review.
