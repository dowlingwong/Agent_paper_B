## Findings

1. **Completed and recovered roots can cross the authorized checkout boundary.** `r1/exam/runtime.py:571` returns an already completed root after `verify_campaign` and `:582` does the same for a recovered root, before the new job's authorization HEAD is built at `:592–596`. The campaign binding does not include the authorized checkout HEAD. Consequently a root created under a different checkout can be reused while the current parent reports the present authorization HEAD. Check the recorded root job's HEAD against the current authorized HEAD after campaign verification on both paths, and exercise mismatches and matches for completed and recovered roots. This finding is based on source inspection; the present production STOP prevents a real run.

2. **Child execution parameters are not bound to the authorized configuration.** `r1/exam/observer.py:25–51` verifies dryrun, host, node, seed, mode, candidate and checkout HEAD but does not compare the job's call cap, worker count, `W`, or audit seeds to `authority_config`. `r1/exam/campaign.py:140–143,156–159` uses those actual job fields. In a synthetic mocked observer context with configuration cap 80, workers 20, W 20, seeds 9101–9104, a job with cap 1000, workers 99, W 999 and audit seeds `[1]` entered the context. Require equality for all execution-relevant parameters, and add negative tests. No model or network was used for this reproduction.
