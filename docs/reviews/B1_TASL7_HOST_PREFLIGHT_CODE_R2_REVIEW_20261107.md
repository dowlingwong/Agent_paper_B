# Independent review R2: executable TASL-7 B1 preflight

**ACCEPTED as a bounded host-preflight implementation candidate** at `c1c4b67e5f00611d0939088ef948356c39223c35`, subject to independently accepted exact final checkout/note and the reviewed current site conditions. This is not a site result or authority to launch. No host, model or GPU was used in this review.

The previously reported early-start STOP defect is addressed for this single-process preflight. During `LlamaServerInstance.start`, the wrapper defers handled signal exceptions while the actual `Popen` executes, binds its owned process before acting on a deferred signal, then restores the module binding. If interrupted before a server record exists, cleanup checks the live unreaped child's actual process group equals its PID before supplying that identity to the existing `stop()`; it refuses a mismatched group. Repeated handled signals during cleanup are recorded instead of interrupting it. The later correction makes shutdown-error and lease-close diagnostics best effort, so a broken stderr does not skip the own-FD close or replace the initiating error. It does not assert successful shutdown or lease release on a failure, or guarantee cleanup after SIGKILL or against a malicious same-UID process.

Against pinned harness `a3fedbb`, I reran **12 passing tests**. These include owned real synthetic processes for interruption before record and during spawn, preservation of another independently owned session, refusal of a mismatched group, real local flock contention/release, repeated cleanup signals, and simultaneous stop/stderr failure. Other gate, GPU and server interactions are mocked, and the tests do not prove actual TASL-7 behavior. The corrected t7j10 digest matches config/authorization: `71525124fcf973ef7465fee9b0ff99c27b3f21b68f3a0ca55fcb9f7357992103`.
