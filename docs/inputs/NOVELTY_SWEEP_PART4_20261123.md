## 2. What Paper B takes from them

1. **Related work (R1-RELWORK-PART4).** Coco is cited next to Calibration Is Not Control as an example of learning when to act from outcome feedback with no explicit cost and with feedback that depends on the agent's own decisions; Paper B's contrast is the explicit run price and decision-independent audited labels. Skill2Env is cited for two points: Oracle/NOP acceptance as positive and negative controls, and evaluation with the same judge that supplied the reward as an instance of measuring with the instrument that was optimised against, which Paper B avoids by auditing on fresh seeds disjoint from the selection seeds.
2. **A positive and negative control row per node (R1-CONTROLS-ROW).** After Skill2Env's Oracle/NOP gate, done with noise in view: the negative control is the share of no-op proposals each rule keeps (zero by construction on bit-exact CPU nodes under a strict rule; informative where runs are not bit-exact); the positive control is whether the K = 10 audit detects E1 edits whose effect is known from the accepted 22 Oct runs. It shows that a negative gate result is not a measurement failure.
3. **Report process and outcome measures separately.** Skill2Env's rubric term pulled against the outcome reward on the training distribution. Paper B already reports governance measures (duplicates, inert edits, failed runs) apart from audited gain; this is cited as support, and no composite score is introduced.
4. **Prompt-rule memory as a cheap learner.** In Coco the evolving rule memory beat the LoRA on two of three backbones. Noted for the follow-up paper as a possible comparison arm; not added to Paper B.

## 3. What the follow-up paper (Paper C) takes from them

1. **Re-audit triggered by the number of keeps (R1-PAPERC-REAUDIT-MOTIVATION).** Coco's memory decays the confidence of stored propositions heuristically. T4 Proposition 9 (restated 22 Nov) gives a derived rule for the same need in Paper C's setting: the recorded incumbent's error rises at every noise-driven keep, so the need to re-measure grows with the number of keeps since the last fresh measurement. This motivates Paper C's re-audit-the-incumbent channel and the follow-up question of when to re-verify evidence after a pause.
2. **Generated and verified nodes.** Skill2Env's plan, diversify, create, verify pipeline is a template for generating new experiment nodes with acceptance checks (a node is accepted only if a known-good edit improves it on fresh seeds and a no-op does not), which would address the small node count. Out of scope for Paper B's submission.
