# M3 Linux supervisor implementation candidate — 5 November 2026

AI-assisted (Codex). **Candidate, unreviewed and unqualified; do not run real cases.** The existing production OpenML replay STOP remains in place and no production code calls this candidate.

## Implemented candidate

`offline_supervisor.py` and `offline_bootstrap.py` assemble a Linux x86-64 trusted-parent/child flow: a fresh private cgroup, pidfd check of the supervisor's own child, a parent-death guard, user/mount/network/IPC/child-PID namespaces, PID-1 parent-pidfd and death guard, a private tmpfs root with individual SHA-bound read-only runtime file mounts and hash-verified private working copies, read-only new procfs, chroot, inherited-descriptor closure, capability drop, no-new-privileges, seccomp user-notification listener handoff, audited prohibited attempts, cgroup kill and bounded teardown. It scrubs the environment by explicit allowlist, requires a new output outside caller-specified protected roots, and retains STOP on unexpected setup or monitor failures. These are implemented *candidate mechanisms*, not established invariants or a safety claim. It returns `COMPLETE_UNQUALIFIED` and provides no scientific replay authorization.

`offline_cases.py` separately validates static identity of 16 cases: two declared trial indices for each of eight nodes, file text hashes, seeds, the recorded worker command, and exact OpenML cache snapshot identities. It labels its output `NOT_ESTABLISHED` and does not run or schedule a case. A static case binding does not prove the 16 configurations are executable offline, that configuration-dependent I/O is absent, or that the environment has all dependencies.

The CPU-only test suite uses a BPF interpreter plus fake control syscalls, mocked cgroup/namespace/mount operations and an entirely simulated supervisor: **45 passed**. No kernel filter, real mount, cgroup, fork, server, model, GPU, or experiment ran. The tests check error paths and integration ordering but do not establish the kernel ABI, Linux process-tree semantics, immutable mount behavior, complete syscall mediation, user namespace policy, capability drops, race safety, or crash cleanup on an actual host. The actual pinned loader test is independently scoped in `MAC_M3_LOADER_SNAPSHOT_20261105.md`.
