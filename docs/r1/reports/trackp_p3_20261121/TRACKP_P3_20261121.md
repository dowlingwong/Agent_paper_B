## The switch to P3 (PRE-SPLIT A)

- `r1/c3/train/sft_data.py`:
  - The split config `split_file` = {path, sha256} of `r1/c3/splits/c3_p3_split_v1.json` makes the signed P3 split file the
    assignment and the universe (dev = the builder's `val`). It is read through `p3_split.load`, which checks the pinned
    sha256 and that the bytes equal the generator's output.
  - Salt or counts beside it are refused, as are another sha256, an instance outside the file and a universe that is not a
    subset of the file. A universe that is a subset is accepted, so the P.4 evaluator's recomputation
    (`assign_splits(union, config, universe=union)` over the recorded instances) reproduces a P3 build (tested).
  - The recorded universe is the P3 file's instances **of the table's nodes** (144 for the T0 tables), not all 240, so
    downstream test-instance counts are not inflated by T1 instances (`sft_data.p3_universe`).
  - **Real labels fail closed without it.** `build_sft_data` refuses a non-synthetic label source unless `split_file` equals
    the signed {path, sha256}; `load_sft_data` (and so `sft-dev`) refuses a real-label directory whose `splits.json` lacks
    it. The pre-signature `trackp_sft/v1` trial directories (1,176/47/74, which hold P3-test-instance labels) are therefore
    unusable with real labels, as §6's narrowing of R1-TRACKP-SFT-DEV to P3 train and dev requires.
  - `holdout_nodes` (leave-one-node-out) still puts whole nodes in test.
  - The duplicate rule stays R1-TRACKP-SFT-DUP.
- `r1/scripts/configs/trackp_sft.json`: `splits` now binds the P3 split file. The `trackp_sft/v1` salt, the 3/3/12 counts
  and the universe are gone; the comment records the replacement.
- `r1/scripts/trackp.py`:
  - A pinned table is a STOP unless the SFT config's `splits.split_file` is the signed one; the old universe branch is gone.
  - An unpinned synthetic dry run (`--table-pin none`, synthetic labels only) keeps the salt split, since its instances are
    not the design's. Every pinned (real) table is built on P3.
- `r1/tests/test_p3_split.py`: the disclosure test takes the old `trackp_sft/v1` values from `sft_data.DEFAULT_SPLITS`, since the
  config no longer carries them. The figures are unchanged: 5, 7, 6, 5, 6, 5, 6, 5.
- With unit 3, Track P's label source is the receipted train/dev partition. An SFT build on P3 therefore holds no row of a P3
  test instance (tested), and its labels can hold no test label (the release step's partition, re-checked on open).
- **The P.4 draft needs a change before merge.** Its evaluator (`sft_test_eval._check_assignment`, on
  `mac-trackp-p4-20261120` and `mac-trackp-p4-h200-20261121`) recomputes the assignment with
  `assign_splits(union, config, universe=union)`; with this unit that passes on a P3 build (tested here). But the draft's
  P4-P1SPLIT A text describes the salt mode plus a fixed universe ("over the fixed instance universe", `split: c3_p3_split/v1
  9/3/6`), which this config no longer offers: the draft's A text should say that the P3 split file is the assignment
  (`split_file`) and drop the salt-mode wording. That edit belongs to the P.4 draft's own unit.

## The P.3b exam set inside P3 train

- `r1/c3/train/exam_set.py` writes a membership file (`trackp_exam_set/v1`) from table rows only. It reads no label, audit or
  evaluation value.
- **Rule** (spec §5.3; R1-MAIN-PROPOSER-ITEMS "the P.3b exam set is drawn from the training partition"):
  1. **Universe:** one source's audited proposals (no rule-skips) on P3 **train** instances of the T0 nodes.
  2. **Order and size:** instances ordered by `sha256("trackp_exam/v1:" + instance)`, taking the shortest prefix with at
     least 400 proposals and at least 3 nodes (whole instances).
  3. **Internal split:** the first `(7 n + 5) // 10` instances (0.7 n rounded half up, in integers) are exam-train, the rest
     exam-val. Exam-val proposals that repeat a key of any exam-train row (rule-skips included) are `val_seen`.
  4. **Flags:** `below_target` (a STOP: `write` refuses), an empty exam-val (a STOP: `write` refuses), `above_target` (500;
     printed, the file is written).
  5. **Label join (later):** `check_labelled` STOPs if any member lacks a `y_train` record (ids only).
- **CLI:** `python -m r1.c3.train.exam_set write --table DIR --table-pin sweep1_v3 --source sweep1 --out FILE` (prints the
  sha256); `verify` regenerates the file and compares bytes. The table must match the pin in `trackp_sft.json` `tables`, and
  the source must be the pin's sweep (`sweep1_v3` → `sweep1`, checked in `draw` itself); the pin, its sha256 dict and
  the SFT config's sha256 are recorded in the file.
- **Committing the membership:** the coordinating session commits it with its sha256 (Portal runbook Phase 6 (b)), from the
  pinned table, on the cluster or wherever the table lives. Its labels come later, from the receipted train/dev partition.
- **Scope:** the spec fixes "≈ 400–500 audited proposals from the training partition, ≥ 3 nodes, … internal split 70 / 30 by
  instance seed, grouped by edit hash". The salt is new, and the choices listed as EX-* items below are this draft's, not the
  spec's.
- **Provenance.** No exam set, membership file or `exam_member` column exists on any branch or in history (the reviewer
  confirmed), so "redraw" means drawing it for the first time within P3 train. The arms-frozen record's §4/§6 item "the exam
  set's provenance" should then read "first drawn after the signature, within P3 train; no earlier membership".
- **Feasibility.** From B.2's totals only (1,725 eligible of 4,999 sweep-1 proposals over 144 instances), P3 train (48
  instances) holds roughly 575 eligible sweep-1 proposals, so the exam takes about 70% of P3 train. A skewed distribution over
  instances could set `below_target`; the CLI then writes nothing and the author decides.

## Proposed author decisions

**EX-SOURCE: which source's P3 train partition the exam set is drawn from.** The (h) item adopted by R1-MAIN-PROPOSER-ITEMS
(PLAN, proposed (h) items) reads: "draw the P.3b exam set from sweep 2's training partition, or from sweep 1's with disclosure
until sweep 2 exists". Both sources share one P3 assignment (R1-MAIN-PROPOSER (e)).
- **A (recommended): sweep 1, disclosed, until sweep 2 exists.** This is within the adopted item. Its labels exist (the
  sweep-1 B.2 audit was accepted) and arrive through the R1-S2-LABELS-TRAINDEV-RELEASE partition. The item implies a
  replacement by a sweep-2 draw once sweep 2's labels exist; the author should say whether that replacement is planned.
  P.3b no longer selects and is not a gate for P.4 (R1-C3-POOL-EXAM; the P.4 draft's P4-ARMS).
- **B: sweep 2.** It waits for a sweep-2 B.2 authorization and audit (R1-SWEEP2-SETTINGS (2)) and its integrity check.
- **C: both, pooled by instance.** Not buildable with this code: `draw` takes one table, and the cross-source grouping by
  (instance, incumbent, edit) of R1-MAIN-PROPOSER (e)(3) is not implemented. It needs a further code unit.

The source is bound to the table pin (`sweep1_v3` → `sweep1`), so a table cannot be relabelled as the other source.

**EX-DUP: the exam-val grouping key.** The draft applies R1-TRACKP-SFT-DUP's `val_seen` with the (node, incumbent hash,
candidate hash) key; §5.3 says "grouped by edit hash".
- **A (recommended):** keep the SFT key, so the exam and the SFT data group the same way; P.3b's E2/E3/E5 read the primary
  exam-val (excluding `val_seen`), with the full exam-val as secondary, as in the SFT builder.
- **B:** group by edit hash only (coarser: more exam-val proposals become `val_seen`).

**EX-SPLIT: the 70 / 30 unit.** The draft splits by instance count, not proposal count, and does not stratify by node; a node
can appear only in exam-train or only in exam-val.
- **A (recommended):** keep instance count, unstratified (the spec says "by instance seed"; it is simple and reproducible).
- **B:** stratify by node (each node's chosen instances split 70 / 30).

**EX-STOP: the prefix size.** The draft stops at the first prefix with ≥ 400 proposals and ≥ 3 nodes (the low end of
≈ 400–500). When the node condition forces a longer prefix it is only flagged (`above_target`); a synthetic case reached
1,101 items.
- **A (recommended):** keep the low-end stop and the flag; the author reviews a flagged draw before it is committed.
- **B:** make `above_target` a STOP as well.

**EX-NOOP: rule no-ops.** The draft excludes every rule-skip (no-ops and within-campaign duplicates), though SFT trains on
`rule_noop` rows. Sweep 1 has 0 no-ops.
- **A (recommended):** exclude them (the spec says "audited proposals"; no-ops carry no audit label).
- **B:** include no-ops with their rule label.

**EX-ROUND: rounding.** `(7 n + 5) // 10` (round half up in integers; 11 for n = 15, 25 for n = 35, 32 for n = 45). Recommended
as is; the alternative is Python's `round(7 * n / 10)` (round half to even: 10 / 24 / 32), which is not recommended
(float forms such as `round(0.7 * n)` differ again, 31 for n = 45).
