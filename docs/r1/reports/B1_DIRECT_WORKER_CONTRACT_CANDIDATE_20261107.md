For production B1, the runner now creates each new campaign root exclusively and sends a worker context only through its owned containment launcher. Before grant it checks the contained bootstrap's actual cgroup and same-OFD lease using the existing ancestor-to-child `kcmp`; checks the guardian lease; and, for LLM candidates, checks the live parent-owned server lease and that its expected loopback listener socket is held by that server. The child inherits the lease, cgroup root and leaf directory descriptors, output directory descriptor, pidfds for the runner, supervisor, guardian and (for LLM candidates) server, plus the supervisor's live STOP channel. A versioned environment record supplies descriptor numbers and parent-bound job metadata; the worker independently checks those against live `/proc`, directory FD identities, the expected runner invocation, parent/supervisor relationships and start ticks, job SHA, and owned output inode **before campaign directory creation, node copy or manager work**. For an LLM it also checks the server's direct cgroup leaf, inherited lease inode, live pidfd, network namespace, exact IPv4 loopback `/v1` URL and listener socket inode. Software anchors require no server and the parent strips any inherited `LLAMACPP_BASE_URL`.

## Limits and required review

* This is a **cooperative same-UID** protocol, not cryptographic protection from a malicious same-UID process that fabricates an entire runner/supervisor/guardian hierarchy or changes checkout and `/proc` state concurrently. The parent establishes the child's and guardian/server's same-OFD lease by `kcmp` before grant; the child only checks its inherited lease and peer descriptor inode, not a second independent cross-process OFD proof. Supervisor/guardian liveness and output/server identities are point-in-time checks; later races and full STOP quiescence are not solved.
* The listener check requires the server and child to share a visible network namespace, an unambiguous `/proc/<server>/net/tcp` IPv4 loopback listener and readable `/proc/<server>/fd` socket links. A valid host with restricted `/proc`, IPv6-only listener or incompatible namespace will STOP. The authorized operator must qualify the actual Linux process, pidfd, cgroup, `kcmp` and TCP visibility before work, without touching other jobs; neither mock tests nor this report constitute site evidence.
* The parent-created job file/log and campaign root precede the child check; this unit binds the child's subsequent writes to the parent-created owned directory, not the entire parent STOP/creation lifecycle. The containment bootstrap currently attaches its log after grant but before `campaign` verifies the contract; a contract failure traceback can append to that log. The whole STOP scene, guardian/lease end-of-run behavior, parent process-tree quiescence, receipt/fault model, audit/cache/server snapshot preservation and pinned harness cleanup remain open. A previously recorded STOP must never be rerun.
* The check is specifically for non-DRYRUN B1. A DRYRUN direct invocation still follows the existing DRYRUN marker/observer checks; this candidate does not claim direct DRYRUN is safe on an exam host or cover its earlier pre-observer directory writes. It does not restore the former Stage A→B1 kill/resume test. All original author, PLAN, rule, Q2, test, host and handover conditions remain in force.
