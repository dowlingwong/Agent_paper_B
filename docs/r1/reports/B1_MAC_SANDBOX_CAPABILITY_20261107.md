## Double-protected syscall probe

Non-root DAC therefore denies changing entries in this directory independently of the tested sandbox. The exact mode/identity assertions, UID and owned paths are prerequisites; the result must not be generalized to a writable directory or a privileged process.

Both requests were made through `/usr/bin/python3 -B` by the same unprivileged UID, first in the auto-approved unsandboxed control and then under `(version 1) (allow default) (deny file-write-unlink)`. The scripts called `os.unlink(sentinel)` and `os.replace(source, sentinel)` and printed numeric `errno`. In the control both returned `13` (`EACCES`); with the profile both returned `1` (`EPERM`). This observed difference is consistent with a sandbox denial occurring before the DAC denial, but does not prove the policy covers those operations on writable paths, all rename variants, all filesystems, or any test process tree. The probe itself attempted two removal-like operations in each mode, but directory DAC prevented a successful removal even with no profile.
