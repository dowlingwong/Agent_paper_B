## R1 correction and STOP coordination boundary

Independent review `B1_OTHER_SNAPSHOT_PRESERVATION_REVIEW_20261107.md` was NOT ACCEPTED for a behavior-preserving, STOP-safe B1 unit. It identified (1) a server serialization change: Python's original `json.dumps` permits NaN and Infinity, and a health body could contain these values, and (2) an interleaving where `write_active` checks the STOP flag before its callback, but a monitor can detect STOP while the callback is still writing or exchanging; the separate campaign worker's audit cache has no demonstrated cross-process STOP barrier. Neither situation was observed in an actual B1 run.

This correction uses the prior server `allow_nan=True` behavior, retaining `allow_nan=False` for audit cache and batch state as before. The new in-memory regression compares server bytes against the original serializer for NaN/Infinity and verifies audit cache still rejects non-finite values before filesystem access.
