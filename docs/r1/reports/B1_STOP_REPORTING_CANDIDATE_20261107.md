# B1 STOP error reporting: scoped candidate — 7 November 2026

AI-assisted (Codex). **Candidate for independent review; not B1 readiness or a full STOP implementation.** The production B1 error path emits the original exception to stderr before attempting to save interruption/STOP state. If that save raises an ordinary `Exception`, stderr reports the save failure when possible and the worker handler re-raises the original exception; the main handler attempts to return failure. In the lock-absent path it does not save. `SystemExit`, `KeyboardInterrupt` and other `BaseException` subclasses from save or stderr are not swallowed and can interrupt that behavior. Later close or earlier stop failures can also mask or prevent return. The stderr stream is best effort: this does not prove durable STOP state or STATUS publication, which remain open. The worker's existing `stop_tree` and `wait` happen before reporting and can themselves mask the original error; this candidate neither changes nor accepts that unsafe signaling path. Closing or stopping service can also fail after reporting. Quiescence, ownership, no deletion, host checks, and other B1 prerequisites remain open.
