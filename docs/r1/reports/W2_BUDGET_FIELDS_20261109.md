## Change

| Where | Before | After |
|---|---|---|
| `r1/c3/features.py` | `budget_frac_left = 1 − (b − 1)/W` (trial index) | `1 − worker_runs_used/W`, with `worker_runs_used` summed over the observed prefix rows by the new `row_worker_runs(row)` |
| `r1/c3/train/serialize.py` | budget line "… (W − (b − 1) worker runs left before this trial)" | the same text with the true worker runs left, from the prefix rows; `budget_line(b, W)` without a count (the synthetic exam, which has no ledger) keeps the old value |
| `serialize.ROW_FIELDS` | six fields | adds `worker_mode` (past rows only; needed to count runs) |
| `NodeContext` | five campaign constants | adds `trial_budget` (default `None` = W): the trial (proposal-slot) budget for skipping arms, so the line need not read "trial 25 of 20"; no caller sets it yet |

`row_worker_runs` follows the rule `r1/c3/accounting.campaign_usage` uses for H.6 accounting (harness `ComputeBudget` semantics), extended for Track S hidden-result arms and rows without `worker_mode` (on those two kinds the two differ; H.6 runs have neither): a row whose worker ran counts 1; `worker_mode == "control_plane"` (E1 skips and D25 inactive-key skips, `campaign._skipped_record`) and `worker_mode` ending in `_precheck` (precondition rejections) count 0; a KG verify adds 2 r re-runs; a Track S `ghost`/`ctrl_only` row (a `control_plane` skip record whose `control.arm` hides a run that was executed and debited, harness `snapshot.py`) counts 1 — except that a ghost whose proposal failed the precondition check was debited 0, which only `branch_shadow.jsonl` shows. A row without `worker_mode` (older fixtures) counts 0 if it is a skip carrying a control record, else 1. A test checks the rule against `campaign_usage` on mixed rows. `accounting.py` itself is unchanged.

LLM calls left and proposal slots left are not shown in the prompt today, so nothing was added there (W2: "where shown").

## Identity on execute-all campaigns

On a campaign where every row ran the worker exactly once (no skips, no precheck rejections, no verify), `worker_runs_used = b − 1` for every trial, so the feature is bit-identical and the budget line byte-identical. `r1/tests/test_w2_budget_fields.py` checks this on five generated execute-all campaigns of W = 20 trials, with and without `worker_mode` on the rows, for the feature value (exact `==`), the budget line and the line inside the serialized prompt; and against a golden file generated by running the base commit's own code (`a15300ca`) on four W = 20 campaigns (three with failed worker runs; 76 views with a prompt), it compares the feature hash, the full rendered prompt text and the prompt meta; a companion test shows that marking one failed row as a precheck rejection makes every later view differ from the golden. The independent reviewer separately compared the base commit and this branch on 1,068 execute-all views (1,008 prompts) and found them identical. Other tests: skips, precheck rejections and a verify follow the true count; the missing-`worker_mode` fallback; the accounting equivalence; the check script.

**Not shown tonight:** identity on the real sweep-1 tables (they hold label seeds that may not be read tonight). `r1/scripts/w2_execute_all_identity_check.py <root_trials.jsonl> … --runs-total W` does that check: it reads only `budget_index`, `decision`, `worker_mode` and `extra.control` of each row (no metric, delta, edit or label), accepts `root_trials.jsonl` and `root_trials.jsonl.gz`, refuses sealed paths (exit 2), and exits 3 on any difference (W2: a difference is a STOP), naming the kinds of rows that do not count one run (precheck rejection, control-plane skip with its reason, verify). If sweep 1 holds D25 inactive-key skips or precheck rejections, its worker-run count is not b − 1 on those campaigns and the check will STOP; that is a real difference between the two definitions, not a bug, and goes to the author.

## Existing test changed

`test_c3_featurizer_online.py::test_control_plane_skips_do_not_count_as_invalid`: its online fixture wrote the skip row with `worker_mode: "local"`, which the harness never does for a skip (it writes `"control_plane"`). With W2 the worker-run count would then differ between the online and replay paths. The fixture now sets `worker_mode: "control_plane"` on that row; the assertions are unchanged.
