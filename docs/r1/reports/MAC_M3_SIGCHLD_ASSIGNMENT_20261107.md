## Problem and bounded change

`PrivateCgroup.add_own_child` verifies a pidfd as a live child but writes its numeric PID to `cgroup.procs`. A pidfd preserves its referenced identity, but does not by itself prevent the numeric PID from being recycled after child death and automatic reaping. If SIGCHLD is explicitly ignored or `SA_NOCLDWAIT` is active, Linux may automatically reap a child rather than leave a zombie ([Linux `waitpid(2)`](https://man7.org/linux/man-pages/man2/waitpid.2.html), notes on SIGCHLD); a numeric PID write after such recycling could move a different process. The preexisting candidate did not check those conditions.

The candidate `offline_child_identity` reads the Linux x86-64 **kernel** SIGCHLD action with `rt_sigaction` (syscall 13; eight-byte kernel sigset), rejects non-default handlers or `SA_NOCLDWAIT`, requires a single supervisor thread, and requires all maskable valid signals blocked. It also rejects callable or unknown Python signal dispositions, because a Python callback queued before masking could otherwise run between the check and the PID write. This conservative condition includes the normal CPython default SIGINT callback: an ordinary interpreter may STOP, and a separately reviewed dedicated launcher would need to establish suitable dispositions in its own process. The kernel-ABI structure layout is based on [Linux v6.6 x86 signal UAPI](https://raw.githubusercontent.com/torvalds/linux/v6.6/arch/x86/include/uapi/asm/signal.h), lines 86–93. `offline_supervisor` blocks maskable signals before checking the guard and forking, restores the original signal mask in the child before bootstrap, and keeps them blocked in the parent through cgroup assignment. `add_own_child` rechecks the guard at entry and immediately before the numeric PID write. The parent restores its original mask after assignment or during error cleanup; restoration failure is STOP. Under these stated cooperative, single-threaded assumptions, a child that exits remains waitable until the supervisor reaps it, preventing ordinary PID recycling during the write. Unknown platform, action, mask or thread count is STOP.

This is not a claim about an externally attached tracer or a hostile same-UID process, actual site kernel behavior, atomic pidfd-based cgroup assignment, full supervisor death safety or the ability to detect withdrawn seccomp notifications. No target host or actual Linux syscall was used in testing. A real-kernel and site qualification, reviewed independently, must establish these assumptions before any production consideration.
