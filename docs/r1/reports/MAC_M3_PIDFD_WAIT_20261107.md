# M3 supervisor pidfd wait hardening — candidate

AI-assisted (Codex), 7 November 2026. **Candidate for independent review, not M3 acceptance or replay authorization.** This unit addresses a narrower boundedness defect; the OpenML production STOP remains and no HUP-as-success path is introduced.

Previously `offline_supervisor.supervise` entered blocking `waitpid(pid, 0)` for *any* poll event on the bootstrap pidfd, including an error, hangup or invalid descriptor. A pidfd failure could therefore prevent the monitor from returning to its deadline or cleanup path while the child remained alive. The candidate gives pending listener `POLLIN` its existing first priority, treats listener `POLLNVAL` and pidfd error/hangup/invalid events as STOP, and only attempts `waitpid(pid, WNOHANG)` for a pidfd `POLLIN` without those error bits. A non-ready or mismatched child is STOP. Teardown no longer treats `ChildProcessError` as proof the child was reaped; it records cleanup uncertainty after still attempting cgroup kill, pidfd signaling and cgroup drain.
