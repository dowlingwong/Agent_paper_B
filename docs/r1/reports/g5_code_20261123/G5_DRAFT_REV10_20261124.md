## 3. The §5 block against `key-lines`: how it is rendered, and the render on `44c3d80e`

**How the lines are rendered.** `g5_tasl.main`, subcommand `key-lines <spec> [--k 10|6] [--k-row R1-…]`: it loads the
spec, runs `validate_spec(spec)` (not for launch) and prints `approved: true`, every line of `note_lines(spec, k=…,
k_row=…)`, `paper_commit` (the spec's `paper.commit`) and `spec_sha256` (the sha256 of the spec file's bytes). Inputs:
the spec file `sweep2/t1_tasl/g5_tasl_spec.json`, and the code of `g5_tasl.py` with the modules it imports
(`note_lines` reads the spec; `t1_table_readings` is `"; ".join(TABLE_READINGS.values())` plus the spec's Δ̂ choice).
`AR_HARNESS_ROOT` is not needed (a render without it on `44c3d80e` gave identical bytes).

**The exact command** (phase 2, on a clean checkout of the final code tip; the same with `<tip>` in the file names):

```

  /tmp/tgport312/bin/python sweep2/t1_tasl/g5_tasl.py key-lines sweep2/t1_tasl/g5_tasl_spec.json \
  > /tmp/staledev/keylines_<tip>_K10.txt
AR_HARNESS_ROOT=/tmp/pb/wt/t1h TMPDIR=/tmp/staledev/t PYTHONDONTWRITEBYTECODE=1 \
  /tmp/tgport312/bin/python sweep2/t1_tasl/g5_tasl.py key-lines sweep2/t1_tasl/g5_tasl_spec.json \
  --k 6 --k-row R1-K-CHECK-EXAMPLE > /tmp/staledev/keylines_<tip>_K6.txt
```
