## 5. Inconsistencies found between the draft and `main`, and judgments made

1. **Autoresearch's host check and third note.** Draft §1, §2.11, §2.13, P1 and P9 say the TASL-2 host check at
   `2d09f9a9` STOPped and that the third note is pending. On `main`:
   - the binding record `TASL2_ISOLATION_HOST_CHECK_AR_PIN_BINDING_20261122.md` (sha256 `cce9b8fb…`) reads PASS at
     `2d09f9a9`, after R1-G1B-AR-PY;
   - the third note `g1b_ar_t1_tasl_20261122.md` is signed.
   Autoresearch's G.1b run, its summary copy and P10 remain pending. Under G5-ARPEND A the record still carries all
   of them.
2. **Rows and the launch chain.** R1-G1B-JOIN and the TASL launch chain are on `main`. The draft calls them pending
   or not yet published.
3. **The G.4 note.** The G.4 pilot note was re-issued as `g4_t1_tasl_20261123.md` (paper commit `b5824240`, spec
   `fd9c6e9d`). The draft cites `g4_t1_tasl_20261122.md`. The spec's `pilot_basis` cites the 20261123 note.
4. **Angle brackets in the seed line.** The §5 line `per-call seed sha256("<manager seed>:<step>")` is rendered as
   `sha256(f"{manager_seed}:{step}")[:8]`. The reason is the draft's own rule that every `<…>` field of §5 is filled
   at signature (§11, "The signature itself"): a line that keeps angle brackets reads as unfilled. (G.5's
   `check_note` would have accepted it, because a value equal to its rendered line is exempt from the placeholder
   test; the earlier version of this item gave that as the reason, which was wrong.)
5. **Lines the §5 block lacks.** The block has no lines for values that §11 fixes. The rendered note adds:
   - `invalid_share_stop`, `infrastructure_stop` and `seal`;
   - `decisions` (options plus the row);
   - `e4_amendment_row` (MEM A);
   - `cuda_ipc_acceptance` (the verbatim line, when CUDA IPC is accepted rather than tested).
   Autoresearch's record path is written as a glob (`docs/r1/reports/*/G5_AR_PREREQUISITES_YYYYMMDD.md`), not as
   `<…>`.
6. **G5-MEM C** is refused as not built (see §1). The coordinator's task said the band doubles under "MEM B/C". The
   draft's STOP 9 says MEM B only, and the code follows the draft.
7. **G5-DIV B.** "The upper 95 % Clopper–Pearson bound" is implemented as the upper limit of the two-sided 95 %
   interval (upper tail 2.5 %), and the note line now says so. The draft does not say whether it means one-sided or
   two-sided. The
   40-audited minimum is applied under B and C as under A; the draft states it only for A.
8. **Host checks for G.5 jobs.** The switch requires the TASL-2 host checks at the G.1b pins (`c025f89a`,
   `2d09f9a9`), not at the G.5 commits. This follows P1. A host check at each G.5 commit would need a draft change.
9. **The freeze wait at a job start** STOPs on or after the deadline date. The deadline is a release date, and a job
   on that day cannot lead to a release by it. This is a consequence the draft's STOP 14 does not state, so the
   `freeze_wait` note line now says "no G.5 job starts on or after this date" and the author signs it. The date is
   read from the note (as `audit_K` is): a docs-only amendment naming an author row on main that names the new date
   can move it without re-issuing the spec.
10. **The note's file name** must equal the spec's `run_id` (`c3_t1_labels_<YYYYMMDD>.md`). The draft names both
    with `<YYYYMMDD>` but does not say they are the same date.
11. **`g5_pin_check` needs both G.5 commits in one checkout.** It runs in the node's family checkout, so each family
    checkout on TASL-2 must also contain the other family's G.5 commit. Cluster test C13 should cover this.
