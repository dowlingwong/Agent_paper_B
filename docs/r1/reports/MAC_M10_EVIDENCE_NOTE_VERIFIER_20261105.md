# M10 proposed EVIDENCE note verifier — bounded unit

AI-assisted (Codex). This is an independently reviewable **format-option verifier**, not an author decision or an enabled EVIDENCE path. `hk2_submit.py` still unconditionally refuses EVIDENCE and late-phase submissions; the real-submission switch remains off. No server, real scheduler, model, GPU or experiment was used.

`hk2_evidence_note.verify_note` validates the draft per-manifest schema in `HK2_EVIDENCE_AUTH_NOTE_FORMAT_DRAFT_20261105.md`: exact author, Boolean approval, HK6/HK7 phase, exact manifest SHA, positive bounded node count, K in {6,10}, and finite positive bounded GPU-hours. Both limit values are explicit caller inputs, not silently chosen author decisions. It checks a clean repository-top-level checkout, exact HEAD-backed regular note and manifest bytes, a matching evidence manifest kind/phase, absence of duplicate JSON keys, and the same clean HEAD at exit. It returns HEAD and checked fields; it has no code path to submit a job. Tests use synthetic temporary Git repositories and synthetic manifests.

This cannot establish an authorized job's actual command identity, node membership or resource use, that the post-HK5 numbers were chosen by the author, that K=6 has its separately required PLAN ruling, or that HK6/HK7 prerequisites and budget/accounting have passed. The verifier's committed-HEAD check is a process boundary: a repository writer could forge both note and manifest, and filesystem or Git state could race between checks. A fresh independent reviewer must verify the exact final checkout, author instruction, actual argv and task/input/output classification, phase-specific prerequisites, note bounds and manifest membership before any phase gate is implemented. No inference from a synthetically approved fixture is an author approval.

To unblock EVIDENCE, the author first chooses an accepted note format (per-manifest or another reviewed format) and, after HK5, determines the task nodes, K and budget. An implementer then binds the actual reviewed work identity and phase gates to the submit path; a fresh reviewer validates that integration and its tests. The authorized HoreKa agent separately qualifies site capabilities at HK1 and later phases. Effort: format/author decision, approximately one to several engineering days for identity and phase integration/review, plus site-dependent qualification. Until then EVIDENCE remains STOP; the verifier is not a second runtime switch.
