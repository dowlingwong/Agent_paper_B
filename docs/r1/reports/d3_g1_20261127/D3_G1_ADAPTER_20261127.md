## What it adds

`r1/c3/d3/campaign_chunk.py` reserved the D.3 adapter for a separate reviewed unit. This is that unit. It supplies
the factory the chunk shell calls:

```text
factory(spec, seed, campaign_dir, recorder) -> (run_real_campaign kwargs, ended_on | resolver)
```

The factory builds one campaign from `campaign_chunk.ChunkSpec`; the chunk still owns the layout, the output-directory
refusal, the hardware/proposer/lease refusals, `wrap()` and `SHA256SUMS`.

### Campaign manifest

Every value is read from one JSON file, schema `r1_d3_campaign_manifest/v1`. A missing or contradictory value is an
`AdapterStop` before a campaign directory is made.

| Field | Declared value / check |
|---|---|
| `stage` | `a` or `b`; stage `a` runs exactly the seven D.3a arms, stage `b` exactly the D.3b arm list |
| `nodes` | exactly the seven D.3 nodes, in order |
| `campaign_model` | one GPU model per instance's arms (R1-HOST-FREE (2)(c)) |
| `W`, `llm_cap`, `trial_budget` | 20, 80, 80 for every arm including A0 |
| `memory_mode` | `append_only_summary` |
| `verify_runs`, `verify_seed_base`, `verify_split_policy` | 2, 20000, `vary` (R1-D3-VERIFY-SEED; task `compute/20261127-16`) |
| `harness_commit` | `9bb416805175149eb87b71f28d77530572aa4bce`, the only pin this unit is written for |
| `proposer` | `gemma4_31b`; alias, http(s) base URL, GGUF sha256, `manager_proposal/v1`, temperature 0.2, thinking off |
| `constants` | `d3_constants.json` path + sha256 (the G2 artifact, `4f5f686b…`) |
| `noise` | `results/r1/noise/D28_REPAIR_20261027/summary.json` path + sha256 (`3d12ce05…`) |
| `predeclaration` | the D.3 pre-declaration path + sha256 |
| `split` | `c3_p3_split_v1.json` path + sha256 (`b5967dd7…`) |
| `data_cache_root` | optional; the OpenML cache template (`<root>/<node>/data_cache`) |

`check_pinned_files()` hashes the four pinned files; `check_harness()` compares a launcher's `harness_commit()` record
with the pin and refuses a dirty checkout. The adapter itself starts no server: `apply_proposer_environment()` sets
`LLAMACPP_BASE_URL` from the manifest and refuses a contradictory value already in the environment.

### Arms

| Arm | Built from | Verify |
|---|---|---|
| A0 | `ContinueController`, keep rule `default/v1` | no verify call |
| A0R | `d3_controllers.a0r_controller`, rule layer on, keep `default/v1` | no verify call |
| A1 | `TableArmPrior(ConstantPrior)` over the constants file's A1 vector; `RuleController`, fallback A1 | 2 runs, `vary`, base 20000 |
| A2 | `TableArmPrior(RulesPrior)` over the A2 vector; `RuleController`, fallback A1 | 2 runs, `vary`, base 20000 |
| LADDER | `d3_controllers.ladder_controller` with the fitted `c`; `eta = c · sigma_node` is re-derived and refused if it differs from the file | no verify call |
| FIXR3, EGATE | `make_replicate_factory`, design revision 6c; never the harness factory | engine-owned replicate runs |
| A3, A5 | `build_controller(..., learned={arm: LearnedArm})` accepts a frozen `PriorModel` from a later unit; without it the arm is refused | as the frozen prior unit declares |
| A6 | always refused here: it needs its own RUNBOOK P.5 / R1-C3-POST path | — |

A1/A2 vectors are read from the constants file bitwise; the adapter does not refit them. The noise constants
(`sigma_local`, `sigma_structural`) enter `RuleController`'s `sigma_cmp` per edit kind. The LADDER `eta` is the
IEEE-754 product the controller computes.

### Replicate arms (FIXR3 / EGATE)

`make_replicate_factory()` returns a `ReplicateUnit` for the accepted `run_replicate_campaign` loop: one `ManagerStatus`
from the current config, the manager's `manager_proposal/v1` proposal, the structured edit applied with
`features.apply_edit`, the candidate files hashed with `snapshots.config_sha256`, and one worker call per replicate
run. Before each proposal it restores the loop's `incumbent_config` to the node workspace, because the loop restores a
discarded candidate only inside the next step's first run.

**Memory (disclosed).** The accepted replicate loop owns the ledger and does not hand records to `propose`. The
replicate unit keeps one bounded line per completed run (`run <budget>.<j>: seed=…; metric=…`) and gives the manager a
`MemoryContext` built from those lines. This is a summary display, not the harness `TrialRecord` memory of a harness
arm; the chunk notes of a replicate run must cite this paragraph.

### `ended_on`

The harness factory returns a resolver; `campaign_chunk.run_chunk` calls it with the recorder after
`run_real_campaign` and checks the result against `ENDED_ON`. The resolver is `accounting.table_ended_on`, so a
campaign at W, at the LLM cap or an unfunded FIXR3/EGATE step gets the pinned analysis's value. A fixed string is
still accepted, so the accepted chunk tests keep their contract.

## Refusals (fail closed)

- a manifest value off the declared set (W, cap, trial budget, memory mode, verify settings, harness pin, schema);
- a changed proposer model, schema, temperature, thinking flag or base URL form;
- a constants, noise, pre-declaration or split sha256 mismatch; a node or arm outside the declared set;
- a constants node set that is not the seven D.3 nodes; a per-node `sigma_node` that differs from the noise table; a
  LADDER `eta` that is not `c · sigma_node`;
- an OpenML node with no `data_cache`;
- a learned arm without a frozen prior, and A6 always;
- an existing campaign directory (the chunk shell owns that refusal);
- a contradictory `LLAMACPP_BASE_URL`.

No label, evaluation or test partition is opened: the adapter reads the constants artifact, the noise summary, the
pre-declaration and the split file only.

- To return an `ended_on` resolver from the factory rather than predict the end before the run, and to accept the

  refused by that function, so the adapter does not invent a fifth reason).

  one-arm layout.
