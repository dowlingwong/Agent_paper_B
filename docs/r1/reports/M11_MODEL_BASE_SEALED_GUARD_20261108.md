# M11 Track P model base and Laya input sealed guards

**Fresh independent review required; scoped generic inputs only.** Based on the accepted wrapper-manifest review `c53f13034ee1b800458b16c5ed0b694331193013`, this change checks `build_model`'s path-like base, `init_from` and `tokenizer_path`, and `_laya_core`'s path-like encoder and weights before calling model loaders. The existing `refuse_sealed` applies to the root and each existing input-tree entry. Existing root symlinks and directory symlinks, even when non-sealed, are conservatively refused so that an unwalked directory cannot conceal a sealed descendant; traversal errors also fail closed. New/nonlocal model identifiers and ordinary existing directories remain available to the existing loader. This conservative symlink restriction is a behavior change, and walking large model trees has a cost.

These checks are a point-in-time input-tree inspection. They do not establish protection from concurrent mutation, hardlinks, later aliases created by third-party loaders, remote/cache paths internally chosen by those loaders, direct calls to constructors outside these two entrypoints, or all other training readers. They do not authorize any sweep-2 label read or D8 gate. The five author-held M3 files and B1 runtime remain untouched. Real model files, sealed data, host, network and GPU were not accessed.

Because the local test Python has no PyTorch, synthetic tests compile the exact source AST for `_guard_model_input`, `_laya_core` and `build_model` with fake loader dependencies. The combined new, manifest and hash guard tests returned **12 passed**, including sealed base, warm-start/tokenizer, Laya encoder/weights, nested sealed file alias, nonsealed directory-symlink refusal, and ordinary/fake-object dispatch. No full-module import, real model loading, or loader-created alias behavior was tested. Independent review should assess this limitation and the nonsealed symlink compatibility tradeoff before acceptance.
