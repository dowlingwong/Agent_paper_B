## 1. What the chain does

R1-T1-DATA-MANIFEST (option A) corrects the census data manifests of `mlgym_fmnist` and `mlgym_cifar10`: the census
recorded `source.datasets: 5.0.1`, while the frozen torch312 environment and both TASL hosts have datasets 3.6.0. The
four data arrays of each node are byte-identical. The G.1b, cross-check and G.4 specs are re-issued with the corrected
values, and their notes with only those changes. This is the first delivery, (a)–(c). (d), the AR spec of
autoresearch's G.1b (third note, R1-G1B-AR-ENV), is a later delivery on top of the published (a)–(c): the TASL-2 host
check at the AR pin STOPped (Python 3.12.16 vs 3.12.15).

`verify_launch_tasl` lets a launch checkout differ from its spec's `paper.commit` only in `docs/` and that run's one
spec file. The re-issued specs therefore form a linear chain on published `main` `3c3f822a`: one commit per spec,
each spec's `paper.commit` its commit's parent, each run launched from its own commit.

| step | commit changes | run(s) it launches | spec changes |
|---|---|---|---|
| (a) | `sweep2/t1_tasl/g1b_tasl_spec.json` | G.1b amendment (`mlgym_fmnist`, TASL-2); G.1b note 2 (three TASL-7 nodes) | the two corrected manifests; `paper.commit` = `3c3f822a`; run id unchanged |
| (b) | `sweep2/t1_tasl/g1b_crosscheck_spec.json` | the cross-check, full rerun | binds the re-issued G.1b spec; run id `g1b-tasl-20261121-b-xc2`; `paper.commit` = (a) |
| (c) | `sweep2/t1_tasl/g4_tasl_spec.json` | the G.4 pilot | the `mlgym_fmnist` manifest; `paper.commit` = (b); run id unchanged |
| (d), later | `sweep2/t1_tasl/g1b_tasl_ar_spec.json` | autoresearch's G.1b (third note) | not in this delivery: one commit on the published (a)–(c), re-binding the re-issued seven-node spec, `paper.commit` = its parent |

No code changes inside the chain: every launch runs the code of published `main` `3c3f822a`. The commit after the
chain adds this report, the joined-assembly module of decision G1B-JOIN (§4, inert without its row) and tests; the
generated launch table is the last commit.

**Order.** The runs that can go first come first: the G.1b, cross-check and G.4 values are reviewed, the AR host check
is not. Until (d) re-binds it, the AR spec on this chain is `main`'s: it binds the first note's seven-node spec
(`060aac91…`), so against the re-issued spec in the checkout `validate_spec` refuses it ("the seven-node spec differs
from the one the AR spec binds"): no AR launch from (a)–(c). A test checks this.

**Publishing.** The launch commits must stay ancestors of `main` with their shas: merge the branch (fast-forward or a
merge commit), never squash or rebase it (a squash or rebase fails closed: every launch then refuses).

**Tests at intermediate commits.** Only the launch binding is checked per commit. The `sweep2/t1_tasl` test suites fail
at the intermediate chain commits (at (a) and (b) the G.4 spec still binds the old G.1b spec, and at (a)–(c)
`test_t1_tasl_g1b_ar.py` still pins the first seven-node spec; the pinned tests are updated in the tail). Any preflight test runs at the chain tip, never in a launch checkout.

**Superseded notes.** The re-issued cross-check and G.4 notes supersede `g1b_xc_t1_tasl_20261122.md` and
`g4_t1_tasl_20261122.md`. Those signed notes could still launch from their old checkouts (G.4 under the same run id:
a complete attempt made that way would block the re-issued pilot's attempt of that node), so the coordinating chat
records the supersession when it publishes, and neither is used again.

## 4. Decision G1B-JOIN: assembling the seven-node row across the three notes (for the author)

**The problem.** The three sealed TASL-2 attempts (`mlab_ogbn_arxiv`, `mlab_imdb`, `mlgym_houseprice`) carry the first
spec's sha256 (`060aac91…`); `mlgym_fmnist` (amendment) and the three TASL-7 nodes (note 2) will carry the re-issued
spec's. `g1b_tasl.assemble`, and so `g1b_crosscheck.assemble`, admits one spec sha256 per table: the row cannot
assemble unchanged. R1-T1-DATA-MANIFEST keeps "the whole-manifest comparison rule and all code unchanged" and does
not say how the row assembles.

- **A (recommended): the same run id, and an assembly that joins the two specs under a strict rule.**
  `sweep2/t1_tasl/g1b_tasl_join.py`:
  - the predecessor spec (given as a file, e.g. `git show 985dd45d:sweep2/t1_tasl/g1b_tasl_spec.json`) and the
    re-issued spec have the same run id and node list and differ in exactly `paper.commit` and the two corrected
    nodes' `data_manifest_sha256` (`spec_difference`);
  - an attempt may carry the predecessor's sha256 only for a node outside the two corrected nodes;
  - each group is assembled by the unchanged `g1b_tasl.assemble` with its own spec and sha256, and the two are merged
    into one run directory whose `ASSEMBLY.json` names the re-issued spec and records the join;
  - the cross-check gate of `g1b_crosscheck.assemble_gated` runs first, unchanged, and writes the same
    `crosscheck_gate.json`, so `g1b_crosscheck.py summarise` reads the joined run as it is;
  - the predecessor must be the signed first note's spec (its `spec_sha256` and `paper_commit` on `main`), and the
    re-issued spec the one the cross-check binds;
  - `ASSEMBLY.json` records both paper commits, the job-code files that differ between them, and the unsealed
    infrastructure attempts given as not used (`mlgym_fmnist`'s two attempts under the first spec, in the runs tree).

  **Two code versions.** The first note's three attempts ran the code of `10fd3343`; the amendment's and note 2's run
  that of `3c3f822a`. Between them the job path (`g1b_tasl.py`, `t1_tasl_node.sh`, `sweep2/g1b`, `r1/noise`,
  `r1/harness.py`) differs only in the autoresearch-only branches of `g1b_tasl.py` (the AR spec kind, its validation
  and summary schema), the cross-check kind of `t1_tasl_node.sh`, and the AR environment's freeze file; `g1b_lib.py`
  and `r1/noise` are unchanged (the seven-node path, as the AR spec-support review found). A test checks this list.

  It reruns nothing, keeps the run id, and changes no job code (the module is used only after the runs, outside the
  launch binding). It refuses to run without the author row (proposed name `R1-G1B-JOIN`). Proposed row: "The G.1b
  seven-node row of run `g1b-tasl-20261121-b` is assembled across the first note's three sealed TASL-2 attempts
  (spec `060aac91…`, paper commit `10fd3343`) and the attempts under the spec re-issued by R1-T1-DATA-MANIFEST (paper
  commit `3c3f822a`), by `sweep2/t1_tasl/g1b_tasl_join.py`: the two specs differ only in `paper.commit` and the two
  corrected manifests; the job code differs only in the autoresearch-only and cross-check branches; each group is
  assembled by `g1b_tasl.assemble` unchanged, behind the unchanged cross-check gate."
- **B: a new run id for the re-issued spec, all seven nodes rerun.** No assembly change, about 5.5 GPU-h and 5.1 CPU
  core-hours more (the three sealed TASL-2 nodes, as measured; within R1-G1B-CAP), but it contradicts R1-T1-DATA-MANIFEST ("not rerun").
- **C: a new run id for the four nodes under the re-issued spec, and a join across two run ids.** It needs the same
  kind of assembly change as A, plus a run-id join; nothing gained.
- **Not posed: one code version.** (a) could sit on a side branch from `10fd3343`, merged into `main` before (b), so
  that all seven nodes ran the same code. The coordinator asked for a linear chain on `main`, and the code difference
  is reviewed as outside the seven-node path, so this is noted, not proposed.

**Autoresearch joins by node** under every option: its noise floor is its own run (`g1b-ar-tasl-20261122-a`, harness
`2d09f9a9`, `ar-cond7a`) with its own summary. `g1b_tasl_join.py floor-by-node` joins the seven-node summary and the
autoresearch summary per node, refuses an overlap, and requires the union to be the split file's eight T1 nodes
(`r1/c3/splits/c3_p3_split_v1.json`). The two are never merged into one assembly (G5-PIN B).
