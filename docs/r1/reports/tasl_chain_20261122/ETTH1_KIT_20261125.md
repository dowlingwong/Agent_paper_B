## 1. Node design (paper semantics, not suite code)

The node implements the paper's **Task 6** as a standard LTSF forecasting task:

| Item | Value |
|---|---|
| Dataset | ETTh1 (Electricity Transformer Temperature, hourly), 7 features (HUFL, HULL, MUFL, MULL, LUFL, LULL, OT), 17,420 rows; public ETDataset |
| Look-back → horizon | **336 → 96** steps, as the paper states |
| Split | standard LTSF **12/4/4-month** split: 8,640 / 2,880 / 2,880 hourly rows; the remaining 3,020 rows are not used (as in LTSF); chronological, fixed |
| Normalisation | per-feature mean/std fitted on the 8,640 training rows only; MSE on the standardised scale (as LTSF/1GC) |
| Windows | train 8,209 look-back windows, validation 2,785, test 2,785 (stride 1, window targets inside their split) |
| Metric | **MSE**; selection on validation (`AR_METRIC val_mse=`, minimize); test sealed (`AR_TEST test_mse=`, never selected) — R1-TRACKG-ROLE |
| Baseline (editable `train.py`) | **DLinear** (moving-average decomposition, kernel 25, two channel-shared linear projections; Zeng et al. 2023), batch 128, Adam lr 1e-3, MSE |
| Fixed budget | **2,000 optimizer steps** (`run_budget.kind: steps`; no wall-clock key anywhere — R1-BX-D5) |
| Workers | dataloader_workers 0, threads 4 (fixed) |
| Suite/domain | `1gc7rc` / `time series` (1GC-7RC is not a suite; the spec's `external_benchmark` says so) |

**Files (all frozen except `train.py`).** `run_fixed_budget.py` (frozen parent: data check, split, windowing,
standardisation, worker calls, MSEs, result channel), `ar_worker.py` (frozen worker entry, alone imports
`train.py`), `ar_fixed_loop.py` (frozen fixed-step **forecasting** loop: step budget counted on the optimizer,
seed, CPU batch order, loss log, plain-tensor prediction conversion), `ar_parent.py` / `ar_data.py` / `ar_isolated.py`
(byte-identical copies of the T1 harness shared helpers; `ar_isolated.py` sha256 `37d99ab0…` = master),
`prepare_data.py` (pinned download + hash + data manifest), `requirements.txt`, `LICENCES.md`, `README.md`,
`representative_edits/`; editable `train.py`. The spec is `configs/trackg/nodes/gc7rc_etth1.yaml`; the isolation
block is `entry: run_fixed_budget.py`, `args: ["--steps", "{budget}"]`.

**Deviations, stated.** (a) The suite's own evaluator/baseline are unavailable (repo 404), so the DLinear
baseline and the whole fixed-step API are **written by the port from the paper's description** — the appendix
must disclose "implemented by the port from the 1GC-7RC paper's description; not the suite's assets". (b) The
node uses its own frozen `ar_fixed_loop.py` (a forecasting variant of the shared classification loop; the
classification loop's `logits_array`/`n_classes` API does not fit 96×7 regression), with the same budget,
seeding, batch-order and plain-tensor safeguards. (c) The 1GC baseline's stated `Train 8,640 / Eval 4,800` in
paper Table 2 is not reproducible from the stated 12/4/4 split (which gives 8,640/2,880/2,880 rows; eval windows
2,785 per split); this port follows the paper's **explicit textual semantics** and records the ambiguity here.

## 7. Suitability, blockers and what this does not establish

- **Data obtainable reproducibly: YES.** Commit-pinned public CSV, hash-pinned in `prepare_data.py` and re-checked
  by the frozen parent; setup exit 0 on TASL-2; manifest stable. The licence conflict does **not** stop
  ENGINEERING_ONLY use, because the data are downloaded, not redistributed.
- **Suitable for a noise floor: provisionally YES, with three caveats.** (i) The baseline is deterministic on a
  same-seed repeat (B2 = B1 to the digit on the CPU); (ii) the declared edits move validation MSE by large,
  ordered amounts (0.6443 / 0.6937 / 0.6584 / 1.7157 vs 0.6546), so the task discriminates proposals — a good
  property for the S1.1 interaction and noise measurements; (iii) **validation MSE (≈0.65) is much larger than
  sealed test MSE (≈0.375)** because the LTSF validation period is harder than the test period. This is a
  property of the task and is disclosed: selection uses validation only (R1-TRACKG-ROLE), so the funnel/σ̂ must
  be read on the validation metric, and no test-based selection is done.
- **Blockers/unknowns.** (1) **Suite repository 404** (re-checked 25 Nov 2026): the kit is a paper-semantics port,
  not suite assets; the appendix/funnel must carry the disclosure, and the author/coordinating chat should
  accept that this candidate is "1GC public dataset, port-implemented baseline" (R1-1GC-FALLBACK allows the
  public dataset as an extra task, but not as a suite). (2) **Licence:** CC BY-ND 4.0 is the most restrictive
  claim and governs here; the three-way conflict remains an author/legal call before a label table cites ETTh1
  (U1 §9.3). (3) **No GPU/U2/G.1b**: VRAM, GPU wall time, GPU fixed-seed determinism, the 10-seed noise floor,
  the 3× timeout basis and D21/D28 are all unmeasured; the CPU smoke is not the census and `port_smoke_gpu.py`
  must be run on the GPU by the census agent with the pinned env/freeze and the pins above. (4) The port's budget
  and run-time estimates are CPU measurements; U2 must confirm the GPU time is in the intended short-run window.
  No STOP: the dataset **can** be obtained reproducibly and the task **is** usable for a noise-floor port; the
  remaining items are the reviewer's acceptance, the author/legal licence line and the U2/G.1b runs.

**What this does not establish.** No measurement, no U2 raw cost, no noise floor, no determinism verdict, no
D21/D28, no label/evidence use, no GPU run and no Track G readiness. It does not re-check the accepted iso kits
or the base harness beyond the ancestry check, and it does not claim the paper's 1GC-7RC assets or evaluation
protocol (unavailable). Review is pending.
