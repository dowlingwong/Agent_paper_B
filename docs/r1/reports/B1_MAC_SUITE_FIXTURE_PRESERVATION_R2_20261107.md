## Pytest infrastructure preservation finding

Independent review `B1_MAC_SUITE_FIXTURE_PRESERVATION_R3_REVIEW_20261107.md` did not accept this unit after finding that installed pytest 9.0.3 uses `current_symlink.unlink()` in `_pytest/pathlib.py:215-220` when creating a numbered temporary directory. The two collision parameters used separate fixture directories but shared the truncated name `test_inheritance_extra_fd_fixtcurrent`. In the retained R2 base that symlink now points to `test_inheritance_extra_fd_fixt1`; pytest's code attempts an unlink before creating each current symlink. A prior symlink to directory 0 is not observable at that name. No syscall trace establishes whether pytest successfully created and removed the first symlink or its initial creation failed. The remaining R2 base, TMPDIR and log are preserved and must not be reused. This does not establish any deletion of real experiment or remote files.

Fresh basetemp and TMPDIR alone do not prevent the pytest unlink attempt. Earlier targeted pytest runs used the same mechanism and cannot be certified deletion-free from their final directory snapshots. No test was rerun after this finding. The candidate plugin `r1/tests/preserve_tmp_path_plugin.py` proposes a `tmp_path` fixture built solely by exclusive `mkdir` under a pre-created, empty, test-owned root, with unique names and no pytest numbered-directory or `current` symlink call. It is an untested proposal for independent review, not proof that pytest will select the fixture or that the process and dependencies do no other cleanup. Any future run needs review of fixture precedence, selected tests, pytest internals, any subprocesses, and a means of observing or enforcing deletion-free behavior across the relevant process tree; a plugin only affects the specific fixture and is insufficient to certify the full suite. Tests requiring `tmp_path_factory` or other temporary-file mechanisms remain outside its scope.
