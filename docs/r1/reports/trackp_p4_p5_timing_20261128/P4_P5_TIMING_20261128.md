The earlier P5 STOP left the timing receipts unable to show which kernels the SFT jobs bound. After the accepted E0
parity check, I repeated the 50-step `sft-dev` timing probe of each arm on the same admitted Ada venv and card, with
an `atexit` hook (`capture_hook.py`) that records the same `kernels_bound` mapping `trackp_gpu_smoke.py` uses, plus
peak device memory and the wall time. The hook is a capture instrument loaded through `PYTHONPATH`; no repository

`flock` on `/data1/zli538/r1_locks/gpu2.lock` (the per-card lease), in a fresh run directory, from the paper checkout
above; nothing resumed.
