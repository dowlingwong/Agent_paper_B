## Conventions decided in this unit (§5.8 leaves them open; for the review)

1. **Charged run 1 of RS is the start configuration.** This is the first trial each D.3a arm's harness campaign runs,
   and it gives the incumbent a metric. It counts as executed and, if it succeeds, as the first keep, as the harness
   keeps the first valid trial. It is not a draw. If it fails, the first successful draw is kept. SMAC3 has no
   separate start run: the start configuration is the default in its initial design.
2. **Executed configuration.** It is the start configuration with its active keys replaced. Two executed
   configurations are therefore equal iff their active projections are.
3. **Snapshot at w.** It is the incumbent after the keep decision of run w. At w = 20 this is the final incumbent, as
   the analysis requires.
4. **SMAC3 repeats.** A SMAC3 ask equal to an executed configuration is evaluated and charged again, and counted in
   both `duplicates_proposed` and `duplicates_executed`.
5. **Config hash.** `default_config_sha256` is the sha256 of the canonical JSON of the key/value configuration. The
   hasher can be swapped (see open question 2).

## Open questions

1. **The SMAC3 version and environment** (§5.8 `<TODO>`, §14) must be pinned before the SMAC3 rows run. SMAC3 and
   ConfigSpace are not installed locally, so the real `Smac3Backend` and `build_configspace` code is untested. It is
   written against the SMAC3 2.x ask/tell API and ConfigSpace ≥ 1.0. Only the driver's control flow is tested,
   through the stand-in backend. A smoke on the pinned environment, a CPU host and synthetic targets should precede
   the review of the run.
2. **The config hash must equal G1's.** `check_pair` compares the HPO-REF start hashes with D.3a's. G1 (branch
   `compute-d3-g1-snapshot-20261127`, `snapshots.config_sha256`) hashes the rendered editable files, so the HPO-REF
   runner must render each configuration into the node's editable file and pass G1's hash as `hasher`. That renderer
   is part of the HPO-REF runner on CPU hosts, which is not built here.
3. **Run 1 of RS is the start configuration (convention 1).** The alternative is to give RS the incumbent's metric
   without a charged run. That is not possible without an extra run, so convention 1 is recommended.
4. **The SMAC3 initial design.** "5 initial configurations including the default" is read as 4 design configurations
   plus the default (`additional_configs`). The run order of the default inside SMAC3's design is SMAC3's.
5. **G8 and G7 adoption.** When G8 merges, `HpoRunCounter` can be replaced by `ChargedRunCounter`. When G7 merges,
   `build_row` can be replaced by G7's `build_row` on `campaign_summary` plus G6 audit rows. The rules are the same,
   and the tests here pin the shape.
