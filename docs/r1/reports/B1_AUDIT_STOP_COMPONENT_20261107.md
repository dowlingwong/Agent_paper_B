# B1 audit STOP notification component — 7 November 2026

AI-assisted (Codex). **Unwired candidate only, independent review required.** The module `r1/exam/b1_audit_stop.py` provides a picklable audit wrapper that checks for a nonblocking pipe writer, calls the supplied real `run_config`, sends one byte before propagating an audit exception, and reports a broken/short notification while retaining the original audit failure as the exception cause. Its runner-side step marks STOP intent, invokes the supplied freeze callback even if marking fails, and reports an audit notification, unexpected EOF, malformed byte, unreadable channel or failed freeze as STOP; an empty nonblocking read does nothing.

Five in-memory unit checks ran with fake OS descriptor operations and mock guardian callbacks using `python3 -B r1/tests/b1_audit_stop_memory/test_notifying_audit.py`. They cover normal return, notification ordering relative to an injected audit failure, invalid descriptor, short/failed write, signal/EOF/malformed byte, would-block, and marking failure before freeze. No real process, pipe, cgroup, host, model, test cleanup or deletion was involved. This checks only the component's source behavior under mocks; it does not test actual `ProcessPoolExecutor`, runner, guardian, job or kernel.

**Not a working production STOP path.** Neither `r1.exam.campaign` nor `ExamRunner` uses this module yet. Descriptor creation, identity/OFD binding in the worker contract, fork inheritance, protected runner monitor and guardian freeze call, monitor lifetime, channel failure reporting, final success ordering and actual complete-path multi-worker tests remain unimplemented. A pipe-shaped descriptor alone cannot prove identity or a live reader. A failed notification may be returned as a failed future while the executor still waits, and this component cannot itself prevent that delay. Other process writes can continue until kernel freeze actually completes, and freeze failure cannot establish quiescence. The notification transports no audit exception details except through the existing future/log; this limited record is not an independent STOP receipt.

The Mac implementer must wire the component to the reviewed owned runner/guardian path and add a two-worker failure-ordering synthetic check; a fresh independent reviewer must check the wiring and failure paths, and an authorized operator must qualify actual Linux semantics before B1. Work is bounded by the explicit checklist in `B1_AUDIT_STOP_CHANNEL_PROPOSAL_20261107.md`, although actual effort and site time remain unknown. This candidate changes no author decision or harness pin and grants no B1 launch.
