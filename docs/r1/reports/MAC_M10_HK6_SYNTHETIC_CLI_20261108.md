No host, GPU, model or real experiment was used.

The caller supplies an explicit `SYNTHETIC_ONLY` JSON label and all plan identities, ordered seeds and shard count. `select` returns deterministic assigned pairs plus SHA-256 of the canonical supplied plan/seeds/count. `merge` binds each supplied synthetic shard to that hash, requires all shard indexes and then uses the reviewed completeness checks to refuse duplicates, wrong pair/shard, missing rows, wrong seeds and non-finite results. `history` invokes the cut-twice core; a twice-cut synthetic history emits STOP and exit 2. Each answer states `execution_authorized: false`. Input has a finite size limit and rejects duplicate JSON keys and non-finite JSON numbers.

These are process conventions on caller-provided JSON, not proof that data are synthetic, an authenticated prior receipt, or protection from a caller who falsely labels evidence. A numeric plan hash only binds the supplied values; it does not establish the real plan or provenance. The accepted shard core refuses `None` failures and does not implement the author’s 20% divergence STOP or the treatment below that threshold. There is no automatic retry or business-file mutation; normal Python imports read code and may create Python caches under the author’s documented exception.
