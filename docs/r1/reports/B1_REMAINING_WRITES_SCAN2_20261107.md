## Concrete unresolved bytecode risk

The real B1 worker is spawned with `worker_environment()` (`r1/exam/runtime.py:150–154,907–908,929–934`). It inherits the operator's environment and does not force `PYTHONDONTWRITEBYTECODE`; the harness `LocalWorker._run_command` passes `seed_environment`, which inherits that environment (`src/autoresearch/worker/local_worker.py:289–301`; `src/autoresearch/worker/seeds.py:27–44`). All three selected node commands invoke Python without `-B` (`configs/nodes/{digits_mlp,openml_credit_approval,openml_ionosphere}.yaml`, `run_command`), and their `train.py` imports `benchmark`. CPython may create or replace `.pyc` cache files when imports are stale and may clean up a temporary cache file after failure. This is a **reachable unqualified runtime behavior**, not an observed deletion or proof that it happens on the next run. The runner itself also imports modules before `worker_environment` is called; setting the child environment alone cannot establish an end-to-end no-delete property. The operator must use a reviewed startup/interpreter policy covering the supervisor, runner, worker, spawned node commands and helpers, followed by independently reviewed in-memory checks and a no-delete site qualification. Concrete implementer/reviewer effort is expected to be bounded by the entry points but has not yet been measured; target-host cache/environment state is not established.
