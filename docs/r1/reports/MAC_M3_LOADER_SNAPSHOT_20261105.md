# M3 pinned-loader and cache snapshot candidate — 5 November 2026

AI-assisted (Codex). This is an incremental implementation candidate, **not M3 acceptance, replay authorization, or proof of offline isolation**. The production OpenML replay STOP remains unchanged.

## Scope and evidence

`r1/c3/offline_preflight.py` computes a deterministic SHA-256 over every regular file of a nonempty cache, refusing symlinks and special files, and verifies exact committed bytes for `dataset.json`, `benchmark.py`, `config.yaml` and `train.py` against harness HEAD `6adf3859de66c4814fcf376eed59880fbd8eeaf7`. It reads the node and integer dataset ID from the verified `dataset.json`. It labels the result `NOT_ESTABLISHED`: a hash does not establish completeness or offline executability, prevent concurrent mutation, constrain worker execution, or identify historical cache provenance. It is not wired into `run` as a release gate.

`r1/tests/test_m3_pinned_openml_loader.py` exercises the actual `nodes/openml_ionosphere/benchmark.py` and `dataset.json` at the pinned Git commit, calling only `_load_frame`, using the locally installed scikit-learn 1.8.0 loader. Its synthetic fixture is scikit-learn's packaged iris test data with metadata assigned the pinned node ID 59. It is **not** an ionosphere dataset or a scientific measurement. The test intercepts scikit-learn's Python `urlopen`, denies Python socket construction and denies `os.unlink` to preserve the test cache; it never calls an external service, model, numerical training, replay, or GPU. A complete fixture loads and leaves its cache fingerprint unchanged with zero intercepted `urlopen` calls. Missing, partial, corrupt and wrong-ID fixtures raise; missing, partial and wrong-ID cases attempt an intercepted `urlopen`. The corrupt case is rejected but no conclusion is drawn about whether a later download would have been attempted. Local invocation with `AR_M3_PINNED_HARNESS=/private/tmp/paper-b-m3-harness-6adf385 R1_REQUIRE_M3_HARNESS=1` produced **8 passed** on Darwin arm64. This is not the required Linux seccomp monitored integration, and Python monkeypatching does not constrain native syscalls, descendants, or other network APIs.

The installed scikit-learn's `_retry_with_clean_cache` removes a cached file before a retry after non-network errors; the fixture prevents this with a monkeypatch. Actual replay must use private copies and the reviewed containment/provenance safeguards, never mutate preserved inputs. This observation does not authorize deletion.
