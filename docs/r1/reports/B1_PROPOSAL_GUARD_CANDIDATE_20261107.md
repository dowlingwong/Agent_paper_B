# B1 pre-execution proposal integrity STOP — candidate, 7 November 2026

**Not accepted; independent implementation and protocol review required.** This candidate adds a paper-side `B1IntegrityWorker` subclass around the unchanged, author-pinned harness `a3fedbb`. For non-DRYRUN B1 it compares the exact objective actually parsed by the pinned worker with the structured edit; it also requires a Python editable file's new value to be a finite numeric literal parsed with `ast.literal_eval`. It does not evaluate the proposed text, impose the node's numeric range, rewrite a proposal, change a manager, or change the harness. The three B1 node specifications each have exactly one editable file and the guard requires the target to be that file. On an inconsistency, missing directive, non-numeric or non-finite Python value, it raises a `SystemExit` subclass with STOP before delegating to the worker; this bypasses the pinned harness's `except Exception` conversion into a failed-invalid trial. It is intentionally a phase STOP, not a new invalid-trial classification or permission to retry. The exact string comparison is conservative: representationally different values that are numerically equivalent may STOP.
