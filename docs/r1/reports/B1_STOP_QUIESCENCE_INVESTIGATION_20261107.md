# B1 STOP quiescence: blocker and options — 7 November 2026

**STOP: no accepted production B1 STOP implementation.** Independent review `597de19e` rejected candidate `bb86931d`: it preserves a live worker, but that worker can continue model calls and output after STOP. Do not integrate or launch from it. This was a static investigation: no host, model, GPU, experiment, or process signalling was used. The rejected candidate and review remain intact in their branches.

The existing B1 runner starts the campaign worker in a new session (`r1/exam/runtime.py`, `run_job`). The worker can spawn a shell and training subprocess through the pinned harness `LocalWorker._run_command`, as well as audit processes through `ProcessPoolExecutor` (`r1/exam/campaign.py`). The model server is started separately (`r1/scripts/llama_server_instance.py`). Stopping or preserving the root alone therefore does not establish that all work has stopped. The current code does not establish an atomic owned-process-tree containment and quiescence mechanism, nor verify that an already submitted model/GPU operation has ceased. Census followed by PID/PGID signalling has membership, exit, reuse, and descendant-fork races; a pidfd pins one identity but does not by itself contain the full tree and server. Without a demonstrated site-supported containment mechanism and process birth protocol, I cannot establish a minimal fail-closed production STOP under the existing runbook.

The B1 runner passes its cooperative flock FD into the worker and server; `r1/exam/b1_lease.py` checks server FD inode identity, but the available evidence does not establish continuous lease possession after runner exit or quiescence of an already submitted GPU request. The runner's storage write can fail on ENOSPC and mask the triggering error, so durable STOP and published STATUS are also not established if the batch filesystem and all fallback channels fail. There is no demonstrated way to guarantee publication when every channel is unavailable; report such a failure rather than claim success.

**Unblock, owner, effort:** the Mac implementation agent must identify and implement a bounded, independently reviewed way to contain the *owned* server, worker, and descendants before workload execution; synchronize STOP with new work and process creation; observe containment and lease state; preserve the original exception if status writing fails; and use an independently checked operator notification channel. The TASL-7 operator must verify the required OS capability and ownership under the host-access rules, with synthetic owned processes, before use. A Linux cgroup freezer may be a candidate if delegation and suitable device behavior are established, but TASL-7 capability is **NOT CHECKABLE** here and a frozen CPU task does not by itself prove an in-flight GPU operation has stopped. If site capability is absent, a different reviewed mechanism or an author decision on a changed operational requirement is needed. Effort is **unknown** pending capability and design checks; it cannot responsibly be expressed as a fixed duration. No author decision is inferred.

Separate blockers remain: normal runner completion deletes its lock, the explicitly pinned harness deletes or truncates its pending guard and can delete a restored editable file, and exact-final-HEAD authorization, determinism, host ownership and handover are not complete. A code change must not silently replace harness behavior while retaining the original provenance claim.
