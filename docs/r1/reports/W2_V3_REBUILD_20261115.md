## 1. `r1/scripts/w2_runs_total_check.py`

**Inputs.**
- `--summary <file>`: the JSON printed by `r1.scripts.w2_execute_all_identity_check`. The cluster agent already ran
  that check read-only on sweep 1, so W2-3 needs no new data access.
- `root_trials.jsonl[.gz]` ledgers, recomputed with the same `check_ledger`. It reads only `budget_index`,
  `decision`, `worker_mode` and `extra.control`, and refuses `r1_sealed` paths before opening any file.

**The check.** Every ledger must have `worker_runs_total == --runs-total` (20). A ledger that differs is reported
with one of three kinds:
- `short_at_trial_cap`: fewer than W runs and at least 2W trials. The campaign stopped at the 40-trial backstop. This
  is the case where the worker-runs-left feature would show runs it could no longer use.
- `short_before_trial_cap`: fewer than W runs and fewer than 2W trials. The campaign ended for another reason.
- `over_cap`: more than W runs.

**Refusals (exit 2):**
- a summary that is not an identity-check output;
- a ledger count that differs from the results;
- a summary made with another `runs_total`;
- a field that is not an integer;
- a ledger listed twice (also across a summary and recomputed ledgers);
- a sealed path or a wrong file name.

**Exit codes:** 0 PASS, 3 STOP (proposed), 2 bad input.

## 2. Use in the rebuild (cluster agent; reviewed separately)

1. Run `python -m r1.scripts.w2_runs_total_check --runs-total 20 --summary <the sweep-1 identity-check JSON>`. If it
   passes, the worker-run feature is exact on sweep 1. If not, the differing ledgers go to the author before any
   table is rebuilt.
2. Rebuild every Track P feature table and prompt set from this branch (`c3_features/v3`, `trackp_prompt/v2`). Write
   `FEATURIZER_VERSION` and the prompt version into each table's manifest. Do not mix v1 and v2 prompts.
3. Disclose both versions and the budget-line change (the W2 stop-rule report, item 3). The synthetic exam
   (`trackp_e0/v1`) keeps the v1 budget line; that is question W2-4, still open.
