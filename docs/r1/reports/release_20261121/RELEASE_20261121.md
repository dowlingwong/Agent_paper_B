## Mechanism (module docstring)

**Release step** (`release`, CLI `python -m r1.c3.release`), once per (source, stage). Before writing, it checks:
- the D8 confirmation;
- the release row's exact text in a dated author table of PLAN §10;
- the frozen preregistration. The decision block is the only fenced block with a `frozen:` line, it ends the document,
  and comments are ignored. It must have exactly the signed keys, each once, and the signed decisions; `frozen: true`; the
  exact split-file line; and the committed builder and gate sha256s;
- the release-code commit: an ancestor of HEAD and `origin/main`, and the running `release.py` must be its file;
- for a test row, the arms-frozen record; for the T1 train/dev row, each G.1b summary;
- that HEAD is unchanged during the step;
- a clean checkout whose authority and the code the step runs equal `origin/main`'s: PLAN, preregistration,
  `release.py`, `release_checks.py`, gate, builder, split file, `p3_split`, `audit`, `dataset` and `analysis_guard`;
- that the integrity checks imported are this checkout's committed `release_checks.py`, and that `audit`, `dataset`,
  `p3_split` and `analysis_guard` are the plain module files beside `release.py` (no shadowing package);
- that the files the row cites (the arms-frozen record, the G.1b summaries) are published;
- the source's registered integrity check. A failure is reported by exception type only, without the original exception
  attached.

It reads the label block once and partitions those bytes. The integrity check's result must name the same bytes' sha256
(and, at the test stage, the evaluation block's); a result without these hashes is refused. A test
release must use the traindev release's label block and table. The receipt records the integrity module's sha256.

**Readers** (`open_partition`, `traindev_labels`, `builder_source`, and `sft_data.LabelBlockSource` for partitions). On
every open they check:
- the D8 confirmation for sweep-2 and G.5 partitions, before any file is opened;
- the receipt's source and stage against what the caller expects;
- the row and its bindings, against the receipt's own release-code commit;
- the output sha256s;
- the P3 membership of every row (from the proposal id's instance and the pinned split file) and the receipt counts;
- optionally, a pinned receipt sha256.

**Locks on the existing readers.** Before the test release row of its tier, the following are refused: a raw label block,
evaluation block or run log, and any file at or below a B.2 evidence audit directory (symlinks resolved; seed journals
included). `audit.RunCache` takes its tier from the directory's completion record: T0 for a B.2 audit, otherwise unknown,
which needs both test rows. A reader that does not
know its tier needs both tiers' test rows. The locks apply in:
- `sft_data.LabelBlockSource` (T0) and `audit.verify_evidence_completion` (T0);
- `offline_eval.assemble`, `env.label_rows` and `ni_masking.load_audits` (tier unknown);
- `audit.RunCache` (a non-empty run log at or below an evidence directory);
- `audit run/collect`, which refuse an evidence directory.

The evidence writer reads back its own run log inside `producer_context`. Pilot `audits.jsonl` files outside evidence
directories keep their path. Each reader's refusal is tested with an audit hook asserting nothing in the directory was
opened.

**Existing tests.** Four modules exercise the raw readers as they behave after the test release row. Each opens the lock
with one autouse fixture: `test_trackp_sft`, `test_c3_evidence_seed_isolation`, `test_c3_evidence_guards` and
`test_c3_evidence_attestation_stop`. The partition path's refusals (source, stage, completion, seeds, label-block sha,
derived sweep, index, classification, tampered rows) are tested in `test_c3_release.py`.

## Points for the coordinating chat

1. **Integrity checks.** Only `sweep1` is registered. Sweep 2 and the G.5 tables have no labelled audit yet, so their
   release STOPs until a reviewed check is added to `release_checks.py`. G.5 outputs are sealed; a reviewed extraction step
   must come first.
2. **Track P ENGINEERING reads stop until the train/dev release row.** `LabelBlockSource` no longer opens the raw sweep-1
   label block before the T0 test row; Track P reads the receipted train/dev partition once R1-S2-LABELS-TRAINDEV-RELEASE
   exists. This follows §6 and the queue: no label table is read until the freeze and the release rows.
3. **The release step reads the whole label block** in memory to partition it; the integrity check reads the evaluation
   block. Neither emits a value.
4. **Limits.** A lock forbids reads; it cannot prevent a deliberate read (copying a block elsewhere under another name, or
   editing a receipt together with its partition is caught only by the membership re-check). Such a read is a §6 STOP.
5. **Environment.** `test_trackp_soft_label_v2::test_existing_pilot_table_rebuilt_under_v1_is_byte_identical` fails in this
   desk's Python for lack of `lightgbm`, with and without this unit (an environment gap, not a regression).
