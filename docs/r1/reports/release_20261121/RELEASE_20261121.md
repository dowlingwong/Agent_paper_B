# Staged label release and partition-reading locks (PRE-STAGE A), and the §8 release-row drafts

Prepared by the Mac-desk agent (Claude), AI-assisted, 21 Nov 2026, for the signed preregistration
(`docs/r1/authorizations/C3_SWEEP2_ANALYSIS_PREREG_20261121.md`, R1-SWEEP2-PREREG) §9 (PRE-STAGE A, §6's integrity carve-out,
§8). It read no table, label or evaluation value; every test uses synthetic records in a pytest-owned checkout.

- **Module:** `r1/c3/release.py`. Tests: `r1/tests/test_c3_release.py`.
- **Drafts:** `docs/r1/proposals/R1_LABEL_RELEASE_ROWS_DRAFT_20261121.md` (approved: false): R1-S2-LABELS-TRAINDEV-RELEASE,
  R1-S2-LABELS-TEST-RELEASE, and for the G.5 note R1-T1-LABELS-UNSEAL and R1-T1-LABELS-TEST-RELEASE. The texts are produced by
  `release.row_text`; the release step accepts only the exact text (`release.row_pattern`).

## Mechanism

- **Release step** (`release`, CLI `python -m r1.c3.release`), once per (source, stage), refusing an existing output. It checks:
  - the D8 confirmation (gate v3.1);
  - the release row's exact text in a dated author table of PLAN §10 on the committed checkout;
  - the frozen preregistration: `frozen: true`, the pinned split file, and `gate_input_builder_sha256` and `gate_sha256`
    equal to the committed files;
  - the cited release-code commit, which must be an ancestor with this file's bytes;
  - for a test row, the arms-frozen record's sha256;
  - the source's registered integrity check, which returns pass/fail, counts and hashes only. A failure is reported by
    exception type, without its message.

  It then writes, through a `.partial` directory renamed at the end:
  - `label_block.traindev.jsonl` (train/dev label rows, byte-identical lines); or
  - `label_block.test.jsonl` and `evaluation_block.all.jsonl`, after the traindev receipt.

  Each partition gets a `RECEIPT.json` recording the row, bindings, input and output sha256s, counts (with label-kind
  counts, so divergence diagnostics without values are available) and the integrity result.
- **Readers:** `open_partition`, `traindev_labels` and `builder_source` (the builder's input) re-check the receipt, the
  row, the preregistration, the release code and the output sha256s on every open.
- **Locks on the existing readers.** A raw `label_block.jsonl`, `evaluation_block.jsonl` or `runs.jsonl` is refused until
  the tier's test release row exists (`guard_raw_label_path`), except inside the release step's integrity check
  (`integrity_context`). The lock applies in:
  - `sft_data.LabelBlockSource`, which now opens the receipted `label_block.traindev.jsonl`; the raw block is opened
    only after the test row;
  - `offline_eval.assemble`, `env.label_rows` and `ni_masking.load_audits`;
  - `audit.verify_evidence_completion`, which is locked before it opens anything.

  Pilot `audits.jsonl` tables keep their path.
- **Existing tests:** five modules exercise the raw readers as they behave after the test release row. Each now opens
  the lock with one autouse fixture (`test_trackp_sft`, `test_trackp_soft_label_v2`, `test_c3_evidence_seed_isolation`,
  `test_c3_evidence_guards`, `test_c3_evidence_attestation_stop`). The lock itself is tested in `test_c3_release.py`.

## Points for the coordinating chat (conditions, not decisions)

1. **Integrity checks.** Only `sweep1` (the sweep-1 B.2 audit, `audit.verify_evidence_completion`) is registered. Sweep 2 and the
   G.5 tables have no labelled audit yet; their release STOPs until a reviewed check for their completion record is added.
2. **Track P ENGINEERING reads stop until the train/dev release row.** `LabelBlockSource` no longer opens the raw sweep-1
   label block; Track P reads the receipted train/dev partition once R1-S2-LABELS-TRAINDEV-RELEASE exists (§6 narrows
   R1-TRACKP-SFT-DEV to the sweep-1 label block of P3 train and dev instances; the queue: no label table is read until the
   freeze and the release rows).
3. **The release step reads the whole label block** in memory to partition it, and the integrity check reads the evaluation
   block; neither emits a value (the receipt carries counts and hashes; a failing check reports only its exception type).
4. **A lock forbids reads; it cannot prevent a deliberate read**, which is a §6 STOP.
5. `test_trackp_soft_label_v2::test_existing_pilot_table_rebuilt_under_v1_is_byte_identical` fails in this desk's Python for lack of
   `lightgbm`, with and without this unit (an environment gap, not a regression).
