## BLOCKER (16 Nov, late): the 16k/32k layout numbers are VOID — worker runs never trained

Post-hoc audit of the S2-C4 pilot and 32k smoke ledgers found every in-campaign worker run ("python3 train.py")
ended in 0.0–0.1 s with `success=False`, `metrics={}` (run.log: `ModuleNotFoundError: No module named 'numpy'`):
the collector/worker subprocess PATH did not include `/opt/r1/envs/harness/bin`, so `python3` was the container
system Python. The collection gates passed because they did not check worker success. Therefore **8,289 s / 9,387 s
per full chunk and 36.84/41.72 GPU-h contain no training**; R1-SWEEP2-LAYOUT's numbers are void until the fixed
2-instance 32k smoke re-measures the layout.

Fix (reviewed unit, `sweep2-main-20261116` @ `77c6394a`): prepend the harness venv to PATH for collector/liveness
worker subprocesses; add the sweep-1 worker-success gate (sweep-1 baseline from the frozen main corpus:
5,287/5,813 = 90.95% success; STOP on any zero-success campaign, on `successful_with_metrics == 0`, or on failure
rate > 9.05% + 5 pp). Re-measurement smoke submitted as clusters **759739/759740** (`s2smoke2-20261116-a`), idle
because no NEMO2 L40S ads; numbers will be replaced after it completes.
