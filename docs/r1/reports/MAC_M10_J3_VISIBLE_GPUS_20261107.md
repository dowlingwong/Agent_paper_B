# J3 job-visible GPU selector prerequisite — 7 November 2026

AI-assisted (Codex). Candidate for independent review; no submission, site access, model, GPU or experiment. HoreKa runbook §3(3),(7) says that GPU selection comes from `CUDA_VISIBLE_DEVICES`, records `SLURM_JOB_GPUS`, and tests the case where the latter is `3` while the job-visible selector is `0`. The new `hk2_slurm_allocation.py::job_visible_gpu` is a pure standard-library helper implementing that narrow environment interpretation: it selects the caller-requested zero-based visible-list entry and retains both original environment values, without using the Slurm field as a visible index. It rejects selector strings outside its lexical pattern, duplicate selector strings and out-of-range indices; lexical acceptance does not validate the syntax or existence of an actual CUDA device. It makes no choice of k, GPU placement or scheduling policy. UUID-looking strings are syntactic selectors only; the helper does not identify, enumerate or validate physical devices, prove that distinct selector strings identify distinct devices, run occupancy checks or verify Slurm environment authenticity. A future J3 runner must establish all those properties and correctly use the selected value when launching child processes.

The module is not imported by the runner or submitter, does not check author notes or classify work, and does not grant authorization. EVIDENCE and HK6 remain unconditionally refused by the existing submitter, and its real-submission switch remains off. It neither implements the J3 runtime, Slurm device mapping, configuration/budget choices, occupancy/server checks, signal/resume behavior nor the full M10 path. The absent J3 runner, executable closure and work-to-phase binding, G.5 note, post-HK5 scope and separate site verification still need implementation and review; see `MAC_M10_HK6_CHECKPOINT_20261107.md` for owners and estimates.

No temp directories, subprocesses or cleanup were used by these tests. They are not actual CUDA, Slurm or site checks.
