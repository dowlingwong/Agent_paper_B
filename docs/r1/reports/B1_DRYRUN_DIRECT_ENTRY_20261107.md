## R2: non-deleting temporary-root discovery

The first review `B1_DRYRUN_DIRECT_ENTRY_REVIEW_20261107.md` did not accept the candidate: an uninitialized CPython `tempfile.gettempdir()` may create and unlink a probe, and the previous `host_check` called it before refusing an exam host. The shared DRYRUN `host_check` now refuses `TASL-2`, `TASL-7` and `ucrtasl` (case-insensitive, short host name) before resolving any temporary root. On development hosts `_dryrun_temp_roots` reads an already configured `tempfile.tempdir` cache, or selects the first existing writable/searchable candidate from `TMPDIR`, `TEMP`, `TMP`, `/tmp`, `/var/tmp`, `/usr/tmp` using only read-only filesystem checks; it also keeps the previous explicit `/tmp` allowance. It does not invoke `tempfile.gettempdir` or a create/unlink probe. A current-working-directory fallback is deliberately not used; this is more conservative than CPython on a system without any of the known temporary roots and can STOP an otherwise old-style fallback. As this helper is shared, this behavior applies to every DRYRUN phase using `host_check`, including Stage A; ordinary marked roots under a cached, environment or POSIX temp directory remain supported. `os.access` is a point-in-time approximation, not proof of actual write availability, and arbitrary environment configuration has the same cooperation/marker limitations as the prior tempfile selection.
