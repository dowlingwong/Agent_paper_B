## 4. Open for the author / operator

- **The 50-prompt file.** Drawing 50 sweep-shaped prompts from sweep-1 contexts needs sweep-1 data on deepthought;
  the tool takes the file and checks it, but does not build it. Who builds it, and from which ledgers?
- **Projection inputs.** The LLM calls per sweep-2 campaign (W = 20 proposer calls plus D25 revisions and side
  queries), the worker runs per campaign, the CPU time per run and the worker count are not fixed in one place; the
  operator states the values used, and without the CPU-term values the criterion is left unevaluated.
- **"Instance" disjointness** is checked by source ledger (`ledger_sha256`). If the author means more (for example
  node and seed against the exam's 9001–9004 namespace), that needs a definition.
- Not done (non-blocking review notes): per-call records and reply texts are not kept; prompt tokens and thinking
  content are not counted; the thinking policy is the B.1b one, not read from the registry, and no template repair is
  applied (a repaired-template model would need it); the `cache_prompt` check runs after the model has loaded; a
  SIGTERM to the tool can orphan the dedicated server (the `finally` covers exceptions, not signals).
- The runbook mentions the probe's `--keep-contents`; the probe at `d10b05b7` has no such flag. The tool keeps
  only the indices of non-identical prompts, not the reply texts.
- B1 separation (partial hand-off §6) still applies: this branch carries the mac-int version of
  `llama_server_instance.py` and must not be merged into a checkout B1 runs from.
