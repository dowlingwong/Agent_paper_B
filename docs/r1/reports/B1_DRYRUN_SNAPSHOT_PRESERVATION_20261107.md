# DRYRUN registry snapshot preservation — 7 November 2026

AI-assisted (Codex). **Candidate; independent review required.** When `ExamRunner.start` has no `batch_state.json` and DRYRUN is selected, it copies the registry to `registry_snapshot.yaml` using exclusive binary creation (`xb`) rather than `shutil.copyfile`. An existing destination, including a final-component symlink, causes an exception instead of truncation. If the copy fails after creation, the helper propagates the failure and deliberately leaves the newly created partial file in place. Non-DRYRUN behavior is unchanged. This narrowly addresses the prior source review's snapshot overwrite concern, not all DRYRUN startup writes or cleanup paths.

`python3 -B r1/tests/test_dryrun_snapshot_preservation_unittest.py` passed three pure in-memory fake-file checks: new snapshot contents, existing bytes retained, and a partial destination retained on synthetic write failure. The test extracts the exact helper from source with AST; it performs no real file creation or deletion and is not a filesystem, crash, concurrent actor, or full runner test. Exclusive-create semantics are standard Python file behavior but are not independently site-qualified here. The output directory and parent-path identity can change concurrently; these checks do not establish ownership or protect against a concurrent writer. They do not prove durable flush or STOP handling, nor authorize synthetic or production execution.
