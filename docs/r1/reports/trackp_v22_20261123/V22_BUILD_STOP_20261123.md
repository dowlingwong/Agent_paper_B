# Track P image v2.2 — STOP: no matching prebuilt causal_conv1d wheel (23 November 2026)

**Outcome: STOP before any Dockerfile/workflow change or image build.** R1-TRACKP-IMAGE-V22 option A requires a
prebuilt `causal_conv1d` 1.7.0 wheel whose **cxx11 ABI and torch/CUDA tags match** the v2.1 GPU image. The evidence
below shows that no such wheel exists on the v1.7.0 release: both the `cxx11abiFALSE` and `cxx11abiTRUE` cp312
cu12/torch2.6 assets link the C++11 `std::__cxx11::basic_string` symbol, while torch 2.6.0+cu124 in the image is built
with the old ABI and exports only the old-ABI `torchCheckFail(...RKSs)`. Option B (source build with
`_GLIBCXX_USE_CXX11_ABI=0`) needs a new author row.

## In-image torch values (v2.1 GPU digest `sha256:31478d99…663831`)

```
torch.__version__ = 2.6.0+cu124
torch.version.cuda = 12.4
torch._C._GLIBCXX_USE_CXX11_ABI = False
```

## v2.1 wheel and actual binary mismatch

- v2.1 Dockerfile pins
  `https://github.com/Dao-AILab/causal-conv1d/releases/download/v1.7.0/causal_conv1d-1.7.0%2Bcu12torch2.6cxx11abiFALSE-cp312-cp312-linux_x86_64.whl`
  sha256 **`5a76a78af8b600dac20cfc017bb45b7b650d27322f1d8f9250b28e51f6bf9ea9`** (confirmed against the GitHub
  release asset digest).
- `nm -D` on that wheel's `causal_conv1d_cuda...so`:
  - undefined `_ZN3c106detail14torchCheckFailEPKcS2_jRKNSt7__cxx1112basic_stringIcSt11char_traitsIcESaIcEEE`
    — the **C++11 ABI** `std::__cxx11::basic_string` form;
  - plus `_ZNKSt7__cxx1112basic_string…` symbols.
- The image's `libtorch_cpu.so`/`libc10.so` export only
  `_ZN3c106detail14torchCheckFailEPKcS2_jRKSs` and `...jS2_` (old ABI), so the import fails exactly as smoke 759983
  showed:
  `causal_conv1d_cuda...so: undefined symbol: _ZN3c106detail14torchCheckFailEPKcS2_jRKNSt7__cxx1112basic_string…`.
- The **`cxx11abiTRUE` cp312 cu12/torch2.6** asset (sha256 `a8f6e7ce…d7a7`) has the same C++11 `std::__cxx11`
  references; importing it in the v2.1 image fails identically. The release's "FALSE" asset is therefore not an
  old-ABI binary in reality.
- Other release assets have torch tags 2.7/2.10 (or cu11), which do not match torch 2.6.0+cu124. No cp312/cu12/
  torch2.6 wheel in the v1.7.0 release is ABI-false in its binary.

## What was not done (correctly)

- No Dockerfile/workflow edit, no causal_conv1d pin change, no build step addition and no GitHub Actions build.
- No v2.2 digest, no I3/I2 rerun, no smoke/E0/P.4. The staged smoke/E0 remain STOPped on the unchanged v2.1 image;
  no assertion was relaxed.

## Proposed fix (for the author)

- **Option B (source build):** in the v2.2 image build env3, build causal_conv1d 1.7.0 from source with
  `-D_GLIBCXX_USE_CXX11_ABI=0` (the torch ABI), then `import causal_conv1d_cuda, causal_conv1d` in env3 and fail
  the build on error. This needs a new R1-TRACKP-IMAGE-V22 author row for option B; the env3 freeze line would differ
  only in `causal_conv1d` at 1.7.0 (R1-TRACKP-V21-FREEZE), to be recorded.
- Option A with a matching prebuilt wheel is not available for 1.7.0 cp312 cu12/torch2.6.
- Authority: R1-TRACKP-IMAGE-V22 (option A) on published `main` `577bee4f` explicitly says that if no matching
  prebuilt wheel exists, the cluster agent reports and option B needs a further row. This report is that STOP.
