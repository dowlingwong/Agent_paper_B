## Findings from the installed pytest 9.0.3 sources

1. `.../_pytest/tmpdir.py:269-276,280-299` obtains `tmp_path` from `tmp_path_factory.mktemp(..., numbered=True)`. The fixture's finalizer can also remove the directory when retention policy is `failed`. `.../_pytest/pathlib.py:214-220,225-243` attempts to unlink the `current` symlink; the earlier synthetic run's finding and uncertainty remain as recorded in `B1_MAC_SUITE_FIXTURE_PRESERVATION_R2_20261107.md`. `--basetemp` creates a fresh base only when its exact path does not exist; if it exists, `tmpdir.py:149-154` calls `rm_rf` on it. Without a user-provided base, `tmpdir.py:205-215` calls numbered-dir cleanup, which registers an exit-time cleanup (`pathlib.py:385-403`).
2. `.../_pytest/capture.py:49-65,362-376,464-495,712-720` shows default `fd` global capture uses `TemporaryFile`, while `--capture=sys` uses in-memory `CaptureIO` for stdout/stderr. This applies only to global capture: the `capfd` and `capfdbinary` fixtures explicitly request FD capture (`capture.py:1109,1138`) regardless of the global mode; plugins or subprocesses can create their own temporary files. `-s` disables global capture but likewise does not remove individual capture fixtures.
3. Fixture choice is contextual, not a mere consequence of naming a plugin `tmp_path`. `.../_pytest/fixtures.py:558-603,1776-1800,1882-1906` orders matching fixture definitions, selects the nearest, and permits dynamic `getfixturevalue` and override chains that can request earlier fixtures. A plugin override must be verified for each selected item and its entire fixture dependency closure before execution; a later or closer fixture can select another implementation, and direct `tmp_path_factory` or `tmpdir` can still invoke pytest's built-in factory. A plain text search of `r1/tests` at this checkout did not find `tmp_path_factory`, `tmpdir_factory`, `capfd`, `getfixturevalue` or `pytest_plugins`, and found one direct `capsys` use. This is not proof that indirect imports, plugins, child processes or native libraries avoid those paths.
4. An absolute, same-UID root pathname alone does not establish fresh exclusive ownership, stable ancestry or identity across use. The rejected plugin's `lstat` does not prove its parent chain or prevent a same-UID participant from changing the path between checks. A future implementation could open an agreed trusted parent through verified directory descriptors, create the root exclusively, retain and revalidate its directory FD/inode, and create fixture subdirectories relative to that FD with exclusive creation. The exact trust assumptions, no-symlink ancestry, failure behavior and OS compatibility need implementation and independent review. This only addresses fixture path ownership, not deletion in the rest of pytest or child processes.
5. This Mac has `/usr/bin/sandbox-exec`, `/usr/bin/dtruss` and `/usr/bin/fs_usage` as filesystem entries, but their availability does not establish that a profile can prevent every unlink, rename-overwrite or recursive deletion by descendants, that tracing is permitted, or that failures are visible rather than ignored. No capability probe was run: a test which succeeds in deleting a sentinel would itself violate the author instruction. A Python-only monkeypatch is inadequate for shell tools, native code and alternate interpreters. A deny-only guard may silently change tests with `ignore_errors=True`; tracing without preventing a delete is too late to preserve it.
