The actual B1 worker starts as a new session (`r1/exam/runtime.py:731`), but its scientific subprocesses and audit pool are not individually supervised by the parent (`r1/exam/campaign.py:202-203`; pinned harness `src/autoresearch/worker/local_worker.py:276-299`). `runtime.py:736,757-758` uses `Popen.poll()` and, if the root remains alive, invokes `stop_tree`, whose PID census and later signal calls are separate (`r1/scripts/c3_label_sweep.py:304-335`). A descendant may exit, fork or move between those steps. If the root already exited, the handler does not establish descendant quiescence. Independently, the model server has its own session (`r1/scripts/llama_server_instance.py:355-356`) and its `poll`/group-stop sequence can reap or signal independently (`:398,408,470-485`). `exam_runner.py:407-408` calls `stop_service` on exception unwinding before the outer STOP handler, and server shutdown can write a record. These paths do not together demonstrate safe, complete owned-work quiescence and preserved evidence on every STOP. No such failure was observed in a real B1 run.

The M3 `PrivateCgroup` candidate cannot simply be reused as an accepted B1 solution. Its later write of a numeric PID to `cgroup.procs` depends on a child-lifetime assumption that the independent M3 SIGCHLD review rejected: Python parent-side `os.register_at_fork` callbacks were not excluded (`MAC_M3_SIGCHLD_ASSIGNMENT_REVIEW_20261107.md`). B1 also has separate server and audit descendants, and a disk monitor thread (`runtime.py:674-699`); blindly calling Python `preexec_fn` or raw `clone3` and returning to CPython would introduce additional unproved process/runtime behavior. A pidfd identifies one process, not its descendants; a process group can be a bounded cooperative mechanism only after the lifetime of its identity and non-escape of every relevant descendant are established. The present source evidence does not establish either condition.

A concrete cgroup-based *alternative*, not the only permitted solution, would create a fresh explicitly owned containment before workload execution, ensure the worker, its audit descendants and the separate server enter it without a numeric-PID reuse gap, bind the actual inherited lease and server identity, serialize STOP with creation/release, use site-supported subtree quiescence and verify it before publishing STOP, and retain all run evidence without deleting paths. Its launcher/exec/parentage, user delegation, crash/EOF handling, STOP-notification failure, and compatibility with the existing GPU lock and operator rules must be implemented and independently reviewed. A process-group anchor with verified identity and an explicitly evidenced non-escape condition is another possible route. Neither CPU process exit nor a cgroup state alone establishes completion or cancellation of already-submitted GPU work.
