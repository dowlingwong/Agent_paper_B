# B1 STOP alternatives: scoped source analysis — 7 November 2026

AI-assisted (Codex). **Investigation only; no production fix, launch, author decision, or claim of quiescence.** No host, model, GPU, experiment, process signal, or test was used. This supplements, and does not replace, the accepted blocker report `B1_STOP_QUIESCENCE_INVESTIGATION_20261107.md`.

## What the instruction requires

The author's 7 November prompt §0.4 requires stopping on a runner, guardian, author-gate, or anchor-gate STOP, preserving everything, publishing STATUS, and never automatically rerunning or changing the stopped scene. It does not explicitly require keeping owned compute processes alive. A reviewed stop of positively identified, owned processes while preserving their files and logs is a possible operational interpretation; the rejected `bb86931d` candidate's approach of leaving a running worker is not the only possible approach. A SIGTERM-triggered cleanup or server shutdown record can itself write to the stopped scene, so neither preservation nor an exception can be assumed: their observable effects need review. Do not infer authority to signal another operator's work or modify its files.

## Source-grounded candidate and limits

The B1 root worker is created with `start_new_session=True` (`r1/exam/runtime.py:634-635`). The pinned harness uses `subprocess.run` without `start_new_session` for node commands (`autoresearch/worker/local_worker.py:292-299` at harness `a3fedbb`), and B1 uses a `ProcessPoolExecutor` for audits (`r1/exam/campaign.py:164-169`). The frozen registered commands for the three B1 nodes are `python3 train.py` or `python3 train.py --config config.yaml`; the local node and harness source search did not find `setsid`, `setpgrp`, or `start_new_session` in these paths. This is evidence for a *candidate* cooperative process-group containment protocol, not proof that all dependency children, alternate execution paths, or future edits remain in the group. The separately started model server needs its own containment.

Current `stop_tree` (`r1/scripts/c3_label_sweep.py:304-335`) first enumerates PIDs, then signals them by PID. A child can fork or exit between census and signalling; an exited and reused PID can name a different process. It does not prove complete membership or safe identity. The server's `stop()` verifies a recorded PGID and then sends group signals (`r1/scripts/llama_server_instance.py:470-485`); the verification and signal are not atomic, and it writes a server record after stopping. Those behaviors cannot alone justify preserving the STOP scene or safely signalling the intended group.

A smaller-than-cgroup route worth engineering is to establish a dedicated process group/session *before* each owned workload starts; hold a separately verifiable group anchor for the entire STOP protocol; prevent arbitrary children from escaping it under an explicitly documented cooperative scope; serialize the stop request with any new server/worker spawn; halt the owned worker group and separately owned server; record whether each halt was verified; and preserve original exception and artifacts even if ordinary state writing fails. A process group is not a security boundary and a check-then-`killpg` race must not be called identity-safe merely because a start-time check passed. Running a group anchor in the correct session, its exit/reap lifetime, inherited descriptors, health-request concurrency, Python version support and independent notification need concrete implementation and review. If membership or ownership is unprovable, STOP and report rather than signal a potentially unrelated process. `SIGSTOP`/`SIGKILL` semantics, pending filesystem operations, and already-issued GPU work have different consequences; neither freezing CPU processes nor their exit establishes instant GPU quiescence without site evidence. A cgroup is one possible containment method, not an established necessity or an author-approved change to the protocol.

## Unblock

The Mac implementation agent can prototype and test an ownership-bound group-anchor protocol using only newly created, test-owned synthetic processes, with no remote host or GPU and no cleanup deletions; an independent reviewer must test races, escaped children, simultaneous STOP and spawn, status-write failure, scene preservation, and no unrelated signals. The TASL-7 operator must then verify site process, lock and GPU behavior after host ownership is established. Effort is unknown until the group-anchor and dependency assumptions are tested; if those assumptions fail, a different containment mechanism or an author decision is needed. This does not unblock the separate approved-note ordering, no-deletion/pinned-harness conflicts, real-worker determinism, capacity, final checkout, or handover gates.
