## What was added

`r1/c3/gate.py` — the path that `analysis_guard.require_d8_confirmation` already binds. It computes, from already computed per-instance utilities:

| Quantity | Implementation | Source |
|---|---|---|
| gap closed per node | (mean U_arm − mean U_A2) / (mean U_oracle − mean U_A2) on test instances | R1-BX-D8 |
| IQM eligibility | dev-split mean U_oracle − mean U_A2 ≥ δ_n; others excluded from IQM, listed, kept in PoI | R1-BX-D8, PROPOSED-CONFIRM (D8) |
| IQM across nodes | accepted `d8_point_statistics.node_iqm` (25–75 % trimmed mean, fractional edges) | briefing §1 option A |
| PoI | per node share U_arm > U_A2, ties ½, mean over all nodes (accepted core for the point value) | R1-BX-D8 |
| bootstrap | 2,000 within-node test-instance resamples; one index draw per node and resample shared by A2, oracle, A3, A5 | R1-BX-D8; briefing §2 option A |
| decision | Holm step-down over A3/A5, first-ranked arm at one-sided 97.5 %, second (only if the first passes) at 95 %; pass iff IQM lower bound > 0 **and** PoI lower bound > 0.5; gate passes iff the first-ranked arm passes | R1-BX-D8, PROPOSED-CONFIRM (D8) |
| practical size | point IQM ≥ 0.1 reported per arm, not part of the pass rule | R1-BX-D8 |
| tiers | T0 and T1 pooled; each node in one tier and resampled within node; node counts and descriptive point statistics per tier | PROPOSED-CONFIRM (D8) |
| partial T1 | every expected suite needs ≥ 1 T1 node, else STOP; node counts per suite and tier in the output | R1-B7-PARTIAL-T1 and its consequences |

Entry points `evaluate(input)`, `load_and_evaluate(path)` and `main` call `analysis_guard.require_d8_confirmation()` before anything else; `load_and_evaluate` also refuses sealed paths before opening the input. The private `_evaluate` is the calculation; tests reach it through `evaluate` with the authority check monkeypatched, or call `_validate`, `_point`, `_bootstrap` and `_holm_decision` directly.

## Implementation conventions not fixed by the PLAN rows (preregistration candidates)

These are the briefing's options, made concrete. They are fixed constants in the code and therefore covered by the gate SHA the author would confirm; they are listed so that the statistical reviewer can check each one.

1. **Seed and generator:** `SEED = 20261108`, `numpy.random.Generator(PCG64)`; nodes in sorted node-id order, instances in sorted instance-id order; per node one `integers(0, n, size=(2000, n))` call. The NumPy version is recorded in the output (2.5.3 in the 9 Nov test environment; the 8 Nov draft environment had 2.5.4); NumPy does not promise identical `Generator` streams across versions, so the analysis venv's NumPy must be pinned in the preregistration.
2. **Lower bound:** `numpy.quantile(boot, 1 − L, method='linear')` (percentile bootstrap, linear interpolation).
3. **Arm ranking for Holm:** ascending composite percentile p-value `max(P*(IQM ≤ 0), P*(PoI ≤ 0.5))` over the bootstrap draws, ties in the fixed order A3, A5. It only orders the arms; the pass criterion is the PLAN's lower bounds. The briefing's centered-bootstrap variant was not adopted: with a percentile lower bound the uncentered tail share is the dual quantity, and centering changes nothing about the decision rule. Whether the ranking statistic matters is open (§ open questions).
4. **Nonpositive denominators:** a resampled test denominator ≤ 0 on an IQM-eligible node STOPs the whole gate (count reported); so does a nonpositive point test denominator on such a node, or no eligible node. No resample or node is dropped (briefing §3 option A). Excluded nodes never STOP for this reason because no ratio is formed for them.
5. **Dev eligibility boundary:** "below δ_n" is read as strict; a dev denominator exactly equal to δ_n is eligible.

## Scope and limits

* **Prefix versus exact match.** The runbook asks that readers refuse without a row whose first cell *starts with* `R1-BX-D8-CONFIRM`. The accepted parser is stricter: the first cell (after stripping `*`, `` ` `` and spaces) must *equal* `R1-BX-D8-CONFIRM`, and the decision cell must match the exact affirmative template. Refusal without a prefix row follows. A row such as `R1-BX-D8-CONFIRM (10 Nov)` would also be refused; the draft therefore uses the bare ID.
* **Authority binds `gate.py` only**, not `d8_point_statistics.py`, `analysis_guard.py` or NumPy. The draft lists their SHA-256 for the record, but the parser checks only the gate file. Whether to bind the imported core too is an open question.
* **Input provenance is the caller's.** The gate does not build utilities, the noisy-oracle ceiling, the dev/test split or the 20-run scaling, and does not verify that the oracle used only the label-seed block. Those come from the offline evaluation path, which is outside this unit.
* **Not shown:** calibration of the composite procedure under the null (a Monte Carlo study), behaviour for very small nodes, and a stable-checkout/TOCTOU guarantee between the D8 check and later reads.
