# B1 pinned editable preservation candidate — 7 November 2026

Status: candidate, **not accepted**. Fresh independent engineering and scientific reviews are required before integration or B1 use. This is not launch authority.

The independent whole-path review found that the pinned harness writes editable node files during trial edits and restore. The author requires preservation of experiment output and remote files while retaining harness pin `a3fedbbd44309b3fdf99d853ad841b9ec2c299e2`. This candidate changes no harness checkout file and does not replace the harness. A B1-only paper-side adapter intercepts the pinned worker's editable path and the campaign's editable-state restore path. Before each replacement or removal it moves the existing regular file into a unique name in the node's `_to_delete/` using an exclusive, same-filesystem rename, then creates a replacement exclusively where required. Unsafe paths, links, unsupported exclusive rename, and errors cause a STOP; the adapter does not retry. A failure after the move may leave the original pathname absent, with the prior version retained in `_to_delete/` and any partial replacement preserved for inspection.

This is an intentional I/O behavior overlay, not a claim of unmodified behavior or scientific equivalence. It changes inode identity, directory contents and elapsed I/O; independent scientific review must assess whether this affects the registered B1 measurements or protocol. The adapter is scoped to the root-level editable files in the B1 node specification and the serialized B1 campaign process; it makes no guarantee against a hostile same-UID process, machine failure or durability failure. It does not change proposals, ledger logic, metrics, harness source or pin, and adds no retry, cgroup, supervisor or exit receipt. The existing B1 STOP paths remain applicable.

Synthetic Mac tests exercise actual pinned worker edit and error restore, actual pinned campaign restore including absent snapshots, actual campaign kept/discarded decisions with mocked node execution, STOP propagation, and symlink refusal. No model, node training, server or GPU was run. Test-specific mocks in the pre-existing proposal guard tests isolate an independently added artifact preservation step; they do not establish its production behavior. Review must inspect both overlays together and verify the exact integrated commit, including any interaction with existing process-management and STOP rules.
