# B1 audit failure notification to the guardian — 7 November 2026

AI-assisted (Codex). **Source investigation and implementation proposal only; not independently reviewed, tested or accepted.** No model, audit, process, host, GPU, signal, file deletion or node execution was performed. Paper source examined at the current base of this isolated candidate branch. The OpenML preservation candidate is a separate, not production-authorized harness change.

## Concrete failure path

`_collect_b1_review` submits `run_config` tasks to `ProcessPoolExecutor` and evaluates futures inside the executor's `with` block (`r1/exam/campaign.py`). `run_config` calls the real harness `LocalWorker.run_trial_at_seed` for each seed (`r1/c3/audit.py`). With the separate OpenML candidate, a node that returns reserved status 85 causes `PreservationStop` in LocalWorker. The exception can be carried as a failed future, but on raising from `future.result()`, the executor context manager shuts down with `wait=True`; other running and queued work can continue and complete before the collector process exits. The existing `ExamRunner` sees the collector exit only through its poll loop; only then does its exception path invoke the existing cgroup guardian's `freeze`. Therefore this code does not promptly freeze peer audits after the failure is reported to the collector. Canceling futures alone cannot stop already running tasks. This is a source-supported interleaving, not an observed experiment or STOP.

## Minimal implementation proposal

1. For non-DRYRUN B1 workers, `ExamRunner` creates one anonymous nonblocking pipe before spawning the collector. Pass the write descriptor through the existing cgroup bootstrap and worker-contract `pass_fds`, explicitly bound in the checked worker contract. Keep the read descriptor in the runner outside the owned subtree. The runner retains neither a write duplicate nor any file on disk. Validate distinct, correct descriptors and close unneeded ends; child subprocess commands must not inherit the notification FD. Existing author, supervisor, lease and cgroup entry checks remain applicable.
2. Launch a runner-owned monitor thread before the audit can run. It polls the read descriptor and, upon a failure byte, invokes the already-owned `B1Containment.freeze()` without signaling any process; the guardian freezes only the previously created B1 cgroup. Set a separate failure event, preserve the frozen scene, and make the normal runner loop check that event before treating the root as complete or publishing success. The runner's STOP path retains the event/error and records STOP only after its freeze attempt, preserving the existing explicit report of failed freeze. Do not read or mutate unrelated processes or cgroups.
3. Submit a small module-level wrapper around `run_config`. On an exception in an owned audit worker, write one bounded notification byte to the inherited pipe **before** returning the exception through the future. Explicitly use Linux `fork` for this executor if relying on inherited descriptors, and verify the descriptor and process membership in each worker before work. The collector also reports submission/serialization and pool failures via its own notification, because those can bypass the worker wrapper. Ensure notification failure itself produces STOP rather than a normal trial result. Keep the context manager's result and wait behavior for normal completion; after notification the frozen tasks remain for inspection, not auto-cancelled, signaled, deleted, or retried.
4. The runner must handle signal-before-loop, signal during a slow health check, child exit concurrent with signal, FD EOF, monitor failure, and normal shutdown. It must join/settle the monitor and check the channel before declaring root success; loss of the channel while work is live is STOP. A thread-safe, single freeze operation can reuse `B1Containment`'s existing control lock. A standalone non-B1 execution must not silently fall back to a fake signal path.

The signal-to-freeze interval is real: a peer can write between the failing operation and confirmed kernel freeze, and the proposer cannot honestly guarantee zero writes from the instant a physical fault occurs. The existing guardian reports whether `cgroup.events` reached frozen state; a failed or unavailable freeze remains STOP with the scene and lease retained as far as possible, not a claim of quiescence. Pipe errors other than a full pipe or an absent reader, process death before writing, parent/monitor death, fork FD lifetime and EOF behavior require explicit fault tests and site qualification. A one-byte atomic write and bounded number of audit workers reduce normal contention; actual capacity, readiness and failure behavior must be established rather than assumed. An inherited writer in an unrelated fork can defer EOF; parent must not treat lack of EOF as proof of normal completion. The user's instruction is to stop and preserve on STOP; the precise detection-to-freeze delay must be disclosed rather than described as instantaneous.

## Evidence needed before using it

The implementer and a fresh independent reviewer should exercise the real runner/collector wiring with synthetic in-memory or fake-process tests: two concurrently owned audits, preservation error before/during sibling execution, notification ahead of executor shutdown, freeze before STOP publication, no success publication, audit result channel failure, broken/full pipe and no-signal normal exit, monitor death, subprocess FD exclusion, child/guardian death, and process identity validation. Site checks must be separately reviewed and must preserve all test-owned artifacts under the strict no-deletion rule; actual Linux cgroup/fork/pipe semantics and safe handover are not established by mocks. A separate scientific review is needed for the changed OpenML artifact layout and exact pin. No author choice or launch authority is inferred.
