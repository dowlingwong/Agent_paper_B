## Independent review finding: deletion restriction violated

**NOT ACCEPTED.** The completed synthetic B1 runner called `ExamRunner.close`, which unlinks its test-owned `b1/runner.lock`; the completed root has no current lock and retains one stale lock from the killed parent. This violated the author's no-deletion instruction, even though the affected lock was synthetic. The archive was created after the run and therefore cannot preserve the removed lock. The earlier synthetic Stage A STOP root remains untouched and no actual B1 runner or guardian STOP was involved.

The synthetic campaign skips scientific `run_config`, but it does call the pinned harness `run_real_campaign` with `FixtureWorker`. Its trial path calls `_release_pending`, which unlinks a pending guard and falls back to truncation if deletion raises an `OSError`; the retained event files record 49 `pending_guard_released` events across 12 campaign trees. An event by itself does not distinguish unlink from the truncation fallback. Campaign state restoration can also unlink a previously absent editable file, while `write_json` atomically replaces existing state files. A replacement of only `ExamRunner.close` would therefore not establish preservation across the child process. No new run was attempted: a scoped test-only mechanism must first cover and independently review each reachable subprocess deletion and replacement path, without weakening production or resuming a recorded STOP. Exact byte-level retention of the already removed lock and any removed guards is not recoverable from the post-run archive.
