# Proposed X.5 v2 author-authority gate design (4 November 2026)

AI-assisted (Codex). **Design proposal only; not an authorization, final rule, or proof of author identity.** The current B1/B2 execution STOPs, the v2 `author_gate` containment STOP, and the B2 ranking STOP stay in force. This document proposes how to remove the v2 authority containment only after implementation, author decisions, synthetic tests and independent review; it does not itself clear those conditions.

## 1. Objective and authority boundary

For an evidence-mode `x5_rule/v2` B1 or B2 request, establish that the exact frozen rule, the dated author decision in PLAN §10, the phase-specific authorization note and the paper/config pins are those the author independently approved and published. A caller-supplied path, a working-tree row, local HEAD, a Git commit's author string, an `approved: true` JSON value or an unverified Git remote URL is not proof of author approval. The current `author_gate` v2 unconditional STOP is correct until the proposed chain exists. No `x5_rule/v2` row or B1 authorization note is created or accepted here.

**Trust root (open author choice).** Before a real use, the author must independently communicate through an authenticated author channel the **full published authority commit identity**, the canonical repository identity, the exact approved code commit, the phase and note path/digest, and the applicable independent review identity. A separately reviewed receiving process must record the authenticated communication verbatim, provenance, and the published commit and blob digests in a committed receipt; the receipt itself must be independently tied to that authenticated communication. It is not sufficient for a local caller to manufacture a receipt, choose a trusted Git ref or claim an author name. An implementable verification mechanism for this out-of-band trust root and how it reaches the operator remain **open**; an unconfigured or unverifiable verifier returns STOP. A cryptographic author signature is one possible design to assess, not an assumed capability or authorization; no key access or new key handling is authorized here.

The receipt must also establish that the authenticated author-approved snapshot is current and has not been revoked or superseded at the point of use. If freshness or revocation status cannot be independently verified, including while offline, STOP; do not infer validity from an old receipt or cached Git object. A reviewable freshness/revocation mechanism and its availability on the target site remain unresolved process and site conditions, not capabilities assumed by this proposal.

The authority commit may follow the code commit. It must contain the final PLAN and final phase-specific authorization note together, the accepted code tree and the exact frozen rule bytes. The trusted receipt binds the authority commit and the separately reviewed code commit, avoiding a circular request for a commit to contain its own hash. The code pin, authority pin, reviewer identity, note digest and resulting tree comparison are checked exactly; a claimed parent relationship alone does not prove file identity. Whether exact full tree identity or an independently reviewed explicit allowlist of permitted documentation-only changes is required is an **open author decision**, to be assessed by an independent reviewer. Until fixed, refuse differences rather than assume them harmless. The author, not an agent, decides when the proposed freeze and authorization take effect.

## 2. Resolve published state, checkout and immutable bytes

After independent receipt validation, identify the canonical repository and fetch or otherwise receive its full commit through the operator's existing authorized transfer process. Verify the full commit object ID and object format against the independently communicated value, and verify origin/repository identity against the receipt rather than trusting a remote name such as `origin`. A branch name is a locator only; mutable refs, local `HEAD`, and abbreviated SHAs are not authority. The author decides how the publication is attested where the deployment host lacks GitHub credentials, subject to independent review; a copy of a ref without verified publication provenance is insufficient. Never read key files or call a server during Mac-side development.

On the target host the operator uses a detached checkout at the reviewed authority commit, or a separately reviewed, explicit mapping between the code checkout and authority commit. Verify its full HEAD and tree identity, its required file bytes and modes, and no relevant dirty/index/untracked shadowing. Do not rely on an executable checkout merely reporting its own HEAD: the independently trusted launcher/receiver must check before executing it. Symlinks, path traversal, duplicate logical paths, non-regular blobs, ambiguous repository roots or Git object errors are STOP. Validate trusted receipt, PLAN, note, configuration and rule using bounded, exact bytes from the specified immutable Git trees; hash them with SHA-256 and record identities. Do not accept caller-controlled alternative note/PLAN paths or an independent unverified commit for either file.

Copying a file or reading HEAD once does **not** by itself guarantee the process later uses those bytes. The verified runner must consume the same pinned blobs for decision-making; executable code, rule and configuration must be immutable throughout the run or protected by a separately reviewed equivalent, with any unverified runtime mutation causing STOP. Git trees remain immutable as objects but a checkout can change. The isolation method and its proof on TASL-7 are unverified, and the gate must not claim them from a hash comparison alone. Protect against time-of-check/time-of-use, symlink and Git replace-object/ref-substitution behavior; reject dangerous Git configuration or use a reviewed scrubbed invocation and strict object identities. No host check or inference is authorized by this proposal.

## 3. Strict dated §10 decision parsing

Parse the pinned **PLAN blob bytes**, never a caller-provided or uncommitted working-tree document. Require valid UTF-8, exactly one `## 10.` section, and the exact first-cell ID `R1-EXAM-RULE-X5V2` in exactly one Markdown table row inside an unambiguously dated 4 November 2026 or later subsection. Date parsing follows a separately specified accepted grammar (for example `### 4 November 2026` with an optional time); reject malformed dates, nested ambiguity, duplicate matching sections/rows and unsupported table syntax. Do not count prose, comments, fenced code, escaped separators, examples, a matching ID in another cell, prefix/suffix variants, a heading outside §10 or a later superseded row. Where Markdown constructs cannot be parsed without ambiguity, STOP; avoid ad hoc substring fallback.

The authoritative **decision cell** must quote the author's actual words, as provided in the independently authenticated receipt, and bind the exact full 64-hex SHA-256 of the rule as an unambiguous token. Compare the full token, not a prefix or substring embedded in another identifier. Reject duplicate/conflicting hashes or inconsistent verbatim author text. Recorder-written proposed/open consequences, table headers, headings, comments and unrelated rows cannot supply the missing decision. If the author wants a decision cell whose verbatim wording does not itself contain the full digest, STOP and seek an explicit author decision on a separately reviewed binding format; the agent must not silently upgrade nearby recorder prose into authority. The actual rule row is still absent, and the unchanged draft SHA is not a freeze.

The author may later amend or supersede a decision. A verifier must apply a separately reviewed supersession procedure and reject ambiguity, stale authority snapshots and conflicting valid rows; no assumption that the first or latest matching textual row wins. The authenticated instruction must identify the applicable snapshot, so a new commit cannot be substituted by a caller merely because a matching row appears in it.

## 4. Rule, note and run-configuration binding

Load and parse the v2 rule from its verified Git blob using exactly the same bytes that are hashed; require the declared supported version `x5_rule/v2`, the unambiguous full SHA from the author decision and the reviewed code's expected semantic checks. Do not hash one file and parse a second read, re-resolve a mutable path after verification, or identify v2 only by a hash read from the mutable default path. Unknown/malformed versions, an alternate v2 rule, mixed or stale pins and parsing errors STOP. An alternative v2 file is acceptable only if separately frozen and authorized through the entire chain, not because its schema happens to parse.

Read exactly one explicit JSON authorization object in the pinned note; reject duplicate JSON keys, multiple candidate blocks, malformed values, non-boolean `approved`, wrong author, phase or full rule hash, and any mismatch with the authenticated receipt. Require the author-approved note's `approved: true` and the phase separately: a B1 note never grants B2, and vice versa. Check the actual frozen Stage A and amendment table bytes, acceptance-record bytes, their full pinned digests and paths under the separately reviewed source-transfer contract; a matching table hash alone is not an independent proof of source provenance. B2 also requires its independently authenticated B1 analysis and power-plan/complete-grid gates. Verify all pins against trusted reviewed snapshots, not merely mutually consistent attacker-supplied files.

Compare the author-bound note and reviewed configuration to each other and the actual run, including `nodes`, `llm_call_cap`, both Stage A table hashes, amendment acceptance hash, the paper code pin, harness pin, host and workers **if** the author approves these fields as machine-enforced bindings. The existing gate records but does not enforce `host`/`workers`; changing that contract is a proposed safety enhancement needing independent review and any required author decision. Do not silently interpret the recent 20/80/digits selections as a final authorization, as fixed host resource headroom, or as a decision on the unresolved amendment-acceptance hash. Also retain template-repair hashes, cache-false and observation evidence, seed policies, host gates and every separate protocol STOP. Missing or conflicting fields STOP before any network/model/GPU operation. The prior user decision concerns host placement, not permission to bypass code or note prerequisites.

## 5. Version separation and compatibility

`stage-a` and dry-run behavior remain subject to their own current gates; this proposal does not authorize dry-run as evidence. At the B1/B2 author gate, identify rule version from its verified bytes. The new strict authority chain is for v2 and must never be bypassed by pointing at a changed rule path, a matching old digest, an unsupported rule version, a locally edited plan or a dry-run flag in an evidence request. Keep the independent run-entry STOPs until the complete requirements for those code paths are accepted.

Preserve legitimate v1 behavior and v1 Stage A configuration without silently migrating it to v2. Establish the actual historical interface and run v1 regression tests on the real pinned v1 file and representative legacy configs, including no-rule or missing-field compatibility where allowed by the existing entry point. Any safety-driven change to malformed legacy inputs must be documented; do not falsely describe altered behavior as byte-identical. The existing v1 substring/working-tree PLAN check is **not** authenticated authority. Whether to harden it is separate scope and, if changed, requires its own compatibility design, independent review and any required author decision. No v1 compatibility exception can authorize new evidence or circumvent a v2 obligation.

## 6. Synthetic test matrix and review

All tests use fake author receipts, temporary local repositories and synthetic config/note/rule objects; they must not load models, contact services, read key material, infer real author consent or remove production STOPs. Include:

1. Positive synthetic v2 chain with an independently injected **test-only** receipt verifier, full commit/tree/blob bindings and an author-verbatim decision cell containing the full hash; check same verified bytes are consumed. Production must not expose this fake verifier or accept a caller-supplied bypass.
2. Rejection of absent, unverified, forged, stale or cross-repository receipt; untrusted local HEAD, moved ref, alternate origin, wrong object format/commit/tree, missing Git blob, dirty checkout, symlink/path traversal, replace-object substitution and plan/note byte changes after check.
3. PLAN counterexamples: missing §10, malformed dates, ID prefixes/suffixes, prose, other cells, comments, fences, other sections, recorder-only SHA, partial SHA, multiple hashes, duplicate/conflicting rows, unsupported escaped pipes, supersession ambiguity and matching rows in stale snapshots.
4. Note and rule counterexamples: duplicate JSON keys, multiple JSON blocks, non-boolean approval, changed phase/author/rule/table/acceptance hash, wrong or missing reviewed code/config/host/workers, alternate v2 byte file, unsupported/malformed rule, missing author note, inconsistent authenticated verbatim words and Git blob content.
5. Time-of-use tests: mutation of checkout or symlink after verification, path substitution, changes between hash and parse, subprocess Git/config manipulation, or unavailable immutability guarantee all STOP before the action. A fake test hook cannot establish real OS immutability; target-host qualification is separate.
6. Use actual pinned v1 rule and representative v1 paths to document preserved behavior and deliberate conservative exceptions. Existing v1 authority weakness remains disclosed. Verify stage-a/dry-run paths do not become evidence; verify all entry STOPs still fire with forged but self-consistent fixtures.
7. Integration checks for review/acceptance, B1/B2 configs and paired-audit worker semantics, harness `a3fedbb`, explicit `cache_prompt: false`, repair template hashes, and the two table/acceptance digests; do not enable ranking until its separate full-grid/reception gate is reviewed. Re-run focused and full Mac suites against the final implementation and compare exact failure IDs with the reviewed historical failure set; the 39 failures do not constitute a passing suite.

A fresh independent reviewer must examine the exact implementation and tests. If changes are requested the **same reviewer** rechecks until accepted. The final review must explicitly list unsupported trust-root or target-host assumptions and confirm all STOPs. A separate author PLAN row and a committed note remain necessary; design or code review alone does not authorize any experiment.

## 7. Open decisions and unresolved evidence

- Which authenticated author-to-operator channel and independently reviewable receipt format establishes the authority commit, note, code pin and reviewer; how published identity is verified without credentials on TASL-7; who can validate/revoke it.
- How freshness and non-revocation are independently verified at use time, including when offline; absent a reviewed, available mechanism, STOP.
- Whether all trees must match exactly or which documentation-only differences are permitted, and how the trusted launcher protects executable/runtime bytes for the duration.
- Exact acceptable dated-row grammar, how supersession is represented, and what to do if the author's verbatim decision cell does not contain the SHA (default STOP).
- Whether host and worker count become mandatory note fields verified by code, how 20-worker headroom is established, and the final amendment-acceptance hash.
- Whether and how separately to improve v1 authorization compatibility without changing frozen historical semantics.
- B2 power-plan, finalist/root evidence provenance and complete grid validation remain separate open prerequisites, as does M2 overall independent acceptance. Nothing here resolves or substitutes for them.
