# D3 protected-input / OFD candidate — SYNTHETIC ONLY

This is an isolated prototype, not a deployed launcher, reviewer acceptance, or proof of isolation. Its `production_entry` unconditionally STOPs. No production code or original STOP fixture is modified; P.3a and B.2 remain STOP.

`open_input` walks a caller-opened root with directory FDs, rejects symlinks, traversal, mutable-by-group/other directories, unexpected uid, hard links and non-regular objects, reads the actual held FD and compares SHA-256. `validate_held_fd` rechecks both identity and bytes. `kcmp_file_verdict` exposes only direct kernel comparison results, mapping unsupported/unavailable/error to NOT_CHECKABLE. It has a built-in Linux x86-64 ABI syscall number 312; other architectures and non-64-bit processes return NOT_CHECKABLE. The target runtime ABI still needs independent verification; callers cannot select a syscall number. PID and FD numbers must be separately bound to process start time, provenance, and safe lifecycle; this prototype does not establish those facts.

This cannot prove the root ancestor path, mount, libc/interpreter/imports or executable are protected. Separate trusted UID and protected parent/launcher still need admin provision. Since files remain writable by the expected owner, no guarantee exists against an attacker controlling that UID, or against a writer racing between the final check and consumption. Callers must consume the held verified object and establish the service identity and immutable backing separately. Hash and `fstat` are not atomic against concurrent modification, nor a substitute for a kernel-enforced boundary.

Read-only FD alone is not immutable: a service-owned protected copy and verified reference to the exact consumed object (or a reviewed sealed immutable equivalent) is required. The code cannot prove ns ownership, no unauthorized same-UID setns, per-request traffic, cold server, GPU/NVML, or real flock lifetime. The kcmp wrapper returns SAME only if the OS returns 0; syscall failure is never inferred to be sameness. `DIFFERENT` means a direct kernel response >0, not a PID/inode guess. The caller must authenticate the kernel response and ensure arguments refer to the intended real participants; no fixture here validates those real arguments.

Synthetic tests: `PYTHONDONTWRITEBYTECODE=1 python3 test_guard.py`. The tests create new synthetic dirs under `/private/tmp` and intentionally retain them; they don't call model, GPU, real lease, remote host, or signal any process. The `kcmp` behavior is mocked because this Mac is not the target Linux host; production evidence still needs an independently reviewed Linux fixture. The user permitted implementation; the original authorizations still require independently reviewed, separately authorized exact future fixtures before execution. Nothing here authorizes testing on portal or launch of Stage A.
