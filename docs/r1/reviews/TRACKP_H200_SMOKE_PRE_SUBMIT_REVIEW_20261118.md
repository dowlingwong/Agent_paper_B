## Blocking findings

1. **Torch fallback can be reported as a successful fast-kernel parity check.** `probe.sh:38–40` trusts the return code of the pinned `r1/scripts/trackp_gpu_smoke.py`. At D, that program records the selected bindings and `kernel_import_error` at lines 69–77, but only combines the three numerical checks at lines 130–134. If a fast kernel is missing or unbound, a comparison of torch with torch can satisfy all three checks. Keep D unchanged, then validate the returned JSON in the job: require no `kernel_import_error`; require the four fast bindings shown in the published TASL-7 `gpu_smoke_tasl7.json` (FLA chunk and recurrent gated delta rule, and `causal_conv1d` full and update), the pinned FLA/causal-conv1d versions, the reported H200 and capability 9.0, and true pass flags for the expected checks and aggregate. A missing or malformed report or true fallback must leave the job nonzero. Preserve the report even when the post-check rejects it. This validates execution of the intended path without changing numerical tolerances, prompt, weights or D.
2. **The scratch lock only coordinates this sandbox; the legacy routine queries GPU processes without restricting the device.** At D, `r1/c3/train/run.py:130–148,178–209` uses the non-TASL-7 portal branch, checking the home marker, fetching and reading `origin/main:docs/r1/STATUS.md`, and calling `nvidia-smi --query-compute-apps=...` before and after taking the given lock. Overriding `--lock` and `--lease-log` changes neither guard. GitHub confirms the repo is public and reports commit D, and the newest matching STATUS heading in reviewed `origin/main` says B1 completed normally; the route does not require credentials on that evidence. Image v2 ships a sidecar `nvidia-smi`, but depends on injected NVML. The build report calls `nvidia-smi` optional until runtime is verified. One visible CUDA device proves PyTorch visibility, not the scope or reliability of an unqualified NVML process query. Show that the existing lease's query works and covers only the assigned H200 on this runtime, or use a separately reviewed, explicitly logged adapter that preserves the smoke implementation at D and scopes the process check to the Condor-assigned H200 UUID. Any process check that cannot be made or attributed must fail closed. A scratch lock is supplemental to Condor GPU assignment, and a nonzero guard outcome is a setup failure, not a numerical parity result. Do not bypass a Track X STOP.
