## Blocking startup-order finding

The guard refuses `capture != 'no'` only in its `pytest_configure` hook (`r1/tests/b1_pytest_session_guard.py:57–62`). The installed pytest `_pytest/capture.py:155–174` implements `pytest_load_initial_conftests` as a **wrapper** and starts global capture before yielding to ordinary hook implementations. Thus even though the guard's own initial-conftests hook is `tryfirst`, the capture wrapper runs its pre-yield code before the guard; moreover the guard checks capture still later at configuration. Capture defaults to `fd` (`capture.py:50–57`), and FD capture creates `TemporaryFile` instances for stdout and stderr (`:464–495,712–714`). An invocation missing `-s` or `--capture=no` can therefore create temporary capture files and invoke their cleanup before the guard rejects configuration. This is a source-supported startup ordering, not an observed invocation or deletion. Explicitly requiring the operator to supply `-s` in advance reduces the intended invocation's exposure but is not a guard that fails closed on an incorrect invocation.
