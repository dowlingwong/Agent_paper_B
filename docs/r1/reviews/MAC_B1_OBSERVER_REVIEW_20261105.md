## Major 1: dry-run observer context is independently callable without a marked development root

`authorized_b1_observer` checks only that the two `dryrun` flags have the same truth value. `author_gate` returns immediately for dryrun; neither the host nor a marked temporary root is checked by this independently callable context. A mocked local test entered it using `{'phase':'b1','dryrun':True,'authority_config':{'dryrun':True,'rule_sha256':'fake'}}`, no `out`, no marker and no committed note, then called the observer and obtained a successful response. The separate `_collect_b1_review` caller checks a marker, but that does not protect direct context use or ensure a development host. Apply the existing host and marked temporary-root checks at the context boundary itself, or keep the context inaccessible until equivalent checks are in place. Add negative tests for absent/outside markers and a production host; no actual network is needed.

## Major 2: journal validator accepts impossible ordering

`validate_observer_journal` groups events by type and verifies the number and hashes, but never checks their order or rejects unknown event types. A synthetic sequence with `response_complete` before `request_attempt`, `response_headers` and `response_chunk` was accepted. This is not a valid durable chronological request/response trace. Require exactly one request followed by one response header, ordered contiguous response chunks and one completion per sequence; reject duplicate, unknown, interleaved and out-of-order events, and test those cases. Also verify response/event correlation and call counts before writing the root manifest.

## Major 3: job identity is not fully bound to the authorized configuration

For non-dryrun, `require_worker_host(job)` verifies `job.host` against the actual host, but `authorized_b1_observer` does not compare it to `authority_config.host`; nor does it bind the job node, seed and other relevant identity to that authorized configuration. With a mocked valid `author_gate` and worker-host check, a TASL-2 job paired with a TASL-7 authority configuration entered the B1 context. Thus checks individually succeeding do not prove they refer to the same authorized job. Validate the host and job identity against the verified config and the parent's bound job before requests, and test mismatches. This is especially important because the author fixed B1 on TASL-7.

## Integration remains incomplete

The production `collect` function deliberately retains its unconditional STOP; `_collect_b1_review` is a candidate used directly by a synthetic driver. Current `ExamRunner.root` does not supply `authority_config` or `authorization_checkout_head` to the child job. No production B1 entry, actual host authorization, A4 observer evidence receipt, complete downstream post-check, or running experiment is accepted by these tests. The fake-server tests exercise success and one HTTP 503 path, but not all journal tampering, missing journal, direct context entry or a real parent-to-child job handoff. Keep B1/B2 STOPs until the fixes, integration and independent review are complete.
