## Blocking finding: the token acceptance test does not enforce the declared BOS ID

`r1/exam/stage_a.py:123-127` accepts `hf_ids == prefix_ids + served_ids` whenever the encoding of the textual BOS prefix has one token. It does not require `prefix_ids == [bos_id]`. The A1 amendment explicitly requires `ids(hf) == [bos_id] + ids(served)` (`docs/r1/reports/EXAM_TEMPLATE_AMENDMENT_IMPLEMENTED_20261104.md`, lines 10–14). Consequently the code can record `prefix_token_id` as one value while accepting an HF and server token sequence beginning with another. A standard-library-only counterexample using the extracted production function and a fake tokenizer returned `accepted: True` for `bos_token_id=2`, `ids('<bos>')=[9]`, `ids('<bos>x')=[9,7]`, `ids('x')=[7]`, and server ids `[9,7]`. This demonstrates a contract violation; it does not assert that any actual model tokenizer has this mismatch or that any recorded result is affected.

Require the token prefix to equal the declared BOS ID and add a negative regression test. The same reviewer should re-check the fix.

## Blocking finding: a D3 evidence STOP is swallowed during A1 fallback

`r1/exam/stage_a.py:275-280` catches every `Exception` from `non_generation.post('/tokenize', ...)` and returns `None`. The recorder converts lease, census, delivery and journal errors into `D3EvidenceStop` (`r1/exam/cache_nongen.py:45-81`); this handler swallows that STOP. `a1_template_equal` then records a failed template check and the loops in `run_stage_a` can continue with further non-generation and generation requests. The end-of-run journal validator may reject incomplete evidence, but that happens only after further requests have already been sent. This is distinct from an ordinary token mismatch and violates the immediate D3 stop behavior. Re-raise `D3EvidenceStop` before any handling of ordinary endpoint failures and test that a synthetic recorder STOP prevents all later requests.
