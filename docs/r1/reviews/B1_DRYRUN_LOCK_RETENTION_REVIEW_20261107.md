# Independent review — synthetic runner lock retention

**Verdict: ACCEPTED for the narrow DRYRUN `ExamRunner.close` lock-retention change only.** Reviewed commit `36f997bd67aa24bd7847624f01154df4e6704f16`, including the surrounding runtime call paths and the proposed mock test. This is source inspection; I did not run the committed test, a runner, a host command, model or GPU workload, or a filesystem deletion. The implementer's reported AST-extracted mock exercise is not independently reproduced here. This acceptance is not evidence that a full test, recovery, Stage A or B1 is safe or authorized.

On a normal close, after `stop_service` and any applicable containment handling, a truthy `dryrun` now clears the runner's reference instead of reaching the `Path.unlink` call (`r1/exam/runtime.py:1010–1028`). For `preserve_running=True`, the pre-existing immediate return keeps the reference and does not stop the service. The non-DRYRUN control flow is unchanged: B1 uses the existing `retire_runner_lock` branch, while a non-DRYRUN non-B1 lock still reaches `unlink`. This review does not approve that non-DRYRUN deletion under the author's strict rule. An exception before the new branch can prevent close from reaching it, but this change introduces no lock deletion in that case.

The retained lock is not itself an indefinite restart barrier. On a same-process attempt while the recorded PID is alive, `start` refuses it; if that PID no longer exists, `start` can rename it to `runner.lock.stale.<time>` outside `_to_delete` and continue (`r1/exam/runtime.py:695–702`). PID reuse can also yield a refusal unrelated to the original runner. No restart or recovery may be inferred as safe from the change. The proposed tests use mocks and check no `unlink` call on ordinary DRYRUN closes and the preservation early return; they do not exercise real files, dead-PID restart, `stop_service`, exceptions, descendants, or the full test environment.

The change does not fix the pinned harness's pending-guard unlink/truncation or editable-state restoration, nor the STOP/guardian finalization ordering, snapshot overwrites or deletion by other subprocesses and test infrastructure. It does not authorize the legacy DRYRUN launcher, whose first command and recovery remain unqualified. **Remaining STOP:** the Mac implementer must address the actual pinned harness and all relevant deletion paths, and independently review a deletion-free execution and STOP/recovery path before such a test or B1 can run; the required effort is not yet established. The operator must also satisfy the already recorded author-gate, host and handover prerequisites. No author decision is recorded by this review.
