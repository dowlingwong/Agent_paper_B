## Findings

**MAJOR 1 — Budget formula departs from the adopted runbook.** `budget_state` excludes all jobs in the live queue from `used_gpu_h`, while §0.4 requires the sum of used GPU-h from sacct plus the full time limit of every pending or running job plus the proposed job. A local fixture with a running one-GPU job, 2 h elapsed and 4 h limit gives used=0, reserved=4; the literal runbook formula is used=2, reserved=4. This may be an intentional effort to avoid double counting, but changes the threshold decision and needs either the specified calculation or a documented author decision amending it. Add boundary tests with running jobs and all three terms. Also handle delayed or missing sacct accounting conservatively so a recently finished job cannot disappear between queue/accounting snapshots and evade the guard.

**MAJOR 2 — Time guards may expire before actual submission.** F and `now + --time <= C` are checked before `sbatch --test-only`, which has a 120-second timeout. A test started just before F, or before the C bound, may return after the limit and the subsequent actual `sbatch` call still proceeds. Re-check time and STOP state immediately before actual submission; test with a clock that crosses each boundary while the fake test-only command runs.

**MAJOR 3 — Authorization depends on self-declared kind and phase.** The current snapshot now refuses every manifest labeled `evidence`, which is a welcome fail-closed interim fix. However the manifest also accepts arbitrary `phase`, `kind=engineering`, `production=false` and arbitrary argv, including `phase=HK6`; nothing binds evidence phases or job contents to their required authorization. An accidental mislabeled HK6/HK7 manifest can pass as engineering and reach submission. Enforce a validated phase/kind mapping and require the relevant author authorization for any evidence phase, or explicitly refuse those phases until a reviewable evidence gate exists. This is separate from the R1-HOREKA-AGENT-SUBMIT row, which settles submission authority but not evidence authorization or open J3 question (c).

**MINOR 1 — Throttle state corruption fails open.** `QueryThrottle.last()` converts an unreadable, malformed or missing state to the same `None`; a malformed existing file permits immediate polling. Preserve the first-use missing-file case but refuse unreadable or corrupt existing state, and test it. Query serialization currently covers these tools sharing one configured results directory; it does not serialize unrelated user Slurm commands or differing config roots, a limitation that should be explicit.

**MINOR 2 — Ledger location differs from the runbook.** §0.4 names `results/r1/trackg/hk2/gpu_ledger.csv`, whereas status writes `<results_root>/engineering/hk2_jobs/gpu_ledger.csv`. Reconcile the copy-back/path contract and ensure the single intended ledger is populated without overwriting evidence.
