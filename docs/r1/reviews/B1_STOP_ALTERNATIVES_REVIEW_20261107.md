# Independent review: B1 STOP alternatives

**Verdict: ACCEPTED as a bounded static investigation only.** Reviewed report `docs/r1/reports/B1_STOP_ALTERNATIVES_20261107.md`, SHA-256 `bbb2fd2298b4ebe8887a1a8edc6eb4fd6ebe5d106ef1334f06b39fb02aadb51a`, at candidate commit `8a4c072a4af3ff56ee11425501de2b024090b7e7`. This review did not run tests, inspect or access a remote host, use a model or GPU, send signals, delete files, or make an author decision. Neither a process-group anchor nor a cgroup design is accepted or established as necessary.

The 7 November prompt §0.4 requires stopping at once, preserving everything, publishing STATUS and reporting on a listed STOP; it does not expressly require the owned worker or server to remain running. Considering termination of *provably owned* computation, while preserving evidence and respecting the other instructions, is therefore a possible operational interpretation, not a proven implementation or a new authorization. §0.3 separately prohibits killing a running job outside the reviewed pause procedure, and §0.5 prohibits pre-emption and modifications to other operators' work. These rules must be honored in context; the report does not authorize signalling any process. A shutdown that alters evidence, or a procedure that merely leaves work executing, does not establish compliance.

At the inspected source, `r1/exam/runtime.py:635` starts the B1 root in a new session and `r1/exam/campaign.py:164-169` creates an audit process pool. In the fixed harness checkout `a3fedbbd44309b3fdf99d853ad841b9ec2c299e2`, `LocalWorker._run_command` invokes `subprocess.run` with `shell=True` and without `start_new_session` (`src/autoresearch/worker/local_worker.py:292-300`). Registry configurations specify `python3 train.py` for digits and `python3 train.py --config config.yaml` for each OpenML node. A source search found no process-group escape primitives in the particular node and harness paths inspected. This is compatible with the report's limited inference, but says nothing conclusive about imported dependencies, shell behavior, dynamically changed executable contents, other processes or all future paths. The model server is separately created with `start_new_session=True` (`r1/scripts/llama_server_instance.py:355-356`). No actual membership or device behavior was measured.

The current `stop_tree` collects descendant PIDs before signalling them (`r1/scripts/c3_label_sweep.py:310-335`), so process birth, exit and PID reuse can make its collected set stale. The server stop checks its recorded PGID against `os.getpgid`, then separately calls `killpg` and subsequently saves its record (`r1/scripts/llama_server_instance.py:470-487`); those operations do not by themselves prove atomic group identity or preserve a stopped scene. The report correctly identifies these as risks, not observed harm.

The proposed cooperative group anchor remains a research direction: membership confinement, process and group identity over lifetime, all descendants including dynamic executables, spawn/STOP synchronization, signal semantics, output effects, GPU requests already in flight, lease behavior and failure reporting need implementation-specific proof and independent review. Merely holding an anchor or sending a signal cannot establish those properties. If ownership cannot be proved, declining to signal protects unrelated processes but does not itself prove the owned workload has stopped; this unresolved conflict remains a B1 STOP. An available fallback notification also cannot guarantee publication when all channels fail. No host readiness, full B1 readiness, design acceptance or author policy waiver follows from this review.

A later candidate must be independently reviewed against the exact integrated code, simulated adverse transitions and the actual host capability. B1's separate approved-note order, pinned harness/no-deletion constraint, determinism, storage, final checkout and handover remain open as recorded in the report.
