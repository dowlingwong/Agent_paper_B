Verdict: **ACCEPTED for the B1 OpenML guard's bounded protocol behavior**, candidate `f63471bf2d0286e11142bf25841cc0485b6bbade`. This does not authorize B1, waive any existing STOP, or establish numerical equivalence by a scientific experiment. I did not access the host or run models or GPU work.

The overlay changes paper-side `B1IntegrityWorker` and B1 audit workers; the harness pin remains a3fedbb. For credit approval and ionosphere only, the exact registered command `python3 train.py --config config.yaml` is replaced by a Python bootstrap which installs the guard, restores `sys.argv` and node import path, and executes the same node `train.py` via `runpy`. The same seed environment, working directory, configuration, benchmark, metrics parser and worker timeout remain in use. It adds an earlier sklearn import and wrapper execution, so subprocess timing is not identical and an invocation near the existing timeout could differ. No change to split, fitting, scoring, seed or metric formulas was identified in the reviewed overlay; I did not measure metric equality.

The original pinned benchmark uses `fetch_openml(..., as_frame=True, parser="auto", data_home=str(CACHE_DIR))`, where `CACHE_DIR` is the node's `data_cache`. Campaign and B1 audit each work on their isolated copied node and copy the pilot cache when needed. The guard checks each sklearn OpenML request resolves to an existing cached file, suppresses clean-cache and network retries, and refuses Python unlink/remove under that node cache. A missing or malformed cache now produces an explicit STOP instead of fetching, deleting and retrying or being recorded as a normal failed trial. It is a deliberate failure-path protocol change to preserve evidence; it does not promise protection against malicious same-UID processes or native code. It relies on sklearn private OpenML APIs; retained site loader capture reported sklearn 1.8.0, but is subject to the separate missing SSH exit evidence STOP and does not verify the runtime at a later launch.

Both the campaign and `run_config(..., preserve_node_outputs=True)` B1 audit use this worker overlay. In audit, a guard exception reaches the future and `run_b1_audits` requests the parent STOP and cancels queued futures; already-running work may continue until the existing owner stop path acts. The guard does not itself freeze processes or prove in-flight work has completed. Audit results are not converted to metrics on this exception. Do not automatically resume after STOP.
