## MAJOR: B1 rule-row check is not an authoritative dated decision row

`r1/exam/runtime.py:author_gate` reads the working-tree `docs/r1/PLAN.md` and accepts if **any line** contains both `R1-EXAM-RULE` and `rule_sha`. It does not require a table row in PLAN §10, an exact row identifier, or that the PLAN bytes equal a committed author-approved authority snapshot. A prose-only draft, superseded note, or uncommitted local change can satisfy this condition. The function does verify the authorization note against local `HEAD`, but that local comparison alone does not establish the authority of the PLAN or independent authorship of that commit.

Synthetic reproduction, local CPU only: a temporary fake PLAN containing `## 9. Notes` followed by `Draft only: R1-EXAM-RULE ` and a 64-character fake hash, with **no decision in §10**, caused `author_gate` to return normally. The note's `git show` result was mocked as equal to the synthetic JSON note, so the test isolates the PLAN predicate; it is not evidence of an actual forged authorization or any past run. A safe fix must check a correctly scoped, exact first-cell decision row and the committed bytes against an independently established author-approved authority source, fail closed when absent or modified, and receive independent review. Do not treat local HEAD or an arbitrary supplied hash alone as author authority. Preserve existing fail-closed B1/B2 execution guards while fixing.

## Implementation constraints for the authority-row defect

For `x5_rule/v2`, the required first-cell ID is **exactly** `R1-EXAM-RULE-X5V2`, in the dated subsection of PLAN §10; similarly prefixed IDs, prose, an ID in another cell, a row in another section and duplicate/ambiguous matching rows must not count. The row must bind the full exact rule SHA, with the author's decision words quoted in its decision cell under the current recording rule. A design that allows the SHA only in recorder-written consequences needs an explicit, independently reviewed authority-binding rule; a bare nearby mention must not suffice. Reject malformed Markdown or an absent/non-dated/ambiguous row rather than infer intent.

At minimum compare the exact bytes used with the PLAN blob at the reviewed, author-approved committed authority snapshot; refuse missing, altered or dirty PLAN. Read/compare once from a single immutable byte snapshot to avoid mixing versions. But **working-tree equals local HEAD does not prove the author made or authorized a decision**: Git author strings and locally supplied refs are forgeable, and a caller-controlled commit or ref is not an external trust root. How the operator verifies the author's actual published approved commit, review and decision against an independently communicated pin remains a separate open design prerequisite; absent that evidence keep the execution STOP. The final note itself likewise needs both committed bytes and a trustworthy author-approved publication identity.

`x5_rule/v1` is the historical Stage A rule and its paths must remain usable as required by M2. Do not silently apply v2's new exact-row ID to v1 and break prior behavior, or weaken v2 to preserve legacy behavior; make the version-specific policy explicit. A v1 historical compatibility exception is not a new evidence authorization. Independently test clean versus dirty committed PLAN, prose/other-section/ID-prefix/duplicate-row impostors, exact full SHA binding and legacy v1 behavior, alongside mock authorization checks. The main B1/B2 entry STOP must remain until the broader evidence work and independent review are complete.
