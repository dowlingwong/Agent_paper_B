## Findings

1. **Blocking — action reward is not the specified fixed-reference u.** Track P defines u using `keep` under the fixed A1 constant prior, independent of the model being trained (`TRACK_P_POST_TRAINING.md:147–153`); R-A1/R-A2 use this u (`TRACK_P_POST_TRAINING.md:325–330`). The new environment computes the keep threshold from `self._belief` (`r1/c3/env.py:183–186`) and then computes reward (`r1/c3/env.py:189`). Its fixture deliberately changes belief and observes keep and reward change for the same row (`r1/tests/test_c3_h8_amendment.py:18–34`). Thus it implements a belief-dependent payoff, not the adopted fixed-A1 target. Preserve the observation separately from an independently established fixed reference and test invariance of u to the submitted belief.

2. **Blocking — belief provenance and outcome isolation are not enforced.** The callback receives the complete row (`r1/c3/env.py:134–142`), including `delta_true` and `delta_label` used as rewards (`r1/c3/env.py:99–104`); a supplied `belief` likewise has no provenance check. The adopted split prohibits mixing evaluation seeds into training quantities (`TRACK_P_POST_TRAINING.md:112–117`). A fixture callback selecting one-hot bins from `row['delta_true']` ran successfully in the label split: evaluation outcomes can therefore enter observations and policy training. This demonstrates an exposed leakage path, not that any existing forecast actually leaked. Restrict provider input to an explicit pre-decision allowlist and establish provenance or an equivalent enforceable contract for precomputed beliefs; test outcome-field perturbations.

3. **Reset failure can silently pair a new row with an old belief.** `reset` assigns `_current` before calling the provider and only clears it for vectors that fail the later validation (`r1/c3/env.py:134–146`). If the provider or NumPy conversion raises, the prior `_belief` survives. In a two-row CPU fixture, after the second provider raised, `step(0)` accepted row `b` with row `a`'s prior belief and returned reward 0.029. Clear state before all fallible work and commit a row and belief together; test provider and conversion exceptions. The existing invalid-vector tests cover only the explicit validation branch (`r1/tests/test_c3_h8_amendment.py:47–57`).

4. **Integration evidence is incomplete.** `_fill` calls the real `serialize_view` by default (`r1/c3/control.py:223–232`), and its state/proposal shape matches the loader (`r1/c3/serve.py:153–157`). However, the new tests inject a synthetic builder and monkeypatch featurization and `_post` (`r1/tests/test_c3_sidecar_prompt_fixture.py:13–18,29–52`); they do not exercise the production serializer, its leak guard, or E2 resume with a fresh controller. The real serializer invokes the tokenizer pool by default (`r1/c3/train/serialize.py:168–171,202–203`), whose loader can call `snapshot_download` (`r1/c3/train/serialize.py:63–69`); no inference or download was attempted in this review. Add a fixture-only test using the actual serializer with injected fake tokenizers, exercising E1, changed E2 and fresh-controller E2 resume, and verifying permitted prompt contents and failure fallback. Failure handling and `prior_unavailable` are covered for injected failures (`r1/tests/test_c3_sidecar_prompt_fixture.py:55–67`), but this is not a real-serializer integration test.
