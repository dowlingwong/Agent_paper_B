**Verdict: NOT ACCEPTED for the B1 path.** Reviewed commit `7ee75d27fb296385ed5afe5086d760059fb82386` against its parent `9891589bf97af9bbda620b756d0f27eafe07d57f` and the 7 Nov prompt §0.4/§0.6. This is a static review. No tests, hosts, GPU, model, experiment, signals or cleanup were run in this review.

The change removes the explicit `shutil.rmtree` in `run_config` and avoids removing a caller-supplied `run_plan` temporary directory. It uses `lstat` to reject a symlink or changed source identity and `renamex_np(RENAME_EXCL)` on macOS or `renameat2(RENAME_NOREPLACE)` on Linux so a destination collision fails rather than replacing an existing entry. The candidate test covers collision, symlink retirement root, changed source identity, caller-owned tmp, and a synthetic worker exception. These tests do not prove the target Linux libc/filesystem supports the atomic primitive or bound the storage needed by retained copies. Before host use, verify that capability in a new owned directory without deleting it, and calculate and monitor disk headroom for copied node trees, artifacts, and caches. Same-UID concurrent mutation of the hierarchy is explicitly outside the candidate's guarantee.

## B1 STOP preservation remains unprotected

`r1/c3/audit.py:132-135` calls `_retire_owned_work` unconditionally in `finally`, including when the worker or its caller raises. The synthetic exception test at `r1/tests/test_audit_preservation.py:76-99` explicitly expects the partial work directory to have moved into `_to_delete`. The source bytes are kept, but the original failure-scene path is altered. For a worker exception, `r1/exam/campaign.py:175-180` receives it from `future.result()`; only after the root subprocess exits does `r1/exam/runtime.py:659` create the runner STOP. Consequently the exception alone is not proof the move occurred *after* a runner STOP, and no such real event has been observed.

There is nevertheless no coordination in this `finally` with a runner or guardian STOP that occurs concurrently while audit subprocesses are running. Such a STOP can precede a worker's subsequent successful or exceptional return, after which this candidate can move its work directory. That leaves the author's requirement to stop and preserve everything on a runner or guardian STOP unestablished. Merely changing to success-only retirement would preserve the original path on a worker exception, but would not solve the concurrent-STOP case. A minimal safe option is to leave audit work at its original fresh path on all paths (no retirement is needed to satisfy the no-deletion instruction); alternatively, prove and review a process-wide STOP handshake that prevents post-STOP mutation. Add synthetic coverage for partial worker exception and concurrent STOP, asserting original paths and byte contents remain intact without signaling or modifying unrelated processes. Scope the test to the actual chosen mechanism and never run it on a real STOP scene.

## Separate pre-existing B1 STOP issue

`r1/scripts/exam_runner.py:538-547` marks `preserve_running` true only for Stage A, then calls `runner.close(preserve_running=False)` for a B1 exception. `r1/exam/runtime.py:727-732` consequently stops the service and unlinks the runner lock; `runtime.py:660-663` can also signal the live child before the exception reaches that handler. This predates the candidate and is not established fixed by it. Compare these actions with the precise author STOP and safe-release instructions, then implement and independently review a B1-specific preservation path as necessary. Do not infer an exception merely because the processes or lock were created by this agent.

## Other limits

`run_plan` only retires an owned temporary directory after normal pool completion; if an exception interrupts the pool, it remains at the original path, which preserves data but can consume storage. A relocation failure is surfaced as STOP and the no-replace primitive leaves the source in place on a failed rename; an exception in this `finally` can replace the outer exception as the primary raised error, though Python retains exception chaining. Only the known audit cleanup is addressed: the pinned harness pending-guard and conditional editable-file operations, B1 runner lock handling, test-suite subprocess cleanup, and site qualification are separate work. This review does not accept the full suite, determinism, handover, or B1 readiness.
