**MINOR**

1. **Report §6/§4 claims `out.tar` and the `out/` tree were "not copied" — false.** The capture tree holds
   five `out.tar` files (the three sealed nodes, ≈11–13 MB each, and both fmnist attempts, 10 KB each) and

   understates the retained evidence but is an inaccurate statement; the table header "`out.tar` sha256
   (not copied)" is self-contradictory. Fix the text (the evidence is retained and verifiable).
2. **Duplicate report file.** `G1B_TASL2_RESULT_20261121_MONITOR.md` is byte-identical to the reviewed report
   (same sha `efd5d4f5…`). Two identically-sha'd files are untracked in the same directory with no
   designation; keep one authoritative file (or mark the other as the monitor memo).
3. **Monitor restarts not disclosed.** `_monitor/polls.log` contains `MONITOR_START` at 21:49:05Z, 21:49:43Z
   and 22:14:30Z, an early `VERDICT_TERMINAL 22:44:47Z` (a pre-v3 monitor loop exited after the two fmnist
   STOP lines), then `MONITOR_V3_START 22:48:44Z baseline_stops=2`. The report's "5-minute polls 21:49:05Z →
   04:06:49Z (77 polls)" is true in aggregate (77 polls; maximum inter-poll gap 305 s, no coverage hole), but
   the restarts and the early monitor-only terminal should be stated so `polls.log` is not misread.
4. **§8 "the only GPU compute process in every sample was the run's own … python".** 60/61 non-empty GPU
   samples fit; one imdb-time sample shows `3425651, [No data], 11246 MiB` (nvidia-smi could not resolve the
   name). The PID/memory pattern indicates it is the job's own engine, so "no foreign process" still holds,
   but "every sample" overstates the captured evidence; say "one sample has an unnamed PID (the job's own
   process)".
5. **"(16 h limit not reached)"** — the 16 h is the monitor loop's own deadline (`poll_loop.sh`), not a
   spec/note wall limit. Reword as "monitor deadline not reached".
6. **Evidence completeness for the STOP's root cause.** The captures hold the produced manifests
   (`24cb3448…`, `54d3a74d…`) but not the census manifests (`8d28287b…`, `c0ef1168…`) nor the `.npy` hash
   listing/diff; the "only `source.datasets` differs" claim therefore needs the live census host to verify.
   This is not a result error (I verified it independently), but add the census manifest bytes and the
   four-file sha256/bytes comparison to the captures so the STOP is self-contained/hash-bound in the
   deliverable.
7. **XC/G4 report — "no G4 server/pilot was started" is an absence claim.** It is well supported (no G4
   artifacts/processes/leases on either host, and the report itself says there is no G4 evidence beyond the
   pre-launch records), but state the check made (hosts inspected, no processes/leases) so a reader does not
   take it as a recorded start/stop event.
