## Blocking finding: the named lock's parent path is not bound

`probe.sh:11–12` uses `ls -la "$HOME/r1_locks"`, which can list the target of a directory symlink; it does not establish that the directory is the intended non-aliased directory. The marker checks at `:25–27,41–43` and lock access at `:56–68` then resolve that pathname again. `os.stat(path, follow_symlinks=False)` and `O_NOFOLLOW` protect the final `gpu0.lock` component, but do **not** reject symlinks in `/home/dowling/r1_locks` or its ancestors. The final inode/owner/link checks can all pass for a single-link file owned by the user under an aliased directory. Thus the probe may briefly lock a different same-UID file and report a passing check of the intended cooperative GPU lock; the snapshot from an earlier SSH session does not rule out an alias or path replacement at this later operation. This is a source-supported possibility, not an observed host event or assertion of malicious behavior.

**Unblock:** establish the canonical path and identity of the relevant directory before marker and lease checks, reject symlinked or unexpectedly owned path components without changing them, and open the existing `gpu0.lock` relative to a validated, non-followed directory descriptor; recheck descriptor/name identity around acquisition and preserve the existing nonblocking/close behavior. Alternatively provide an independently reviewed mechanism that establishes the same path binding. The ordinary same-UID concurrent replacement limitation should remain disclosed; the existing `775` lock directory is not grounds for an invented permission-change requirement. **Owner:** probe implementer and independent reviewer; authorized operator performs a fresh read-only occupancy check and runs the reviewed probe only when non-preemption and other site conditions hold. **Effort:** a small script correction plus review, then a short site-dependent probe; no elapsed-time guarantee for concurrent workload coordination.

## Checked scope and remaining limits

* Before the flock attempt, the script verifies hostname/account, lists the lock directory, reads each full STATUS file with before/after SHA-256 checks, refuses either active/dangling marker, and queries the specified GPU UUID, utilization and compute-app list (`probe.sh:4–44`). The status check rejects a symlink in the final STATUS component, missing/non-regular/unreadable files and hash mismatch; it does not establish an atomic snapshot or prove no later workload starts. A separate path-identity and fresh site review is still needed. `nvidia-smi` itself runs as a normal system process, not a model or GPU compute workload, and its potential tool/system side effects were not measured here.
* The lock is opened read-only with `O_NOFOLLOW|O_CLOEXEC` and no create flag; it uses a nonblocking exclusive flock and attempts `LOCK_UN` in a `finally`, followed by descriptor close (`:60–83,109–110`). On a normal completed Python process this does not write the lock bytes. Abrupt signal, suspension, runtime malfunction or concurrent path changes cannot be ruled out by static reading; report a successful unlock only when observed and treat process/SSH completion separately. The short nonblocking flock may affect a concurrent cooperative launcher even though it does not preempt a running job; the proposal correctly requires current coordination and prohibits claiming exclusivity.
* The Python invocation `-I -S -B` isolates site imports, disables site initialization and bytecode writes. The script checks Linux/x86-64 before using syscall number 312, calls `kcmp(KCMP_FILE)` on its own same FD only after unlock, and uses a self pidfd (`:47–58,84–108`). Nonzero `kcmp` and pidfd error/unexpected state are labelled `NOT_CHECKABLE`, not PASS. These observations cannot prove ancestor-to-child `kcmp`, shared open-file-description continuity, an inherited server descriptor, real worker Python binding or cgroup/freezer behavior. No actual syscall result or target interpreter behavior has been checked in this review.
* The literal local capture checks existing/dangling paths and enables noclobber; the proposal itself notes this is not a proof against all concurrent same-UID path replacement. Before execution the operator needs a fresh uniquely owned capture path and an independently reviewed exclusive mechanism or explicitly established cooperative local ownership. The command preserves a failed SSH exit code and hashes the capture; it never deliberately removes the capture. SSH, shell startup, `nvidia-smi`, Python and system services can have side effects not established by source inspection. The script contains no explicit remote output redirect, `O_CREAT` for the lock, file deletion, rename, process signal, server launch or GPU compute call.
* A successful self-test cannot establish that a currently unlisted job is absent or that a lease remains held after the probe; it must not be described as formal B1 preflight, host reservation or launch authority. A fresh occupancy/STATUS check, exact reviewed checkout and authorization, safe handover, real worker/server descriptor checks and the remaining B1 STOPs remain independently necessary.
