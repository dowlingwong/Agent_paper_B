## 1. Disabled by default (Q1) — PASS

`submit()` order is exactly `check()` → two-key gate → JDL existence → `condor_submit` (`s2_c5_switch.py:114-122`):

1. `checked = check(spec_path, note_path)` (line 114) — read-only validation;
2. `if not enable or os.environ.get("S2C5_ENABLE_REAL") != "1": raise Stop(...)` (lines 115-116), message
   `STOP: S2-C5 real submission is disabled (needs --enable AND S2C5_ENABLE_REAL=1)`;
3. only then is the JDL checked and `subprocess.run(["condor_submit", ...])` reached (lines 117-122).

There is no other call site of `submit()` except the `submit` subcommand (`main`, lines 130-143), no import-time
execution, and no repo automation invoking it (`grep -rn "S2C5\|s2_c5"` finds only the switch, its test, the unit
report and the template). `S2C5_ENABLE_REAL` appears only in the switch, its test and the unit report's prose;
`--enable` exists only in the switch's CLI. `docs/r1/authorizations/` contains **no** `c3_sweep2_*` note (only the sweep-1 `c3_sweep1_20261027.md` and unrelated
notes), and the template is deliberately `approved: false`. Neither key nor a valid note exists in the repo.

**No side effect in `check`:** it only does `read_text` + `json.loads` (lines 88-90) and returns a dict; no writes,
no submission. Probe: with a valid synthetic note/spec and no keys, `submit` STOPped at the disabled message and
the temp dir contained only my input files (no `S2C5_SUBMISSION.json`).

**Can a spec/note trick it into submitting? No.** The note/spec can only satisfy `check()`; they cannot set
`--enable` or the environment variable, and the gate is an independent `or` after `check()`. Verified for all
three key combinations:

| `--enable` | `S2C5_ENABLE_REAL` | result |
|---|---|---|
| absent | unset | `STOP: S2-C5 real submission is disabled (needs --enable AND S2C5_ENABLE_REAL=1)` |
| present | unset | same disabled STOP |
| absent | `1` | same disabled STOP |

One deliberate nuance (documented, `S2_C5_UNIT.md:18`): a *malformed* note/spec yields the more specific validation
STOP before the disabled STOP, because `check()` runs first. That is fail-closed and leaks nothing operational.

## 2. Gate correctness (Q2) — core correct; two pre-enable gaps and parser hardening needed

**Correct and matching the authority:**

  `ghcr.io/dowlingwong/r1-htc-gpu@sha256:69b06b35…` string (short digest forms are rejected — exact string compare,
  `:63`); `b2_audits` must be `none`/`n/a`/`not-authorized`; `d8_lock: true`.
- 32k layout: `layout_request_walltime_s` 12203, `layout_request_disk_kb` 42460977,
  `layout_request_memory_mb` 32000, `layout_chunks` 16, `layout_gpu_hours` 41.72 ± 0.05 — exactly

- P1–P7 required present and non-empty; the spec must pin `label_source.authorization` to the note **basename**
  and `authorization_sha256` to the sha of the bytes read (`:92-95`); spec `run_id`, `image.digest`, walltime
  (`request_walltime_s`, falling back to `walltime_s`), `request_disk_kb`, `request_memory_mb` must equal the
  note's values (`:96-105`). The spec's real committed shape (`sweep2/spec.example.json`: `walltime_s`, no

- The template is not a valid note (`approved: false`), and the frozen digest matches

**Issues:**

- **M1 (major, pre-enable): the documented "author-committed note under `docs/r1/authorizations/`" is not
  enforced.** `AUTHORIZATION_NOTE` (line 31), `_text()` (lines 41-44) and `import s2_c2_lib as lib` are
  defined/imported but never used; `check` compares only `Path(note_path).name` with the spec pin (`:92-93`) and
  the sha of whatever file is passed. It never requires the path to be under `docs/r1/authorizations/`, never
  matches `c3_sweep2_<date>.md`, and never checks that the bytes are a committed blob on an author branch. Probe:
  valid notes named `anything.md`, `README.md` and placed in a temp dir all `ACCEPT`. The module docstring
  ("the author-committed authorization note `docs/r1/authorizations/c3_sweep2_<date>.md` is present" and "is the
  exact note the spec pins (path + sha256)", lines 5-8) and `S2_C5_UNIT.md:10` therefore overstate the
  implementation; runbook §2 P3 requires the note be author-written and committed. The spec sha pin binds exact
  bytes but not provenance. **Fix before enablement:** require the note's resolved path under the repo's
  `docs/r1/authorizations/`, `AUTHORIZATION_NOTE` fullmatch (`c3_sweep2_<YYYYMMDD>.md`), and that the file's bytes
  equal the committed blob on the pinned author branch (e.g. `git cat-file -e <author-branch>:<note>` and compare
  the blob hash) — or, if provenance is to remain a human precondition, correct the docstring/unit report and add
  the check to a follow-up. Add tests for a valid note outside the directory, wrong basename, and uncommitted blob.

- **M2 (major, pre-enable): the submitted JDL is not bound to the authorized note/spec.** `submit()` never reads
  the JDL (`:117-126`); it records `run_id`/`image`/`note_sha256` from `check()` and then runs

  different run/digest/layout/ENGINEERING label would be submitted while the record still reads the authorized
  run id + digest. Probe: a spec with `request_walltime_s: 12203` (checked) **and** `walltime_s: 99999` (the field
  `render_jdl.py` actually renders into `+RequestWalltime`) is accepted; the reviewed ENGINEERING example
  (`sweep2/dryrun/s2_c2_eng_example.jdl`, run id `s2eng-20261116-b`) would also be accepted. This is short of
  P6 ("real submission enabled only for the authorized run ID and image digest") and of the launch checklist's
  "submits only the reviewed EVIDENCE JDL". **Fix before enablement:** pin the JDL (e.g.
  `label_source.jdl_sha256` in the spec, or render it inside the switch from the checked spec with the reviewed
  `render_jdl.py` and refuse on mismatch), verify the JDL's image digest / walltime / disk / memory / run-id lines
  against the note, require `request_walltime_s`/`walltime_s` agreement when both are present, record the JDL
  sha256 in `S2C5_SUBMISSION.json`, and test both the matching and mismatching JDL.

## Findings

### Blockers
**None.** The committed unit cannot submit: the two-key gate is ANDed, reached only after validation, and neither
key nor a valid note exists in the repo. No side effect in `check`. No labels are read and no job/chunk is selected.

### Majors (must be closed before the author enables the switch; not blockers while disabled)
- **M1 — "author-committed note under `docs/r1/authorizations/`" is documented but not enforced.**
  `AUTHORIZATION_NOTE`/`_text`/`lib` are unused scaffolding; any path/basename whose bytes the spec pins is
  accepted. Evidence: `s2_c5_switch.py:5-8,31,41-44,92-95`; `S2_C5_UNIT.md:10`; probe accepted
  `/tmp/anything.md`, `README.md`. Fix: enforce `docs/r1/authorizations/c3_sweep2_<date>.md`, fullmatch the
  basename, and compare the bytes with the committed blob on the author branch; add tests.
- **M2 — the submitted JDL is not bound to the authorized note/spec** (no JDL read, no sha pin, no
  image/walltime/disk/memory/run-id check). Evidence: `s2_c5_switch.py:117-126`; probe accepted a spec whose
  `walltime_s` (the field `render_jdl.py` renders) differs from the checked `request_walltime_s`; the reviewed
  ENGINEERING JDL would pass. Fix: pin/render and verify the JDL, record its sha; add tests.

### Minors
- **m1 — the committed template, once "filled", is still rejected by the parser.** Template line 21 is
  `b2_audits: none (this authorization carries no B.2 audits)`; the parser requires exact `none`/`n/a`/
  `not-authorized` (`:65`). Probe: a "filled" copy (`approved: true`, run id) STOPs
  `STOP: the sweep-2 authorization carries no B.2 audits; note must say none`. The launch checklist repeats the
  same phrasing. Fix: make the template value bare `none` (parenthetical as a comment), or (less safely) accept a
  `none` prefix; also consider the template P6 wording ("switch enabled for this run id only") — it describes the
  post-enablement state, so keep it prospective until the author enables.
- **m2 — `layout_gpu_hours: nan` bypasses the estimate check.** `abs(float("nan") - 41.72) > 0.05` is `False`, so
  `nan` is accepted (probe). Add `math.isfinite` (and reject a `bool`) before the comparison.
- **m3 — duplicate keys are last-wins, not fail-closed.** `parse_note` overwrites (`:52`); probe: `approved: true`
  then `approved: false` STOPs, but `approved: false` then `approved: true` ACCEPTs. A contradictory committed
  note should STOP. Also any line anywhere in the file matches, including inside markdown fences/examples; reject
  duplicate required keys and document that the note carries one machine-readable field block.
- **m4 — P1–P7 need only be non-empty.** Probe: `P1: FAIL` ACCEPTs. The checklist says "each with the PASS
  evidence pointer"; require the value to start with `PASS` (or another explicit accepted token).
- **m5 — no `run_id` form validation; the template placeholder could pass.** `_text` is unused. If the author
  sets `approved: true` but leaves `<author run id, e.g. s2sweep-20261117-a>` in the note and copies it into the
  spec, `check` accepts it. Use `s2_c2_lib`'s `SAFE`-style `^[A-Za-z0-9_.-]+$` plus a length bound.
- **m6 — spec `label` is optional/vestigial.** `spec.get("label") is not None and != "EVIDENCE"` (`:106-107`):
  absent is accepted (probe with the committed spec shape) and a different value is rejected. The authoritative
  label is the note (and the in-job `resolve_label` enforces EVIDENCE), so this is not a label-EVIDENCE bypass
  through this field — but the check is cosmetic and its interaction with M2 (JDL label unverified) should be
  clarified: either require `label: EVIDENCE` too, or drop the field check.
- **m7 — digest computed over decoded/normalized text, not file bytes.** `raw = Path(note_path).read_text()` then
  `sha256(raw.encode())` (`:88,94`): universal-newline translation means a CRLF note's pinned "file sha" is not the
  file's byte sha, and a non-UTF-8 locale makes `read_text` raise. Use `read_bytes()` + explicit UTF-8 decode and
  hash the bytes.
- **m8 — missing file / malformed JSON raise tracebacks, not clean STOPs.** `read_text`/`json.loads`
  (`:88-90`) are unguarded; a missing note or spec is a `FileNotFoundError`, invalid JSON a `JSONDecodeError`.
  Wrap in `try/except (OSError, ValueError)` → `Stop`; add tests.
- **m9 — submission record is minimal and overwritable.** No spec path/sha, note path, layout, or gate flags;
  `S2C5_SUBMISSION.json` is overwritten by any later invocation (a duplicate submit loses the first record), and
  a write failure after a successful `condor_submit` raises with the job already submitted. Record the extra
  fields and the JDL sha; refuse a second submission (or keep an append-only record); test both.
- **m10 — test gaps** (see §4): no successful-submit / mocked `condor_submit` path, no rc≠0 path, no JDL-content
  or note-provenance tests, no missing-field case despite the test name, no `walltime_s`-shape test, no template-
  validity test, no duplicate-key/NaN/encoding/IO tests, no `--enable`-only case (behaviour verified by probe).
- **m11 — `condor_submit` has no timeout and is resolved from PATH.** A hung scheduler call blocks indefinitely;
  consider `timeout=` and an explicit binary path. Low risk on the controlled submit host.

## Residual risks

- **The switch's safety in the current state is the two human-held keys, not the note/spec pin.** Anyone who can
  run the switch and set both keys can submit an arbitrary reviewed-form JDL (M2) with an arbitrary note path
  (M1). That is acceptable only while the unit remains disabled and only if the author treats the two keys as the
  authorization act; the M1/M2 fixes make the tool enforce P6 rather than rely on that operator discipline.
- **The in-job S2-C2 `resolve_label` re-checks `approved: true`, the run id and `label: EVIDENCE` in the staged
  note** (`s2_c2_lib.py:239-265`), and EVIDENCE additionally needs `paper.evidence_ready = true` — useful defense
  in depth for the label, but it does not check note provenance or the JDL's identity, so it does not remove M1/M2.
- **Base drift:** `sweep2-main-20261116` has since advanced to `abc3ed1e` (doc-only launch checklist). No code
  interaction, but the merge/ordering and the checklist's `b2_audits` phrasing (m1) should be reconciled with this
  review. The launch checklist already records the correct "DISABLED, not enabled" status for P6.
- `S2_C5_UNIT.md` accurately describes the two-key gate, the layout/digest fields and the tests; only its
  "author-committed note" claim needs the M1 fix (or a qualification).

**Verdict:** the unit cannot and does not submit in its committed state; the two-key disabled gate, the layout/
digest/run-id/spec-sha checks, the no-label/no-job property and the 3-test suite all check out, and the template
and unit report honestly state "not enabled". Two majors (M1 note provenance, M2 JDL binding) and the minor
hardening items should be closed before the author enables the switch, but they are not blockers for merging the
disabled unit. No submission or execution was performed in this review.
