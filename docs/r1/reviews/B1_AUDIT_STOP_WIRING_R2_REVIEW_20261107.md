The wrapper now attempts STOP on *both* writers when descriptor validation fails or audit work raises (`:47–83`); with one broken writer and a usable second channel, a successful second write gives the single monitor a STOP to process before waiting for executor completion. Monitor processing marks stopping, calls the owned freeze, and reports failure (`:100–133`). The collector also attempts notification before executor shutdown on submission/result/cache exceptions. The prior specific single-writer failure is addressed, not every common-mode failure.

After observing child exit the monitor now drains each pipe until no byte is currently readable (`:151–169`). `D` marks completion and causes another read; `S` invokes freeze and raises, including during this drain (`:117–133`). Thus the R1 normal scheduling case where an empty read precedes a queued `D` and exit is addressed at source level, assuming correct nonblocking pipe semantics. Actual success additionally needs both `D` markers, zero child exit and an empty worker cgroup. Completion bytes alone never accept a batch. The candidate's test source includes simulated invalid/failed primary writer with backup success, empty read then exit plus completion byte, and a STOP in the exit drain; none establishes kernel or process behavior.

**Remaining limitation:** both notification writes can fail, or the shared monitor, parent, kernel or guardian can fail. If both writes fail while another pool task retains a writer, EOF can be deferred and executor shutdown can continue waiting; R2 expressly does not solve that common-mode condition. Full pipes with queued STOP should be analyzed separately from unavailable descriptors, not automatically treated as equivalent. A reader must not interpret this scoped review as proof that all possible detected STOPs immediately quiesce peers.
