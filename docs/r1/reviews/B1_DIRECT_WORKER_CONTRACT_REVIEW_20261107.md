The new contract and `host_check` are skipped whenever `job['dryrun']` is truthy (`campaign.py:152-164`). A directly invoked job with such a value and a `.dryrun` marker in an ancestor can pass the marker check, create `out` and copy a node (`:170-173`) before reaching `authorized_b1_observer` (`:187-189`). The observer rejects DRYRUN on approved exam hosts (`observer.py:58-63`), and it enters before `run_real_campaign`; therefore this trace supports **pre-refusal filesystem writes**, not a claim that an LLM request or real B1 campaign ran. An early failure caused by missing or malformed job fields can occur after those writes as well. This pre-existing direct-entry gap can touch paths the author reserved for other work and must be closed before a claim that the direct entry is safe on TASL-7. Require a strict boolean DRYRUN value and apply the applicable approved-host/marked-root checks before *any* directory creation or copy, retaining the existing development-host DRYRUN behavior; add negative mocked host tests that assert both `mkdir` and `copytree` are not reached. A fresh reviewer must check the change. This finding is not an observed real invocation.
