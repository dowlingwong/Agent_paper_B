# Independent whole-unit review: B1 audit failure notification — 7 November 2026

**Verdict: ACCEPTED for the wired exceptional-audit-failure notification unit under the documented cooperative, single-writer-failure model.** Reviewed `f6185c33` and its actual runner, worker contract, collector, pool wrapper, monitor, and containment code. This is source review, not acceptance of the integrated checkout, all audit failure semantics, or B1 launch. No tests, real processes, host, GPU, model, experiment, deletion, or overwrite were performed. The 17 mock checks are implementer-reported; I inspected test/source only.

The runner creates two nonblocking pipes and passes both writers into the actual contained worker through v3 (`r1/exam/runtime.py:910–932`, `r1/exam/b1_cgroup.py:294–328`). The worker contract verifies distinct nonblocking FIFO writers before campaign execution (`r1/exam/b1_worker_contract.py:137–155`, `r1/exam/b1_audit_stop.py:20–44`). The collector retains `job['workers']` as the pool maximum and uses a fork context so the pool can inherit these FDs; it does not substitute serial execution (`campaign.py:234–247`). The actual pool function `run_notifying_audit` invokes the real `run_config`, attempts STOP to both channels when a task raises, and re-raises; the collector also notifies on submission/result/cache exceptions before the executor context exits. A single bad writer can be covered by a functioning second writer; this assumes the other channel and shared monitor/guardian remain operational. It is not an assertion that a pipe write proves freeze.

The parent monitor invokes the owned containment freeze on STOP or abnormal channel data, and marks stopping before the call (`b1_audit_stop.py:100–133,151–180`). The parent runner checks the monitor during work and invokes its own existing B1 freeze/STOP handling on failure (`runtime.py:941–991`). Peer tasks can still write between their failure, the 50 ms monitor polling interval and confirmed cgroup freeze; if freeze fails, quiescence is not established. The unit does not notify a separate STOP for every ordinary `WorkerResult.success == false`: `run_config` collects such values and the existing collector checks paired completeness after the pool exits (`r1/c3/audit.py:128–138`, `campaign.py:242–261`). The present acceptance is for **raised exceptional failures**, including a preservation exception that actually propagates; it does not claim earlier cancellation or alter the scientific treatment of ordinary failed audit runs.

Normal completion requires both `D` markers, zero collector exit and an empty owned worker cgroup (`campaign.py:113–122`, `b1_audit_stop.py:151–192`, `runtime.py:973–977`). The exit drain addresses the reviewed read-before-exit race; a drained `S` remains a STOP. Marker bytes by themselves are not batch acceptance. The contract binds descriptors by their cooperative launch and checks distinct FIFO identities; it does not independently establish pipe-peer provenance or defend against a same-UID actor replacing descriptors. The module's introductory `Unwired` wording is stale relative to this candidate and must not be read as its runtime behavior.

Both writer channels failing, monitor or guardian loss, parent death after notification, shared kernel faults, or unconfirmed freeze remain outside the demonstrated single-writer model. If both notifications fail while another worker retains a writer, executor shutdown may still wait and the parent may not immediately observe the exception. This is an explicit operational limitation, not a proven response to all STOP scenarios. The supported fault model and actionable response must be disclosed at handover; an authorized operator must qualify actual pipe/fork/inheritance, freeze, worker/cgroup, and failure behavior on Linux without deleting probe artifacts before B1. Exact site time is unknown. The experiment implementer and independent reviewer must verify compatibility with the actual selected harness, node artifact fixes, scientific protocol and final combined checkout; existing author gate, test, pin, no-deletion and handover STOPs remain. This review authorizes no experiment or author decision.
