## Proposed transport change — initial review before deployment

Reviewed uncommitted `r1/exam/hub_download.py` and its two fake-byte tests. Switching transport does not change the source policy, artifact identity, fit protocol or GPU phase. The proposed receiving code explicitly passes `token=False`, uses approved work locations for HF/Xet caches, validates an existing certificate's source, checks every full received/reused file size and SHA256, and preserves mismatching files. Each child has its own process group and the per-artifact disk monitor terminates that owned group on its own exception. Those mechanisms are appropriate subject to the following correction.

**MAJOR T1 — Multi-artifact STOP does not propagate to other tasks.** The `ThreadPoolExecutor.map` queues multiple artifacts, and a `receive_one` STOP affects only that task. Another active or queued artifact can continue/start while the main iterator unwinds and the executor waits. An independent fake-byte/no-network reproduction supplied eight rows with row 0 immediately raising `STOP synthetic source/hash failure`; rows 1 and 2 nevertheless started before main returned. The two current tests cover single-artifact receiving and disk termination but not this controller-level case. Add shared cancellation on the first STOP, prevent further launches, terminate/wait only controller-owned active child groups, preserve partials, and re-raise. Handle controller interruption consistently; a bare main-process SIGTERM currently leaves separately-sessioned children without a cleanup handler. Re-review before using the proposed helper. This finding does not stop the already-authorized original HTTPS downloads.

The planned manual transition must first establish exact PID ownership/start times, stop only the existing owned download helpers, and archive every original `.partial` without altering its bytes, with recorded size/hash. Record new package versions and preserve new transport caches after STOP; resumption after an actual STOP requires explicit authorization rather than an automatic retry. No GPU job is part of this transport review.
