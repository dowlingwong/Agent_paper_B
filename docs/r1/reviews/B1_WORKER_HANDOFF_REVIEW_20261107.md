# Independent review: B1 cooperative worker handoff

**Verdict: NOT ACCEPTED** for the proposed production handoff at candidate `667cede`. The proposed exclusive root and parent/child identity checks are useful in the cooperative intended path, but a failure of the new handshake can change the STOP scene after the parent has recorded STOP; the claimed refusal of existing batch paths also does not hold for every supplied path. No tests, subprocesses, signals, host access, model, GPU, experiments, or deletion were performed in this review. This review does not authorize B1, and its absence of a passing verdict does not affect other existing STOPs.

## Blocking findings

1. **The unreleased child can append to the STOP scene after the parent reports STOP.** `r1/exam/runtime.py:756-768` opens the new root's `runner.log` as the child's combined stdout/stderr, starts the child, records and saves the in-progress state, then verifies/releases the pipe. If state save, `make_record`, or `release` fails, the `finally` closes the pipe and unwinds; that block precedes the separate supervision `try/except` at lines 771-800, so the parent does not wait for the child on this path. The child reads its job and enters `await_parent` (`r1/exam/campaign.py:276-285`, 150-156). EOF, timeout or invalid release raises an uncaught exception (`r1/exam/b1_worker_handoff.py:84-95,129-130`), and the module entry point has no exception suppression; Python can append a traceback to the already-open `runner.log`. The parent may record `STOPPED` first (`r1/scripts/exam_runner.py:542-553`), while the child subsequently writes the traceback. This is a scheduling possibility derived from source, not an observed real STOP. It conflicts with the 7 Nov prompt §0.4 requirement to stop and preserve everything on STOP, and the test at `r1/tests/test_b1_worker_handoff_unittest.py:101-116` only checks mocked pipe closure, not child completion or write ordering. A correction needs a reviewed failure protocol that closes/reaps or otherwise safely quiesces this *known owned child* without post-STOP mutation, preserves the original reason and evidence, and handles timeout, short-write, failed `Popen`/state save, and parent death. It must not rely on an unchecked signal or conceal an unproved no-deletion behavior. Full process-tree/guardian STOP handling remains a separate unresolved prerequisite.

2. **The exclusive creation applies after resolving the operator-supplied path.** `ExamRunner.__init__` sets `self.out = Path(out).resolve()` (`r1/exam/runtime.py:494`); the new `start()` checks and creates only this resolved path (`runtime.py:545-553`). For example, an existing supplied `/approved/work/alias` symlink to absent `/approved/work/newbatch` resolves to the latter, which is then exclusively created, even though the supplied batch pathname existed. No concrete host symlink or interference was observed. This does not justify the candidate report's unqualified statement that an existing batch path is refused and left untouched, and could change the effective target of an existing other-operator link. Validate the original input path and relevant ancestors before following them, fail closed on existing symlinks/aliases, and separately retain the same-UID race/cooperation limit. Add a non-destructive test for an existing symlink to an absent target. The existing mock of `Path.mkdir` raising `FileExistsError` (`test_b1_worker_handoff_unittest.py:118-132`) does not exercise the resolution path.

## Scope and remaining evidence

The child compares a job digest, parent and child PIDs/start ticks, root device/inode/owner, descriptor device/inode/owner, and, for an LLM server, a parent/lifetime/FD/URL snapshot. Parent `Popen(pass_fds=...)` supplies the lease FD in the intended path. A blocking pipe and a record within the stated 4096-byte limit provide a bounded single-write handoff; EOF, truncation and mismatches refuse entry. Neither descriptor inode equality nor the URL/string and process checks independently proves a shared open-file description or kernel TCP-socket ownership; the report correctly discloses these, same-UID adversarial forgery, and site preflight limits. A pipe record is not persisted as a receipt. No actual Linux handoff, `/proc`/site behavior, external process lifetime, or GPU state was verified here.

The candidate intentionally refuses every pre-existing production B1 batch, including a non-STOP crash, while retaining earlier DRYRUN/Stage A paths. This is an operational restriction, not proof that former Stage A→B1 kill/resume coverage is restored. The candidate report says 16 in-memory mocked tests passed; the tests were not independently rerun and no retained test log is claimed. Existing no-deletion, pending-guard, real-worker determinism, full-suite, STOP quiescence, host handover, note-order, final-checkout and review prerequisites remain open. On correction, preserve earlier evidence; a fresh review should test the exact real entry/suppression behavior using demonstrably test-owned processes only if an independently reviewed no-deletion test method exists.
