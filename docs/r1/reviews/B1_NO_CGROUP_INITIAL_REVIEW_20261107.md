## Concrete blocking findings

1. **A launched worker can survive STOP when recording its state fails.** At `a77d8554`, `ExamRunner.run_job` starts its child (`r1/exam/runtime.py`, near 766–770) and calls `self.save()` before entering the `try` that calls `stop_tree` on error. A filesystem or state-publication failure there reaches `main`'s STOP handler, but that handler only attempts server shutdown; the already launched worker is not stopped. This is a normal caught I/O failure path, not an observed incident. `33268974` moves `self.save()` into the protected region, fixing this specific interleaving, but two adjacent post-spawn operations remain outside that region: `runner.log` context-manager close after successful `Popen` can raise inside the preceding `except`, which closes the pipe and rethrows without stopping `self.child`; and `os.close(stop_write)` after successful `Popen` precedes the STOP-handling try. The implementer has been asked to put successful spawn, log close, pipe close, tracking and state publication under one owner-aware failure handler and test each injected failure. **Owner:** implementer and independent reviewer. **Effort:** bounded code change plus focused tests; no author decision or cgroup needed.

2. **An audit exception can be hidden behind a failed log write.** Follow-up `33268974` correctly replaces the campaign's new `killpg` call with an inherited notification pipe so the parent can use its existing owned-worker `stop_tree`. However `run_b1_audits` first executes `print(..., flush=True)` on the worker's `runner.log`, then cancels futures and writes the notification byte. If the log write raises (for example on a full filesystem), cancellation and notification are skipped; `ProcessPoolExecutor.__exit__` may wait for running workers, so the parent may not learn of the STOP until a later deadline. Make logging best-effort, ensure cancellation and notification still occur, preserve the original error, and cover the concrete injected log failure. Handle notification failure with a bounded parent-observable STOP; do not claim arbitrary kernel-failure guarantees. **Owner:** implementer and reviewer. **Effort:** focused code/tests, then site qualification.

3. **Snapshot parent permissions can make ordinary B1 runs stop under a common umask.** New `b1_state_preserve._publish_named` refuses directories with group/other write bits. Server instance batch directories and campaign roots are otherwise created using default `mkdir` modes; under umask `0002` they can be `0775`, causing the first server-record or audit-cache publication to fail even when the runner owns the tree. The actual TASL-7 umask was not verified in this review, so this is a conditional source finding, not a site observation. Create B1-owned output directories with suitable reviewed modes or bind and check an appropriate launch umask; add a test with umask `0002`. **Owner:** implementer/reviewer and site operator for final preflight. **Effort:** bounded change and test.
