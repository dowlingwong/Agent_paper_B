## Protected input copy and binding contract

The final launcher must accept only allowlisted relative paths and expected digests from the approved spec. Reject `..`, symlinks, magic links, hard-link aliasing, mount escapes, unexpected uid/mode/ACL, group/world write, missing data, duplicate paths, unsupported syscalls or inability to establish trusted ancestry. Resolve from a verified directory FD using reviewed `openat2` resolve flags or an independently validated equivalent; reject escapes. Pin the actual consumed file descriptions / validated immutable objects across worker launch and imports: hash-then-reopen by path is insufficient. Record exact dev/inode/mode/owner/mount, open FDs, fstat and SHA-256, executable identity, directory chain, and runtime dependency bindings. Bind source bundle's prompt and all ledger files independently; no untracked import or writable external path. STOP on mutation, replacement, uncertain identity, checksum mismatch or missing evidence. Any admin-managed copy needs atomic publication/immutable backing and a test proving a same-UID attacker cannot mutate the protected backing between validation and use.

**Current prototype limitation:** `guard.py` is synthetic-only and stops production unconditionally. Its `O_NOFOLLOW` and held-FD SHA identify the object it read; they do not verify root ancestry/mount or make a shared-UID-owned file immutable. It cannot serve as the admin launcher.

Trusted coordinator acquires existing GPU `flock` before launching any service. Before/after FD transfer, identify holder and consumer PID + start ticks, target device/inode and explicit FD ownership, and use `kcmp(KCMP_FILE)` or a separately independently accepted equivalent to prove same OFD; `EPERM`, unavailable `kcmp`, PID reuse or any uncertain result is NOT CHECKABLE/STOP. Negative fixture: independently open the same inode twice and verify the comparison rejects OFD equality; absence of access to kcmp must not fall back to PASS.

Keeper holds the same OFD from before service start through service completion and STOP preservation, including coordinator disappearance. A file named `runner.lock` or recorded inode does not prove this. Describe real service-holder lifetime, failure monitoring and operator recovery; if holder dies or monitoring coverage is lost, STOP and preserve evidence.
