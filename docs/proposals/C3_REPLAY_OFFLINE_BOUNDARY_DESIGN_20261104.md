# C3 environment replay: proposed offline boundary (revision 2)

AI-assisted (Codex), 4 November 2026. This is a design proposal, not an implementation, authorization, or evidence of host capability. Revision 2 addresses `reviews/MAC_M3_OFFLINE_DESIGN_REVIEW_20261104.md` (not accepted). The OpenML replay hard STOP remains in force. No remote host, download, or experiment was used to prepare this design.

## Fixed contract and source observations

The predeclared replay protocol requires a STOP when a selected configuration needs a download, with all 16 configurations established executable offline **before any are scheduled**. A denied data-download attempt is a STOP. Egress denial alone, an unchanged cache, or a returned dataset is insufficient if attempts cannot be observed. This design uses a conservative stricter operational rule: **any attempted network, socket, or prohibited IPC syscall during preflight or replay is a STOP**, whether data-related or benign, even when blocked. This avoids relying on semantic classification of an intercepted connection. If a harmless operation triggers the rule, preserve the record and stop; it is not silently exempted. A different rule would require an author-approved protocol change.

Pinned harness `6adf3859de66c4814fcf376eed59880fbd8eeaf7` reads the dataset ID from the frozen node `dataset.json`; the benchmark uses `fetch_openml(data_id=DATA_ID, as_frame=True, parser="auto", data_home=str(CACHE_DIR))`. Its `LocalWorker._run_command` calls `subprocess.run(..., shell=True, cwd=node_root, env=seed_environment(...))`. The ionosphere node's pinned run command is `python3 train.py --config config.yaml`. A check in the parent alone does not restrict the shell or descendants.

The locally inspected scikit-learn 1.8.0 `fetch_openml` signature has **no** `download_if_missing` parameter. Its cache path returns an existing cached resource or attempts `urlopen` if absent. These observations do not establish that the actual replay host has the expected environment or can run this design.

## Concrete candidate launcher and trust boundary

Proposed new local tool `r1_offline_guard`, implemented and independently reviewed before use, consists of (a) a small trusted Linux supervisor outside the sandbox, and (b) a trusted single-threaded bootstrap that installs isolation before executing the preflight or replay interpreter. No change to the pinned harness, benchmark, configuration, interpreter, numerical libraries, worker command, seed controls or historical records is permitted. The supervisor, bootstrap, their libraries and policy are identified by SHA-256 and version; their build provenance and kernel support must be reviewed. If any required setup, observation or verification fails, the bootstrap never execs the workload and the supervisor records STOP.

The candidate requires all of the following; availability is an unresolved host prerequisite, not an assumption:

1. **Process containment.** Place the bootstrap in a dedicated delegated cgroup-v2 subtree with no write access to cgroup control files from inside. Place it in fresh mount, PID, network and IPC namespaces, without host network devices/routes, with `/proc` mounted only for the isolated PID namespace. No host `/proc`, host cgroup filesystem, container runtime socket or host Unix socket is mounted. Deny access to external process file descriptors (`pidfd_getfd`, `ptrace`, `process_vm_*`, namespace handles) and prohibit namespace or privilege creation/entry and filter removal. Drop effective, permitted, inheritable, ambient and bounding capabilities; set `no_new_privs` before the workload. The sandbox filesystem is a read-only allowlist of pinned code, runtime, libraries and necessary OS configuration, plus isolated private writable work/output and pre-verified dataset copies. No writable host-shared directories, named pipes, proxy sockets, writable runtime or mutable host code enter the sandbox. Bind mounts and loader symlink targets must be validated, and required host inputs must be either copied or read-only pinned. These restrictions must be enforced, not merely listed in configuration.
2. **Descriptors and IPC.** Bootstrap closes every descriptor except explicit controlled standard input/output/error before exec; none can be a socket, pipe to an untrusted outside process, namespace handle or untrusted directory descriptor. The trusted supervisor retains the seccomp listener outside the workload and directs logs through its controlled channels. Block attempts to create or use network and Unix-domain sockets, including inherited-descriptor paths; block `io_uring` and other indirect mechanisms which could bypass syscall mediation. Block mounting, process inspection, IPC and syscall mechanisms that could reach or cooperate with an outside process. The exact architecture-specific syscall policy, including compat/x32 and indirect forms, must be enumerated and reviewed; refuse unsupported architectures or kernel semantics. A network namespace alone is not sufficient to prevent a pathname Unix proxy or filesystem-mediated cooperation.
3. **Trusted observation and descendant invariant.** Before any untrusted interpreter, import or child runs, install a reviewed seccomp-BPF filter with `no_new_privs` and a supervisor-held `SECCOMP_RET_USER_NOTIF` listener for every socket/network/prohibited IPC syscall in the policy. The supervisor denies every notification, durably records the attempted syscall and process identity, marks STOP, and kills the whole cgroup, regardless of whether the workload catches an error or a later result looks successful. Abort if the listener, audit record, cgroup membership or monitor health cannot be maintained. Block bypasses such as io_uring, filter/namespace alteration and out-of-sandbox cgroup migration. The inherited seccomp filter and namespace membership constrain fork, clone, exec, shell and later descendants without relying on periodic PID enumeration; cgroup kill and reaping handle failure. Cgroup/namespace/filter configuration is verified before workload exec and independently qualified on the target kernel. A supervisor failure must kill or prevent the workload, not leave it running unmonitored. The exact crash-safe handshake and Linux capability checks are implementation obligations; absent proof, STOP.
4. **Threat model.** The supervisor, reviewed launcher/policy, kernel and host administrator are trusted. The protocol assumes no malicious same-UID process or administrator deliberately tampers with sandbox inputs, outputs, launcher, cgroup or supervisor, and assumes the sandbox is not configured to share any writable channel with another process. This is an explicit limitation, not proof of host-wide single-user isolation. To reduce accidental mutation, the supervisor creates uniquely named private directories with restrictive permissions, hashes source and cache before copying, hashes the read-only execution copies after transfer, and rechecks them at use and completion. Never claim this protects against a hostile same-UID process; if exclusive access/immutability cannot be established for the practical workflow, STOP. No external service or cooperating same-UID process may be used as an isolation component.

The policy is deliberately broad: it may reject library startup or local IPC that would be harmless. Such rejection is a STOP, not a reason to loosen it without independent review. Finite negative probes provide evidence but cannot alone establish the kernel enforcement invariant.

## Exact-data preflight and execution binding

Before scheduling any case, for each of the six selected OpenML nodes: verify frozen `dataset.json`, benchmark and node-config bytes against the pinned clean checkout; resolve the integer ID and cache exactly as that node does; create a fresh private working copy from the same cache selection used by the pinned collector; hash all files and bind the copy to its source. Run the actual pinned `fetch_openml` with the exact node arguments using the pinned interpreter and scikit-learn, under the above trusted boundary. Require data and target, no cache mutation, zero recorded prohibited attempts, normal completion and intact monitor/manifest. All node preflights must pass before any case starts. Missing, unrelated, incomplete, corrupt or wrong-ID cache, changed files, attempted connection, supervisor fault, or uncertain identity is STOP. A partial preflight is never a pass.

Preflight must also validate all 16 recovered configurations, their frozen files, declared command, dependencies, and required local input paths under the same boundary before any case is scheduled. The implementation and review must specify how this establishes offline executability for each configuration without executing the numerical replay or concealing configuration-dependent access; if this cannot be established, STOP. Six successful loader calls alone do not prove all 16 configurations are executable offline.

Each actual case must use a fresh private cache copy whose complete digest matches the specific successful node preflight immediately before execution; source, frozen files and cache digest are checked after execution as well. Run the pinned command and historical environment under the *same* policy, ensuring every shell and worker descendant inherits it. Copies and working directories are retained on STOP; preserved batch/corpus files are never modified. The cache's present hash is not proof of its historical provenance, and the bounded 16-case replay cannot prove all original environments.

Record launcher/policy hashes, host/kernel, architecture, namespace/cgroup identities and setup results, capability/no-new-privileges/filter checks, monitor and teardown outcome, exact interpreter/package pins, source/dataset IDs, per-node complete cache/frozen-file digests before/after, all prohibited-attempt observations, and the mapping from preflight to each case. Evidence of successful trusted bootstrap and zero prohibited notifications is needed; a missing or ambiguous record is STOP. There is no host-wide isolation claim.

## Required tests and qualification before reconsidering STOP

- A local Linux integration suite must use the **actual pinned** scikit-learn 1.8.0 `fetch_openml` and actual pinned node `dataset.json`/loader path, with a synthetic but structurally valid cache fixture and no remote traffic. Test complete, missing, partial, corrupt and wrong-ID cases. Independently confirm that missing/partial data causes a monitored attempt and STOP; verify the complete case returns data and target with zero prohibited notifications and no mutation. Fakes may supplement failure injection but cannot replace these tests. If a valid synthetic cache fixture, pinned interpreter or real loader is unavailable, record the test as unverified, not passed.
- Test the supervisor with controlled loopback-only or fixture endpoints: IPv4/IPv6, DNS, Unix pathname socket and deliberately inherited socket/FD, nested shell and grandchildren, `/proc`/pidfd access, namespace entry, filter bypass, cgroup escape, and indirect I/O. No request or packet may leave the boundary. Every prohibited attempt, including one swallowed by a child, must produce durable STOP and cgroup teardown. Test supervisor death, failed audit writes, bootstrap setup failures, unsupported kernel/architecture, daemonized grandchildren, timeouts and teardown. Prove no scheduling when any one of the six dataset preflights fails.
- Test exact data-ID and frozen-byte binding, source/cache changes at copy and before/after case use, and preflight-to-execution digest equality. Demonstrate on synthetic data that isolation preserves the pinned run command, seeds and fixture metrics versus the same pinned environment without isolation; this test does not establish historic equivalence.
- Independently review the complete launcher, policy, tests and evidence, then separately authorize and independently review actual-host capability and safety qualification. No target host access or experimental replay follows merely from this document. If any guarantee cannot be independently established, retain the hard STOP and present alternatives to the author.

## Open limitations

The concrete implementation, kernel/architecture syscall list, complete executable closure and mount allowlist, cgroup delegation, seccomp notification lifecycle, fail-closed supervisor death handling, trustworthy synthetic cache fixture and target host's supported policy are unverified. The launcher must demonstrate all of them before use; a shell wrapper, proxy environment variable, preflight success or inaccessible remote endpoint alone does not satisfy this design. Existing B.2 gates and historical results remain unchanged.
