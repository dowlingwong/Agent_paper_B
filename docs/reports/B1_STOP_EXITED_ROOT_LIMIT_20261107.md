# B1 STOP: exited-root limit — 7 November 2026

AI-assisted (Codex). **Static source finding, not an observed B1 STOP or an accepted fix.** This supplements the independently reviewed `B1_STOP_QUIESCENCE_INVESTIGATION_20261107.md` and `B1_STOP_ALTERNATIVES_20261107.md`. The production code examined is B1 checkout `8b196b1a`; no host, model, GPU, experiment, process signal, or stopped real batch was used.

In `r1/exam/runtime.py`, `run_job` starts the campaign child in a new session and repeatedly calls `self.child.poll()`. If that child exits with a nonzero return code, the function raises a STOP. In the exception handler, it calls `stop_tree(self.child.pid)` **only if a fresh `poll()` returns `None`**. Python's `Popen.poll()` waits for and records an exited child; once the root has exited, this conditional skips the tree stop even if a descendant of that child remains alive. A child can exit before all its descendants; the source does not establish that this happens in an actual B1 run. The separate model server is outside this worker session. Thus a root-exit STOP and its recorded return code do not prove owned descendants or GPU work have stopped.

For a still-live root, `r1/scripts/c3_label_sweep.py` `stop_tree` collects numeric descendant PIDs first and signals them later; the cited alternatives report explains why births, exits and PID reuse prevent this census alone from proving both complete quiescence and absence of unrelated signals. No conclusion that another user's process was signalled or that a real job continued follows from this static finding.
