## The defect

The G.1b note review (READY 75) found that `g4_tasl.launch` used `g1b_lib.verify_launch`. That binding can never be
satisfied by a note on `main` that names the launch commit, because the launch commit would have to descend from the
`main` that names it. `serve` (on TASL-7) checked only the note, with no launch binding at all. `check_note` also did
not bind the spec's `run_id` or harness commit, although R1-T1-TASL-ENV requires "harness at the commit the signed note
names".

## What changed (`sweep2/t1_tasl/g4_tasl.py`)

- `launch` (run-node, TASL-2) now defaults to `g1b_tasl.verify_launch_tasl(repo, spec, PLAN_ROWS, spec_path=...)`.
  This is the binding of R1-G1B-TASL-DECISIONS LB A, which that row decided for G.1b only; applying it to G.4 is the
  new author decision G4-LB in the draft. `g1b_lib.verify_launch` is no longer used.
- `check_import_sources` runs at launch, before `verify_launch_tasl` (round-2 minor 2): `g1b_tasl`, `g1b_lib`, `g4_lib` and `s2_c2_lib` must be imported from their
  reviewed source files. Otherwise a sourceless `.pyc` that git ignores in `sweep2/g4`, which is first on `sys.path`,
  would shadow them; `verify_launch_tasl`'s ignored-file scan covers only the G.1b directories.
- New `serve_launch`, called by the `serve` CLI, puts `serve` behind the same gate before the GPU lease is taken:
  - the note, with the spec;
  - both keys;
  - the same TASL launch binding.
- `check_note(..., spec=)` changes:
  - requires `run_id` and `harness_commit` to equal the spec's;
  - P3 must cite a signed G.1b note (`g1b_t1_tasl_`), not the word "G1B";
  - any field still holding a `<…>` placeholder is refused, so an unfilled template cannot pass;
  - given `read_main` (as `launch` and `serve_launch` pass it), every review file P4 names must be on `origin/main`.
- `serve` writes nothing for the run before the lease is held and every check has passed. Any exception there,
  not only a `Stop`, is written as a refusal and raised as a `Stop` (round-2 minor 3). A refusal goes to
  `<run_dir>/<run_id>/_refusals/`, and each started server gets a new `<run_dir>/<run_id>/server-N/`. Before this
  change, a refused `serve` left the run directory behind, and no later `serve` could start: `FileExistsError`,
  outside the `Stop` handling.
- The module docstring gains a Launch paragraph. The G.4 block of `g1b_tasl_authorization.template.md` gains
  `run_id`, `harness_commit` and the new P3 wording.
