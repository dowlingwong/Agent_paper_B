**AI-assisted (Claude, Mac agent). Engineering unit, desktop only. No data, ledger, table or label was read.**

This branch is the code base for the Track P data rebuild under `c3_features/v3` and `trackp_prompt/v2`. Branch
`mac-w2-v3-rebuild-20261115`, from `mac-w2-v3-prompt-20261114` @ `90d17fde`, which carries:
- the W2 stop-rule report (`mac-w2-stoprule-20261114` @ `87f67467`);
- the budget line in worker runs ("worker runs used k of 20", no trial total) and `PROMPT_VERSION = trackp_prompt/v2`
  (accepted at `f21ab320`).

This unit adds the **W2-3 check**: every source ledger made exactly W = 20 worker runs. This is the precondition the
stop-rule report puts on the worker-run budget feature.

**The STOP is not in force yet.** The check's STOP (exit 3) is a proposed rule. Adopting it as a STOP of the rebuild
is a separate author decision. Until then its output is a report to the author.

## 1. `r1/scripts/w2_runs_total_check.py`

**Inputs.**
- `--summary <file>`: the JSON printed by `r1.scripts.w2_execute_all_identity_check`. The cluster agent already ran
  that check read-only on sweep 1, so W2-3 needs no new data access. The script reads `rows`, `runs_total`,
  `worker_runs_total`, `differences` and `rows_not_counting_one`.
- `root_trials.jsonl[.gz]` ledgers, recomputed with the same `check_ledger`, which reads only `budget_index`,
  `decision`, `worker_mode` and `extra.control`. This path also checks two more things:
  - `budget_index` runs 1..rows;
  - no row follows the row that used the W-th worker run.
- `--expect-ledgers N`, required (288 for sweep 1). A partial or oversized set is bad input, so a partial set cannot
  pass.
- `--trial-budget`, default 2W. That is sweep 1's trial cap: `e1b_collect` passes `budget = runs * 2`.

The script (`main`) refuses `r1_sealed` paths, summaries and ledgers alike, before opening them.

**The check.** Every ledger must have `worker_runs_total == --runs-total` (20). A ledger that differs gets one of
these kinds:
- `short_at_trial_cap`: fewer than W runs at exactly the trial budget. The campaign stopped at the trial backstop.
  This is the case where the worker-runs-left feature would show runs it could no longer use.
- `short_before_trial_cap`: fewer than W runs and fewer rows than the trial budget.
- `over_cap`: more than W runs.
- `rows_over_trial_budget`: more rows than the trial budget, which sweep 1's harness cannot produce.
- `rows_after_cap`: exactly W runs, but rows after the W-th run. Recompute path only.

**Refusals (exit 2):**
- a summary that is not an identity-check output, including `BAD_INPUT`;
- a ledger count that differs from its results, or from `--expect-ledgers`;
- a summary made with another `runs_total`;
- a field that is not an integer;
- `differences` without any row kind that counts other than one run. That would mean duplicated or missing budget
  indices.
- a ledger listed twice, also across summaries and recomputed ledgers. Recomputed paths are resolved; summary paths
  are normalised as written.
- `budget_index` not running 1..rows;
- a sealed path or a wrong file name.

**Exit codes:** 0 PASS, 3 proposed STOP, 2 bad input. The JSON output carries
`"stop_rule": "proposed (adoption is a separate author decision)"`.

**Limits of the summary path.** The summary has no per-row data, so the recompute path is the stronger check. On
the summary path:
- A ledger with exactly W runs followed by trailing rows is not detected.
- A ledger whose duplicated budget indices and prechecks add up to W runs is not detected. The `differences` test is
  a consistency heuristic, not a full index check.
- Ledger paths are compared as written. The same file named twice under different spellings in a summary counts as
  two ledgers.

The harness's stop rule and ledger writer cannot produce the first two cases. The recompute path detects them, and it
compares resolved paths.

`--trial-budget` below `--runs-total` is refused.

## 2. Use in the rebuild (cluster agent; reviewed separately)

1. Run `python -m r1.scripts.w2_runs_total_check --runs-total 20 --expect-ledgers 288 --summary <the sweep-1
   identity-check JSON>`.
   - A PASS shows that each of the 288 ledgers made exactly 20 worker runs, within the 40-trial budget.
   - Under the **proposed** W2-3 rule, a ledger that differs would be reported to the author before its table is
     rebuilt. Whether that holds the rebuild is the author's decision.
2. Rebuild every Track P feature table and prompt set from this branch (`c3_features/v3`, `trackp_prompt/v2`). Write
   `FEATURIZER_VERSION` and the prompt version into each table's manifest. Do not mix v1 and v2 prompts.
3. Disclose both versions and the budget-line change (the W2 stop-rule report, item 3). The synthetic exam
   (`trackp_e0/v1`) keeps the v1 budget line; that is question W2-4, still open.
