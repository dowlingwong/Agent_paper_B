On the observed work/model filesystem it reports 613,359,476 KiB free (584.95 GiB) and 118,633,645 free inodes. This is a non-atomic snapshot, not a reservation, user-quota measurement, current occupancy or a verified measure of every final output path. The configured existing 100,000,000,000-byte floor is 93.13 GiB, leaving about 491.81 GiB above it at that snapshot, before other consumption. The same capture reports 63,420,669,952 bytes MemAvailable and 1,106,530,304 bytes swap used, also time-limited; these do not establish the memory use of the 20-worker/server combination.

The captured `du -sk` node sizes are 12 KiB digits, 32 KiB credit and 32 KiB ionosphere. Their fallback cache sizes are 84 KiB credit and 112 KiB ionosphere. As a *copy-cost proxy*, one copied node plus its fallback cache is respectively **12, 116 and 144 KiB**; actual allocation can differ because source and destination filesystems, metadata, symlinks, sparse files and copy behavior differ. Node trees must not already contain another cache for these sums to apply; actual `copytree` behavior and paths must be checked at use.

The existing planning count is 216 primary roots (18 selected entries × 3 nodes × 4 seeds), plus 44 descriptive credit roots (11 switchable × 4 seeds), totaling 260 if all complete. That yields 72 digits, 116 credit and 72 ionosphere roots. One initial copied node/cache per root at the proxy sizes totals **24,688 KiB (24.11 MiB)**. This is a component estimate, not the total run cost.

For a concrete stress scenario, suppose every root additionally retains **40 distinct audit configuration copies**: `run_config` makes a node/cache copy once per distinct configuration and executes four audit seeds in that copy. Initial plus 40 audit copies per root give digits 35,424 KiB, credit 551,696 KiB and ionosphere 425,088 KiB, together **1,012,208 KiB (0.965 GiB)** of source/cache proxy allocation. Each extra average audit copy per root adds 24,688 KiB (24.11 MiB) under these assumptions. Forty is an illustrative 2 × W scenario using W=20; it is **not asserted as a proven bound** on distinct configurations or total retained directories. The source also sets llm_call_cap=80 and workers=20, but the caps do not independently establish a total-byte bound or exclude additional records, retries outside a STOP, partial directories or other filesystem activity. B1 does not run the B2-only final-Y audit. If the actual number of roots, selected models, or copies differs, recalculate from the accepted final inputs.

## Remaining costs and practical monitoring

The proxy excludes worker run logs and patches, node `artifacts` preserved across trials and audit seeds, model/server logs, prompt/response and ledger contents, editable-file versions, partially completed work, manifests, and metadata/inodes. `publish_audit_cache` and batch-state publication retain prior full versions; cumulative snapshot bytes can grow faster than the final state. The actual size of these terms, quota, temporary shutdown writes and competing workload growth are **unknown**, so 0.965 GiB must not be presented as full-run usage or a guarantee. Prior real-worker site evidence covers a bounded individual worker, not the full preserved B1 workload; Stage A evidence is a different workload. Neither establishes a representative whole-B1 output size or 20-worker peak RAM. Do not infer an upper bound from those observations.

Use the existing runtime `space_check` on `work_dir` and `models_dir` and its 100 GB floor, and check the actual output filesystem, free inodes and applicable quota at handover. Retain the existing operator monitoring at least every 30 minutes: record free bytes/inodes, B1 owned output growth, current root and elapsed time, worker/server state and other visible resource pressure. Compare recent growth with remaining headroom and the time needed to stop safely; check more often if growth or contention warrants it. The built-in monitor checks the floor during active root execution; it is not an instantaneous guarantee against another process consuming space or an overshoot during shutdown. If a required check fails, a quota is exhausted, or safe room for continued work cannot be established, follow the existing STOP path and retain evidence. No deletion, automatic retry, new fixed storage threshold or new 20-worker profiling requirement is implied. If a material unknown prevents a reasonable operational estimate, an operator may propose the smallest separately reviewed, non-interfering measurement rather than assuming an arbitrary bound; any measurement must respect existing authorizations and no-preemption.

Final reviewed checkout, current site state and capacity, loader evidence STOP, author gate, preflight and O2 handover remain separate conditions. This calculation neither resolves them nor changes the author's 20-worker decision.
