# Architecture-specific cache estimate provenance

ENGINEERING_ONLY. Estimates remain separate from Stage A measured qualification. Source: pinned llama.cpp v0.7.0 commit `620d2225cc436ab0b001e3200e590e3b286ef9ab`; base config bytes and hashes are saved beside the fit table. No config bytes were altered to make a model fit.

- Nemotron H: `layers_block_type` identifies mamba, attention and MoE-only blocks. The latter retain no KV/recurrent state. `conversion/nemotron.py` (NemotronHModel) derives Mamba inner width from `mamba_num_heads * mamba_head_dim`, not the FFN `intermediate_size`. `src/llama-hparams.cpp` `n_embd_r` / `n_embd_s` use convolution state `(conv_kernel - 1) * (inner + 2 * n_groups * ssm_state_size)` plus SSM state `inner * ssm_state_size`; fp32 state storage is four bytes per value. Attention blocks retain ordinary q8_0 KV. No MTP draft execution is enabled.
- LFM2 MoE: `layer_types` distinguishes `conv` and `full_attention`. The pinned `n_embd_r` uses `hidden_size * (conv_L_cache - 1)` short-convolution history, fp32. Full-attention head dimension is exactly hidden_size/num_attention_heads.
- GLM-4.7-Flash: `conversion/glm.py` maps `Glm4MoeLiteForCausalLM` to DeepseekV2Model. `conversion/deepseek.py` `set_gguf_parameters` sets compressed MQA with one KV head and K width `kv_lora_rank + qk_rope_head_dim`. `src/llama-kv-cache.cpp` uses `has_v = !is_mla`: MLA retains no separate V cache. The estimate therefore uses one `(512 + 64)`-value q8_0 stream per token per layer, not hidden_size/attention_heads. Stage A must confirm the actual GGUF architecture and compressed MLA path; a legacy uncompressed GGUF cannot inherit this estimate.

The declared q8_0 estimate remains one byte per KV value, per R1-EXAM-FIT; runtime allocation and >=1 GiB free margin are measured separately. All estimates include the unchanged 1.5 GiB buffer allowance and 23.5 GiB limit. Hand calculations for these three newly encountered real config shapes are additional unit tests, alongside the original attention/sliding/DeltaNet calculations.

- Gemma4 local/sliding and global attention have different dimensions: the pinned converter's `global_head_dim` / `num_global_key_value_heads` set full-attention KV shape, while `head_dim` / `num_key_value_heads` set sliding shape. `src/models/gemma4.cpp` retains both K and V runtime tensors even when projection weights share `attention_k_eq_v`. Estimates count both caches. The 31B hand calculation is 50 sliding layers × 2 × 16 × 256 × 1024 + 10 global layers × 2 × 4 × 512 × 32768 = 1,761,607,680 KV bytes. 26B and 12B have separate hand calculations in tests. Declared shared-KV suffix layers, if present, allocate no independent cache; all three pinned exam Gemma configs currently declare zero shared layers.
