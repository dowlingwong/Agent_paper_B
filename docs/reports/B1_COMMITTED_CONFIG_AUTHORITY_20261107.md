# B1 committed configuration authority — candidate, 7 November 2026

AI-assisted (Codex). **Candidate for independent review, not B1 readiness or launch authority.** The production B1 entry point previously accepted `--config` from an arbitrary path, parsed its contents, and checked the clean checkout and note fields without comparing the loaded configuration with the reviewed committed config. A clean checkout and matching author-note fields alone therefore did not bind settings such as `root_timeout_seconds`, watchdog parameters, server binary or registry path to the reviewed configuration. This is a source-level defect; no real B1 invocation with an alternate configuration has been observed.

The candidate requires production B1 to use `r1/scripts/configs/exam_b1_v2.json` in the host checkout, with no resolved aliases or symlink components; it reads the committed Git blob for a clean HEAD, compares those exact bytes to the checkout file and their parsed JSON to the actual in-memory `cfg`, and checks HEAD again. This occurs immediately after parsing and before `ExamRunner` construction and anchor preflight. `ExamRunner.start` rechecks the canonical config and in-memory settings, then requires both that HEAD and the independently verified author-gate HEAD to equal the initial config HEAD before creating output, taking the GPU lease, or starting a service. A direct production `ExamRunner` caller must supply the checked HEAD and cannot pass the new start check without it. Normal CLI callers should explicitly supply the reviewed B1 config; this does not alter Stage A, B2, DRYRUN or `--check-config` behavior. The author note still requires its own approval and matching fields.

This is a point-in-time check, not exclusion of a concurrent writer: a same-UID or repository writer can race HEAD, file or source changes between checks, and the configured registry and value-grid paths retain their existing independent binding and provenance limitations. The user forbids checkout or config changes after launch; independent final-checkout review and operational cooperation remain necessary. The candidate does not address STOP quiescence, no-deletion, full test suite, host ownership, real worker, handover, or the author-note ordering cycle.

## Registry and working-directory correction after independent review

The first review was NOT ACCEPTED: the actual registry could be supplied through the internal `registry_path` override, and the CLI's relative registry could resolve against a non-checkout working directory. Production B1 now rejects a registry override at construction, resolves the config's relative registry against the checkout, requires its worktree path and bytes to match a regular committed Git blob at the checked config HEAD, and rechecks both the selected path and already-loaded registry object before the author gate and any output or lease. The check also requires the committed config to be a regular Git blob. This is a cooperative point-in-time check, not a lock against a concurrent writer or malicious direct caller altering objects after the checks.

For the remaining relative-input inventory, the config names `rule`, `value_grids`, the anchor reference JSON, `authorizations.b1` and the Stage A amendment acceptance record using relative paths; existing readers do not all rebase them against the checkout. Production B1 therefore now refuses unless cwd resolves to the checkout root. The two Stage A table paths, server binary, model directory and work directory are absolute in the reviewed config, with existing separate hash, host, storage and preflight checks; the anchor JSON, rule and tables retain their separate SHA checks. The child campaign runs with `cwd=REPO` in `ExamRunner.run_job`. This inventory is not a proof of every transitive source or protection from a concurrent writer.

After the correction, 17 pure in-memory unittest checks passed, including non-checkout cwd, committed symlink mode, registry path substitution, worktree-byte tampering, parsed-object mutation, and direct constructor override; the command is the same as above with `-q`, and the tool output reported `Ran 17 tests in 0.004s` and `OK`. No test or output log is represented as independently rerun. Stage A, B2, DRYRUN and `--check-config` retain the earlier guard scope; future independent review should check this and all relative-path consumers.
