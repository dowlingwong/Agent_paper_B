## What it settles

- FIXR3/EGATE run in a G1 loop (`run_replicate_chunk`) outside `run_real_campaign`; the engines decide E2
  unchanged, G1 owns E1 (execute every validated proposal), manager calls, worker calls and records.
- Engine-owned charging: `run_one` never charges the counter; it catches a worker exception and returns a failed
  `RunOutcome`, so the engine's existing `counter.charge` runs exactly once; a reused EGATE incumbent run charges
  nothing. `ComputeBudget` is frozen and is held in a mutable holder with every return reassigned; the
  `ChargedRunCounter`/`ComputeBudget`/engine-charge parity is asserted after every step.
- Snapshots: step-start projection (including EGATE's incumbent runs from `counter.lookup`), exact
  w = 5/10/15/20 live, a `pending` object with the in-step metrics/diffs, and a post-decision `final.json` from
  the final config contents so a keep on the last step is audited.
- Records: `campaigns/<instance_id>/` layout, `campaign_kind` in `campaign.json`, `extra.control.replicates` per
  G8, `zero_variance_cases` and `RunAttempt` failure classes; G6 reads `final.json`/`w` snapshots unchanged.
- The verify-seed collision remains on the harness verify arms only (R1-D3-VERIFY-SEED); FIXR3/EGATE have no KG
  verify. G2 remains a harness-arm prerequisite; the pre-declaration is on `main` and binding in its own order.
